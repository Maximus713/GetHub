# 🔄 **ПОЛНЫЙ АЛГОРИТМ РАБОТЫ ПО НОВОЙ СТРАТЕГИИ**

## 📌 **ОБЩАЯ КОНЦЕПЦИЯ**

**Три этапа — три разных чата:**
1. **Чат-архитектор** → создаёт мини-ТЗ для каждого файла
2. **Чат-разработчик** → пишет код по мини-ТЗ (один файл за раз)
3. **Чат-тестировщик** (опционально) → проверяет соответствие

---

## 🔄 **ПОЛНЫЙ АЛГОРИМТ ШАГ ЗА ШАГОМ**

### **ЭТАП 1: ПОДГОТОВКА МАТЕРИАЛОВ**

**Шаг 1.1: Соберите ВСЕ документы в один файл**
- Основное ТЗ (полная версия)
- Архитектурный манифест  
- Дополняющее ТЗ с жёсткими ограничениями
- Список прошлых ошибок (что чаты делали неправильно)

**Шаг 1.2: Создайте новый чат "Архитектор"**
- Платформа: DeepSeek, ChatGPT, Claude — любой новый диалог
- Название: "NPK Архитектор — создание мини-ТЗ"

**Шаг 1.3: Отправьте промпт для архитектора** [[Промпт чата архитектора мини ТЗ]]
- Скопируйте промпт, который я только что создал ("ПРОМПТ ДЛЯ ЧАТА-АРХИТЕКТОРА")
- Это первое сообщение в новом чате

**Шаг 1.4: Дождитесь подтверждения**
Чат должен ответить: *"Понял роль архитектора-документалиста. Готов создавать мини-ТЗ. Жду полное ТЗ проекта."*

**Шаг 1.5: Отправьте все ТЗ одним сообщением**
```
Вот полные технические требования:

[ВСТАВЬТЕ СЮДА ВСЕ 3 ДОКУМЕНТА:
1. Основное ТЗ (полная версия)
2. Архитектурный манифест  
3. Дополняющее ТЗ с жёсткими ограничениями]

ПРОШЛЫЕ ОШИБКИ ЧАТОВ:
1. State определялся в JavaScript (if (concentration >= range[0]))
2. Data_Adapter участвовал в расчетах
3. Нарушалась слоистая архитектура (вызовы между слоями)
4. Дублирование бизнес-логики в нескольких местах

Начинаем с Calculation_Engine.php.
```

---

### **ЭТАП 2: СОЗДАНИЕ МИНИ-ТЗ**

**Шаг 2.1: Получите первое мини-ТЗ**
Чат создаст мини-ТЗ для `Calculation_Engine.php`

**Шаг 2.2: Проверьте качество мини-ТЗ**
Убедитесь, что в нём есть:
- ✅ Явные запреты (например, "не вызывать другие классы модуля")
- ✅ Формула расчёта массы
- ✅ Алгоритм определения state
- ✅ Структура возвращаемого массива
- ✅ Упоминание прошлых ошибок

**Шаг 2.3: Если нужно — поправьте**
```
Отлично, но добавь явный запрет:
"НИКАКИХ вызовов Data_Adapter, AJAX_Handler, Shortcode или JS-классов"
```

**Шаг 2.4: Переходите к следующему файлу**
```
Теперь создай мини-ТЗ для AJAX_Handler.php
```

**Шаг 2.5: Создайте все 8 мини-ТЗ**
Порядок создания (рекомендуемый):
1. [[Calculation_Engine.php]] ← **самое важное!**
2. [[AJAX_Handler.php]]
3. [[Data_Adapter.php]]
4. [[Shortcode.php]]
5. [[concentration-module.php]]
6. [[calculator.js]]
7. [[calculator-template.php]]
8. [[calculator.css]]
9. [[npk-calculators.php]]


**Шаг 2.6: Сохраните все мини-ТЗ в отдельные файлы**
- `ТЗ-Calculation_Engine.txt`
- `ТЗ-AJAX_Handler.txt`
- ... и т.д.

### **ЭТАП 3: РАЗРАБОТКА КОДА**

**Шаг 3.1: Создайте новый чат "Разработчик"**
- Новый диалог, название: "NPK Разработчик — написание кода"
- **Это ОТДЕЛЬНЫЙ чат от Архитектора!**

**Шаг 3.2: Отправьте стартовый промпт для разработчика**
```
Ты — разработчик модуля WordPress "Калькулятор концентрации".

ПРАВИЛА РАБОТЫ:
1. Ты будешь получать мини-ТЗ для ОДНОГО конкретного файла
2. Ты НЕ должен предполагать ничего о других файлах
3. Перед написанием кода ты ДОЛЖЕН:
   - Перечислить ВСЕ требования из мини-ТЗ
   - Задать вопросы если что-то неясно
4. Только после моего "Продолжай" — пишешь код

Готов? Ответь "Готов к разработке. Жду первое мини-ТЗ."
```

**Шаг 3.3: Начните с Calculation_Engine.php**
```
Вот мини-ТЗ для Calculation_Engine.php:

[ВСТАВЬТЕ мини-ТЗ из файла ТЗ-Calculation_Engine.txt]

Твои действия:
1. Перечисли ВСЕ требования из этого ТЗ
2. Задай вопросы если что-то неясно
3. Только потом напиши код
```

**Шаг 3.4: Контролируйте процесс**
Если чат пытается сразу писать код:
```
СТОП! Ты не выполнил шаг 1. 
Сначала перечисли ВСЕ требования из ТЗ по пунктам.
Например: "1. Файл должен содержать метод calculate(), 2. State определяется только здесь, 3. ..."
```

**Шаг 3.5: Проверьте готовый код**
Убедитесь, что:
- ✅ Соответствует мини-ТЗ
- ✅ Нет запрещённых вызовов
- ✅ State определяется только в `find_state_for_concentration()`
- ✅ Формула расчёта массы правильная

**Шаг 3.6: Сохраните код в файл**
Скопируйте код и сохраните как `Calculation_Engine.php`

**Шаг 3.7: Переходите к следующему файлу**
```
Отлично. Теперь следующий файл: AJAX_Handler.php.

Вот мини-ТЗ для него:
[вставьте ТЗ-AJAX_Handler.txt]

Повторяем процесс:
1. Перечисли требования
2. Задай вопросы
3. Пиши код
```

### **ЭТАП 4: КОНТРОЛЬ КАЧЕСТВА И СБОРКА**

**Шаг 4.1: Проверьте архитектурные зависимости**
После создания всех файлов, проверьте, что:
- `Calculation_Engine` → вызывает только `NPK_Database`
- `AJAX_Handler` → вызывает только `Calculation_Engine`
- `Data_Adapter` → вызывает только `NPK_Database`
- `calculator.js` → НЕ определяет state

**Шаг 4.2: Создайте структуру папок**
Вручную создайте папки:
```
npk-calculators/
├── npk-calculators.php
├── shared/config/          ← сюда npk-database.php
└── module-concentration/
    ├── concentration-module.php
    ├── includes/           ← 4 PHP класса
    ├── assets/             ← js/, css/
    └── templates/          ← HTML шаблон
```

**Шаг 4.3: Разместите файлы по папкам**
Распределите созданные файлы по соответствующим папкам.

**Шаг 4.4: Создайте главный файл плагина**
Либо попросите чат создать `npk-calculators.php`, либо создайте сами:
```php
<?php
/**
 * Plugin Name: NPK Calculators
 * Description: Калькуляторы удобрений для агрономов
 * Version: 1.0.0
 */

// Подключение модуля концентрации
require_once __DIR__ . '/module-concentration/concentration-module.php';
```

## 🎯 **КЛЮЧЕВЫЕ МОМЕНТЫ ДЛЯ УСПЕХА**

### **КРИТИЧЕСКИЕ ТОЧКИ КОНТРОЛЯ:**

1. **Calculation_Engine.php** — если он идеален, 80% успеха
2. **Определение state** — только в Calculation_Engine, нигде больше!
3. **JavaScript** — НИКАКИХ `if (concentration >= range[0])`
4. **Слои архитектуры** — не смешивать!

### **ЧТО ДЕЛАТЬ ЕСЛИ ЧАТ ОШИБАЕТСЯ:**

```
СТОП! Архитектурная ошибка.

Ты написал: [цитата кода]
Это нарушает: [конкретное правило из ТЗ]
Потому что: [объяснение]

Удали этот код и начни заново, но сначала подтверди:
"Понял ошибку. State определяется только в Calculation_Engine."
```
