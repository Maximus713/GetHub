## **🔧 1. ДОБАВИТЬ ПОЛЕ `npk_sum` ДЛЯ УДОБРЕНИЙ**

### **Что сделать:**
Для КАЖДОГО удобрения в методе `get_fertilizers()` добавь поле `'npk_sum'`.

### **Что такое `npk_sum`:**
Это **сумма процентов N, P, K** удобрения.

### **Как рассчитать:**
`npk_sum = N% + P% + K%`

### **Пример:**
```php
// БЫЛО:
[
    'id' => 1,
    'name' => 'Азофоска (Нитроаммофоска)',
    'npk' => [16, 16, 16],           // N=16%, P=16%, K=16%
    'solubility_total' => 95,
    // ...
]

// СТАЛО:
[
    'id' => 1,
    'name' => 'Азофоска (Нитроаммофоска)',
    'npk' => [16, 16, 16],
    'npk_sum' => 48,                 // 16+16+16 = 48
    'solubility_total' => 95,
    // ...
]
```

### **Расчёты для всех удобрений:**
1. **Азофоска** [16, 16, 16] → `npk_sum` = 48
2. **Диаммофоска** [10, 26, 26] → `npk_sum` = 62
3. **Аммиачная селитра** [34.4, 0, 0] → `npk_sum` = 34.4
4. **Калийная селитра** [13.5, 0, 46] → `npk_sum` = 59.5
5. **Монофосфат калия** [0, 52, 34] → `npk_sum` = 86
6. **Сульфат калия** [0, 0, 50] → `npk_sum` = 50
7. **Кальциевая селитра** [15.5, 0, 0] → `npk_sum` = 15.5
8. **Мочевина** [46, 0, 0] → `npk_sum` = 46
9. **"Весеннее" комплексное** [22, 10, 12] → `npk_sum` = 44
10. **"Осеннее" комплексное** [5, 20, 30] → `npk_sum` = 55

**Важно:** Значения `npk_sum` должны быть **числами** (int или float).

## **🔧 2. ИСПРАВИТЬ ДИАПАЗОНЫ СОСТОЯНИЙ В ПРОФИЛЯХ**

### **Проблема:**
В профилях грунта (`dry`, `medium`, `wet`) диапазоны состояний пересекаются на границах.

**Пример проблемы в профиле 'dry':**
```php
'states' => [
    ['range' => [0.05, 0.15]],   // 0.05-0.15
    ['range' => [0.15, 0.25]],   // 0.15-0.25 ← 0.15 принадлежит двум состояниям!
]
```

### **Правило из ТЗ:**
- Для **всех состояний, кроме последнего**: `нижняя ≤ X < верхняя` (верхняя НЕ включена)
- Для **последнего состояния**: `нижняя ≤ X ≤ верхняя` (обе включены)

### **Что сделать:**
Измени границы диапазонов, чтобы **не было пересечений**.

### **Предлагаемое решение:**
Сделать небольшие сдвиги на 0.0001:

**Профиль 'dry':**
```php
'states' => [
    ['range' => [0.05, 0.14999]],    // 0.05 ≤ X < 0.15
    ['range' => [0.15, 0.24999]],    // 0.15 ≤ X < 0.25
    ['range' => [0.25, 0.34999]],    // 0.25 ≤ X < 0.35
    ['range' => [0.35, 0.59999]],    // 0.35 ≤ X < 0.6
    ['range' => [0.6, 1.5]],         // 0.6 ≤ X ≤ 1.5 (последнее состояние!)
]
```

**Профиль 'medium':**
```php
'states' => [
    ['range' => [0.05, 0.14999]],    // 0.05 ≤ X < 0.15
    ['range' => [0.15, 0.29999]],    // 0.15 ≤ X < 0.3
    ['range' => [0.3, 0.69999]],     // 0.3 ≤ X < 0.7
    ['range' => [0.7, 1.09999]],     // 0.7 ≤ X < 1.1
    ['range' => [1.1, 1.5]],         // 1.1 ≤ X ≤ 1.5
]
```

**Профиль 'wet':**
```php
'states' => [
    ['range' => [0.05, 0.19999]],    // 0.05 ≤ X < 0.2
    ['range' => [0.2, 0.39999]],     // 0.2 ≤ X < 0.4
    ['range' => [0.4, 0.99999]],     // 0.4 ≤ X < 1.0
    ['range' => [1.0, 1.29999]],     // 1.0 ≤ X < 1.3
    ['range' => [1.3, 1.5]],         // 1.3 ≤ X ≤ 1.5
]
```

**Альтернатива:** Можно использовать `0.1499` вместо `0.14999` — главное, чтобы границы не совпадали.

## **🔧 3. (ОПЦИОНАЛЬНО) УПРОЩЕНИЯ**

### **3.1. Убрать поле `ranges` из профилей:**
В каждом профиле есть поле `'ranges'` с `'absolute_min'`, `'absolute_max'`, `'default'`. Это избыточно, потому что:
- Слайдер всегда 0.05-1.5% (фиксировано в ТЗ)
- Значение по умолчанию всегда 0.3%

**Можно:** Удалить поле `'ranges'` из всех профилей.

    'is_default' => true  // ← добавить этот флаг

    'name' => 'СУХОЙ',
    'is_default' => false
    // ...
],

    'name' => 'СЛАБО ВЛАЖНЫЙ',
    'is_default' => false
