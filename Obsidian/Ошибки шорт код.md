Отличный подход! Создание **"Контрольного списка ошибок"** для чата перед генерацией кода может резко повысить качество результата. Такой список не только возможен, но и очень эффективен.

Вот структурированный список, который вы можете давать чату как **обязательный чек-лист перед написанием кода**. Он фокусируется на **системных ошибках WordPress**, а не на логике бизнес-задачи.

---

### **ЧЕК-ЛИСТ ДЛЯ СОЗДАНИЯ КОРРЕКТНОГО ПЛАГИНА WORDPRESS С ШОРТКОДОМ**
**Перед началом генерации кода, убедись, что плагин избежит следующих критических ошибок:**

#### **Раздел 1: Безопасная инициализация и регистрация**
1.  **`add_shortcode` на правильном хуке:** Функция `add_shortcode()` должна вызываться **не позднее** хука `init`. Идеально — внутри хука `init` с приоритетом по умолчанию или в корне плагина (после `plugins_loaded`).
    *   ❌ **Запрещено:** Регистрация на `wp`, `template_redirect`, `wp_head` или в конструкторе класса без проверки хуков.
    *   ✅ **Обязательно:** `add_action('init', 'register_my_shortcodes');`

2.  **Уникальность всех идентификаторов:** Все имена функций, классов, констант, хуков, имен шорткодов должны иметь **уникальный префикс** (напр., `mycompany_`, `scproject_`, `xyz_`). Никаких `create_shortcode`, `display_form`, `MAIN_PLUGIN_PATH`.
    *   ✅ **Обязательно:** `awp_booking_form_shortcode()`, `scp_booking_main_class`.

3.  **Проверка на прямой доступ:** Каждый файл `.php` плагина (кроме главного) должен начинаться с проверки `!defined('ABSPATH')` для защиты от прямого вызова.
    *   ✅ **Обязательно:** `if ( ! defined( 'ABSPATH' ) ) exit;`

#### **Раздел 2: Корректная обработка шорткода**
4.  **Функция шорткода ВСЕГДА возвращает строку:** Функция обработчик шорткода **не должна ничего выводить напрямую** (`echo`, `print`). Все данные должны собираться в переменную и возвращаться через `return`.
    *   ❌ **Запрещено:** Использование `echo` внутри функции шорткода.
    *   ✅ **Обязательно:** `$output = '<div>...</div>'; return $output;`

5.  **Обработка атрибутов:** Использовать `shortcode_atts()` для безопасного извлечения и назначения атрибутов шорткода по умолчанию.
    *   ✅ **Обязательно:**
    ```php
    $atts = shortcode_atts( array(
        'count' => '5',
        'type' => 'post',
    ), $atts, 'my_shortcode' );
    ```

6.  **Экранирование и безопасность (Security & Sanitization):**
    *   **Ввод (атрибуты, GET/POST):** Все входящие данные из `$atts`, `$_GET`, `$_POST` должны быть **пройдены через функции санитизации** (`sanitize_text_field()`, `absint()`, `esc_url()`).
    *   **Вывод (HTML):** Все переменные, выводимые в HTML, должны быть **пройдены через функции экранирования** (`esc_html()`, `esc_attr()`, `wp_kses_post()`)

#### **Раздел 3: Загрузка ресурсов (CSS/JS)**
7.  **Регистрация и подключение стилей/скриптов через официальные хуки:**
    *   ❌ **Запрещено:** Прямое подключение `<link>` или `<script>` в функции шорткода.
    *   ✅ **Обязательно:** Использовать `wp_register_script()/style()` и `wp_enqueue_script()/style()`.
    *   ✅ **Обязательно:** Подключать фронтенд-ресурсы на хуке `wp_enqueue_scripts`, а админские — на `admin_enqueue_scripts`.

8.  **Условная загрузка ресурсов (Оптимизация):** CSS/JS должны загружаться **только на тех страницах, где используется шорткод**. Использовать `has_shortcode()`, глобальную переменную или проверку `is_single()` / `is_page()`.
    *   ✅ **Рекомендуется:**
    ```php
    global $post;
    if ( is_a( $post, 'WP_Post' ) && has_shortcode( $post->post_content, 'my_shortcode') ) {
        wp_enqueue_style( 'my-plugin-style' );
    }
    ```

#### **Раздел 4: Совместимость и производительность**
9.  **Отсутствие "тяжелых" операций в конструкторах/инициализации:** Не выполнять сложные запросы к БД, большие вычисления или HTTP-запросы при каждой загрузке страницы. Перенести их внутрь функции шорткода или использовать кэширование.
10. **Кэширование и шорткоды:** Помнить, что выход шорткода может быть закэширован. Если нужны динамические данные для каждого пользователя, использовать AJAX или отключать кэширование для страниц с шорткодом (через `Cache-Control` headers).

#### **Раздел 5: Административный интерфейс (если есть)**
11. **Регистрация админ-меню и страниц на правильном хуке:** Использовать хук `admin_menu` для добавления пунктов меню и страниц в админке.
12. **Сохрание настроек через Settings API:** Для страниц настроек использовать WordPress Settings API (`register_setting`, `add_settings_field`), а не произвольные обработчики форм.

### **ИНСТРУКЦИЯ ДЛЯ ЧАТА (как подать этот список):**

> **Перед тем как писать код плагина, внимательно изучи следующий Чек-лист. Твой код должен строго соответствовать ВСЕМ пунктам из разделов 1-3. Пункты из разделов 4-5 — обязательны, если плагин требует соответствующих функций (админку, тяжелые операции).**
>
> **После написания кода, проведи виртуальную проверку (code review), сверяя каждый пункт списка с твоим кодом. Если какой-то пункт не соблюден — перепиши соответствующий участок.**
>
> **Начни свой ответ с подтверждения: "Чек-лист изучен. Код будет сгенерирован с соблюдением всех пунктов."**
