## 1. ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК РАБОТЫ ДЛЯ ИСПОЛНИТЕЛЯ

**1.1. Перед началом разработки исполнитель обязан:**

1.  **Полностью изучить настоящее ТЗ.**
2.  **Изучить предоставленный файл базы данных** `npk-database.php` (расположение: `npk-calculators/shared/config/npk-database.php`).
3.  **Выявить и зафиксировать все противоречия** между данными в `npk-database.php` и требованиями данного ТЗ.
    *Пример противоречия:* В БД `water_volume_max = 1000`, а в ТЗ указано, что максимальный объём — 200 л.
    **ПРАВИЛО:** При любом противоречии между ТЗ и данными в БД — **приоритет имеет ТЗ, за исключением случаев, когда изменения в БД согласованы с Заказчиком и отражены в официальных дополнениях к ТЗ.** Исполнитель обязан запросить у Заказчика исправленный файл БД.
4.  **Немедленно приостановить работу и сообщить Заказчику** о всех найденных противоречиях, указав конкретные файлы, строки и несоответствия.
5.  **Не вносить изменения в файл `npk-database.php` самостоятельно.** Исправление данных — исключительная прерогатива Заказчика.
6. **Прочитать и понять все комментарии для разработчиков** в БД, особенно:
    - Систему полуоткрытых интервалов диапазонов состояний
    - Проверочное правило для начальной концентрации 0.45%
    - Исключение для последнего состояния
7. **Не изменять числовые значения в БД** без явного разрешения Заказчика.  
    _Пример нарушения:_ Изменение диапазона `[0.25, 0.35)` на `[0.25, 0.36)`.
8. **Проверить математическую корректность** начального состояния:
    - Для влажного грунта: состояние `'optimal'` = `[0.4, 0.6)`
    - Концентрация 0.45%: `0.45 ≥ 0.4 = true`, `0.45 < 0.6 = true`
    - Результат: `0.45% ∈ optimal` ✅ (соответствует ТЗ п.6.1.1)

**1.2. Начало кодинга без полного понимания ТЗ и разрешения всех противоречий запрещено.**

**1.3.** При изучении файла `npk-database.php` исполнитель обязан проверить наличие **всех ключевых структур**, требуемых ТЗ:

- ✅ Наличие профиля с ключом `'wet'` в `get_concentration_profiles()`.
- ✅ Наличие поля `'range'` в каждом состоянии (`state`) всех профилей.
- ✅ Значение `'water_volume_max'` в `get_constants()['thresholds']` равно **200**.

## 2. НАЗНАЧЕНИЕ МОДУЛЯ

Модуль «Калькулятор концентрации» предназначен для решения следующих задач агронома/садовода:
1.  **Расчёт массы удобрения (в граммах),** необходимой для приготовления рабочего раствора заданной концентрации и объёма.
2.  **Учёт типа грунта** (сухой, слабо влажный, влажный) для корректной оценки риска выбранной концентрации.
3.  **Визуальная и текстовая оценка уровня риска** выбранной концентрации для выбранного типа грунта.
4.  **Учёт реальной растворимости (`solubility_total`) удобрения** для получения точной массы.
5.  Растворимость (`solubility_total`) — значение из БД, используется исключительно
  в Calculation_Engine как коэффициент компенсации:   `(100 / solubility_total)`.


**Главный принцип:** Калькулятор даёт рекомендации на основе агрономических данных, но окончательное решение и ответственность за применение остаётся за пользователем.

## 3. ИСТОЧНИК ДАННЫХ И АРХИТЕКТУРА

### 3.1. Единый и единственный источник данных
Все справочные данные **обязательно** берутся из файла:
`npk-calculators/shared/config/npk-database.php`

Допустимые методы:
- `NPK_Database::get_fertilizers()` – список удобрений.
- `NPK_Database::get_concentration_profiles()` – профили грунтов и их состояния.
- `NPK_Database::get_constants()` – константы и пороговые значения.

**Запрещено:**
- Жёстко прописывать данные в коде PHP или JavaScript.
- Изменять логику или формат данных, полученных из БД.
- Создавать дублирующие источники данных.

### 3.2. Архитектура модуля (MVC-подобная)

```
ДАННЫХ (БД) → ЛОГИКА → ПРЕДСТАВЛЕНИЕ
```

1.  **Слой данных (БД):** `npk-database.php`. Только хранение. Никакой логики.
2.  **Слой логики (`Calculation_Engine`):**
    - Содержит **все формулы** и **алгоритмы** расчёта.
    - Является **единственным источником истины** для итоговых результатов.
    - Получает сырые данные напрямую из `NPK_Database`.
    - **Не зависит** от других классов модуля (`Data_Adapter`, `Shortcode`).
3.  **Слой представления:**
    - **`Data_Adapter`:** Подготавливает и валидирует (для отображения) данные из БД для передачи в JavaScript. **Не участвует в расчётах.**
    - **`Shortcode` + Шаблоны:** Формируют HTML-разметку.
    - **JavaScript (`calculator.js`):** Обеспечивает интерактивность, мгновенные предрасчёты, анимации и отправляет запросы на финальный расчёт.

### 3.3. Единицы измерения в формулах

- Все концентрации и показатели растворимости в БД хранятся как **проценты (`%`)** в числовом виде.

**В формулах расчёта:**

- **Целевая концентрация из UI (например, 0.3):**  
    интерпретируется как проценты и преобразуется в долю:  
    `(concentration / 100)`.
    
- - **Растворимость (solubility_total):**  
    значение берётся **непосредственно из БД**, используется как процент
    растворимой части удобрения и применяется  
    **исключительно как коэффициент компенсации**:  
    `(100 / solubility_total)`.
    
JavaScript может использовать solubility_total исключительно для приблизительных UX-расчётов (preview), не являющихся финальными значениями."
    

**Логика расчёта:**

- Пользователь задаёт концентрацию **всех растворённых веществ**.
- `solubility_total` показывает, какая доля удобрения фактически растворяется.
- Множитель `(100 / solubility_total)` компенсирует нерастворимую часть.

**Важно:**  
Состав NPK (массив `npk`) **НЕ используется** в формуле расчёта массы,  
так как концентрация относится ко всем растворённым веществам, а не к отдельным элементам.

## 4. ЯДРО ЛОГИКИ: `Calculation_Engine`

### 4.1. Основная формула расчёта массы
```
масса_удобрения_г = (концентрация_из_ui / 100) × объем_воды_л × 1000 × (100 / solubility_total_из_бд)
```
Где:
- концентрация_из_ui - концентрация ВСЕХ растворённых веществ (NPK + растворимый балласт) в %
- (100 / solubility_total_из_бд) - КОМПЕНСАЦИЯ НЕРАСТВОРИМОЙ ЧАСТИ

Пример для концентрации 0.45%, объёма 10 л, растворимости 95%:
1. Концентрация в долях: 0.45 / 100 = 0.0045
2. Масса растворённого вещества: 0.0045 × 10 × 1000 = 45 г
3. Компенсация: 45 г × (100 / 95) ≈ 47.37 г
4. Итог: 47 г удобрения (после округления)

### 4.2. Валидация растворимости (`solubility_total`)
Перед использованием в формуле **обязательно** применяется единая функция:
```php
protected function validate_solubility_total($value) {
    if ($value === null || $value === 0) return 100; // Если данных нет — считаем полностью растворимым
    if ($value < 1) return 1;                        // Минимально возможная растворимость
    if ($value > 100) return 100;                    // Максимально возможная растворимость
    return (float)$value;
}
```

### 4.3. Определение состояния (`state`) концентрации

**Алгоритм для выбранного типа грунта (`ground_type`):**

1. Получить массив `states` из профиля грунта.
2. Возвращается **первое** состояние, в диапазон которого попадает концентрация.
3. Если концентрация ниже диапазона первого состояния — вернуть первое состояние.
4. Если концентрация выше диапазона последнего состояния — вернуть последнее состояние.

**Важно:**
- "Первое состояние" — это элемент с индексом 0 в массиве `states`.
- "Последнее состояние" — это элемент с последним индексом массива `states`.
- Никакой дополнительной маркировки состояний в БД НЕ требуется.
- Для последнего состояния применяется правило:  
  `нижняя_граница ≤ концентрация ≤ верхняя_граница`.
- Для остальных состояний применяется правило:  
  `нижняя_граница ≤ концентрация < верхняя_граница`.



**Пример корректных данных для `states`:**
```php
'states' => [
    ['range' => [0.05, 0.25]],   // very_low: 0.05 ≤ X < 0.25
    ['range' => [0.25, 0.4]],    // low: 0.25 ≤ X < 0.4
    ['range' => [0.4, 0.6]],     // optimal: 0.4 ≤ X < 0.6
    ['range' => [0.6, 0.9]],     // high: 0.6 ≤ X < 0.9
    ['range' => [0.9, 1.0]],     // danger: 0.9 ≤ X ≤ 1.0 (последнее!)
]
```


**Пример проверки для начального состояния:**
```php

// Профиль 'wet', состояние 'optimal'
$range = [0.4, 0.6]; // Из БД
$concentration = 0.45; // Начальное значение из ТЗ

// Проверка по правилам п.4.3:
$is_optimal = ($concentration >= $range[0]) && ($concentration < $range[1]);
// Результат: true (0.45 ∈ optimal)
```

## 5. СТРУКТУРА ИНТЕРФЕЙСА (МАКЕТ)

Интерфейс строится **строго сверху вниз** в следующем порядке:

**1. Панель выбора грунта:**
- Три кнопки в ряд: **[ Сухой ] [ Слабо влажный ] [ Влажный ]**.
- Кнопка **«Влажный»** активна по умолчанию при загрузке.
- При нажатии на кнопку меняется только интерпретация концентрации (состояние, цвет).

**2. Пояснительный текст:**
- Располагается под кнопками грунта.
- Содержит краткие рекомендации по определению влажности грунта. *Примечание: конкретный текст будет предоставлен Заказчиком на этапе интеграции. На этапе разработки оставить блок-заглушку.*

**3. Блок выбора удобрения:**
- **Слева:** Выпадающий список (`<select>`) со всеми удобрениями из БД.
    - Формат пункта: `Название [N-P-K]` (например, `Азофоска [16-16-16]`).
    - Удобрения в списке **должны быть отсортированы по возрастанию значения `id`**.
    - Первое удобрение в отсортированном списке (с минимальным `id`) выбрано по умолчанию.
    - Список **не содержит** пустого или невыбираемого пункта.
- **Справа:** Крупный текст, отображающий NPK выбранного удобрения в формате: **`N - P - K`** (например, **`16 - 16 - 16`**).

**4. Панель ввода параметров:**

- **Три поля ввода на одном уровне** с единым стилем управления.

    - **Поле «Объём воды» (слева):**
        - **Компоновка:** [кнопка "-"] [поле ввода] [кнопка "+"]
        - **Кнопки:** крупные, высотой равной высоте поля ввода
        - **Шаг изменения:** <10 л → шаг 0.5; ≥10 л → шаг 1.0
        - **Коррекция ввода:** при потере фокуса значение корректируется до одного знака после запятой
        - **Формат отображения:** одно значение после запятой (10.0)

    - **Поле «Общая концентрация» (по центру):**
        - **Компоновка:** [кнопка "-"] [поле ввода] [кнопка "+"]
        - **Кнопки:** крупные, высотой равной высоте поля ввода  
        - **Шаг изменения:** 0.01%
        - **Основное управление:** это поле связано со слайдером и является основным для ввода
        - **Значение:** ПОЛНАЯ концентрация всех растворённых веществ (NPK + растворимый балласт)
        - **Формат отображения:** два значения после запятой (0.30)
        - **Цвет фона:** плавно интерполируется от белого к цвету текущего состояния
        - **Подпись:** "Общая концентрация, %"

    - **Поле «Концентрация NPK» (справа, только для отображения):**
        - **Компоновка:** [статическое значение]
        - **Только чтение:** поле не редактируется, показывает расчётное значение
        - **Значение:** концентрация ТОЛЬКО по NPK (без балласта)
        - **Расчёт:** `общая_концентрация × (сумма_NPK / 100)`
          где `сумма_NPK` = N% + P% + K% из выбранного удобрения
        - **Формат отображения:** три значения после запятой (0.144)
        - **Подпись:** "Только NPK, %"
        - **Визуальное отличие:** более светлый фон, отличается от редактируемых полей

- **Иерархия управления:**
  1. Основное поле "Общая концентрация" связано со слайдером
  2. Поле "Концентрация NPК" расчитывается автоматически
  3. Изменение удобрения меняет "Концентрацию NPK" при той же общей концентрации

        - 
5.Шкала (слайдер) концентрации:
- Располагается под полями ввода.
- Единственный элемент для визуального выбора концентрации.
- **Технический диапазон:** 0.05% — 1.0%. Шаг: 0.01.

- **Метка состояния над слайдером:**
  - Располагается по центру над слайдером
  - Отображает название (name) текущего состояния
  - Фон метки окрашивается в цвет (color) текущего состояния
  - Цвет текста: контрастный (белый/чёрный) для читаемости на цветном фоне

- **Технические метки под слайдером:**
    - Равномерно распределённые значения для удобства ориентации:
    * Слева: "0.05%" (минимум)
    * Далее: "0.25%", "0.50%", "0.75%"
    * Справа: "1.00%" (максимум)
  - *Точный набор меток может быть адаптирован разработчиком, но должен включать минимум, максимум и несколько равномерных промежуточных значений*

- **Заливка слайдера:**
  - Полоска слева от ползунка окрашивается в тот же цвет (color) текущего состояния
  - Цвет меняется синхронно с фоном метки над слайдером

- **ВАЖНО:** Эмодзи состояний отображаются ТОЛЬКО в блоке результатов, НЕ на метке над слайдером.


**6. Блок результатов:**
- Располагается под слайдером.
- Три информационных поля **в один горизонтальный ряд**:
    1.  **Слева:** «Масса удобрения» (формат: `157 г`). **Округление:** до целого числа по математическим правилам (PHP: `round($масса, 0, PHP_ROUND_HALF_UP)`).
    2.  **По центру:** «Концентрация» (формат: `0.45 %`). **Формат:** всегда два знака после запятой (PHP: `number_format($концентрация, 2, '.', '')`).
    3.  **Справа:** «Состояние раствора». Отображает название состояния и его эмодзи (`emoji`) на цветном фоне (цвет `state.color`).

## 6. ПОВЕДЕНИЕ И ЛОГИКА ИНТЕРФЕЙСА

### 6.1. Начальное состояние
При загрузке страницы калькулятор **немедленно** отображает рабочий пример:
1.  Грунт: **«Влажный»** (кнопка активна). *Определение: выбирается профиль с ключом `'wet'` из `get_concentration_profiles()`.*
2.  Удобрение: **Первое в списке** (выбрано в `<select>`). *Определение: удобрение с минимальным значением `id` из `get_fertilizers()`.*
3.  Концентрация: **0.45 %**.
4.  Объём воды: **10.0 л**.
5.  Выполняется **полный цикл расчёта** (локальный + AJAX) и отображение результатов.

### 6.1.1. Логика начального состояния:
Начальная концентрация 0.45% для влажного грунта ('wet') должна соответствовать состоянию 'optimal'.

**Математическая проверка:**
- Берём профиль `'wet'` из БД
- Состояние `'optimal'` имеет `range = [0.4, 0.6)`
- Проверяем: `0.45 ≥ 0.4 = true`, `0.45 < 0.6 = true`
- Результат: `0.45% ∈ optimal` ✅

**Это проверочное правило для согласованности данных ТЗ и БД.**  
_Примечание: Если проверка не проходит — остановить разработку и запросить инструкции у Заказчика._

### 6.2. Взаимодействие и перерасчёт

-- **Изменение любого параметра** (удобрения, грунта, концентрации, объёма воды) → **мгновенный перерасчёт в UI (клиент)** и последующий **точный перерасчёт на сервере**.
- **Логика расчёта — гибридная:**

    1. **Мгновенная реакция (клиент):** JavaScript определяет предварительный `state`, используя **те же диапазоны (`state.range`)**, что и сервер,  
**без дублирования бизнес-логики и без изменения правил**, описанных в п.4.3. (включая правила для последнего диапазона и граничных значений), и выполняет **упрощённый расчёт массы** для мгновенного обновления UI.

    **Правила предварительного расчёта:**
    - `state` определяется по алгоритму из п.4.3
    - Масса вычисляется по формуле: `масса ≈ (концентрация × объём × 1000) / 100`
    - Все значения округляются до целых

    2. **Точный результат (сервер):** После окончания ввода (отпустили слайдер, убрали фокус с поля) — **AJAX-запрос** к `Calculation_Engine` для получения точных данных.

    3. **Приоритет данных:** При получении ответа сервера, все предварительные значения заменяются точными.

- **Debounce стратегия:**
    - Изменение концентрации/объёма: запрос через 500мс после последнего изменения
    - Смена грунта/удобрения: немедленный запрос
    - Перетаскивание слайдера: запрос только после отпускания
    
Допускается предварительное определение состояния (state) на стороне JavaScript
исключительно для визуального UX (цвета, метки, индикаторы).
Такое состояние не считается финальным и всегда перезаписывается state,
полученным с сервера.


### 6.3. Валидация и коррекция ввода
- **Десятичный разделитель:** Только точка (`.`). Запятая автоматически заменяется на точке в UI.
- **Концентрация (0.05% — 1.0%):**
    - В UI: значение за границами мгновенно корректируется до ближайшего предела (0.05 или 1.0).
    - В `Calculation_Engine`: финальная коррекция с возвратом скорректированного значения.
- **Объём воды (0.5 л — `water_volume_max` л):**
    - Аналогичная логика двусторонней коррекции.
    - Максимум берется из `get_constants()['thresholds']['water_volume_max']`.
    - **Шаг изменения кнопками:** <10 л → шаг 0.5; ≥10 л → шаг 1.0.
    - **Округление при ручном вводе:** До одного знака после запятой.
- - **Управление кнопками:**
    - Кнопки "+"/"-" изменяют значение на фиксированный шаг
    - Длительное нажатие/клик: постепенное увеличение/уменьшение значения
    - При достижении границ диапазона кнопка становится неактивной
    - Визуальная обратная связь при нажатии (изменение цвета/тени)
- - **Расчёт концентрации NPK:**
  - Формула: `NPK_концентрация = общая_концентрация × (сумма_NPK / 100)`
  - Где `сумма_NPK` = сумма процентов N, P, K из выбранного удобрения
  - Пример: удобрение 16-16-16 (48% NPK) при общей концентрации 0.45%:
    NPK_концентрация = 0.45 × (48 / 100) = 0.216%
  - Обновляется при: изменении общей концентрации, смене удобрения

### 6.4. Цветовая логика и интерполяция

1. **Слайдер:** Заливка слева от ползунка = `state.color` (сплошной цвет).
   - Источник цвета — текущий `state`, используемый интерфейсом.
- До получения AJAX-ответа UI использует **предварительный `state`**, определённый в JavaScript.
- После получения AJAX-ответа UI использует **финальный `state`**, полученный с сервера.

**Сервер не управляет цветом напрямую — он передаёт `state`, а применение цвета всегда выполняется в UI.**

2. **Метка над слайдером:** Текст = `state.name`. Цвет текста = `state.color`.
   - **Источник данных:** Тот же принцип что и у слайдера
   - **Единая логика:** Все элементы интерфейса используют один источник `state` на каждом этапе

3. **Поле ввода концентрации:** Фон плавно интерполируется от `#FFFFFF` (белый) к `state.color`.
   - **Рассчитывается исключительно в JavaScript** на основе `state.range` и `state.color`
   - **Источник `state`:** Тот же что и у слайдера и метки

**Источники данных для интерполяции:**

- **До первого AJAX-ответа:** Используется предварительный `state`, определённый по правилам п.4.3
- **После AJAX-ответа:** Используется финальный `state` с сервера
- **При отсутствии данных:** Используется профиль грунта "влажный" (по умолчанию)

**Формула интерполяции (RGB):**
```javascript
// weight от 0 (начало диапазона) до 1 (конец диапазона)
let weight = (currentConcentration - state.range[0]) / (state.range[1] - state.range[0]);
let r = Math.round(255 + (state_color_r - 255) * weight);
let g = Math.round(255 + (state_color_g - 255) * weight);
let b = Math.round(255 + (state_color_b - 255) * weight);
let backgroundColor = `rgb(${r}, ${g}, ${b})`;

```


### 6.4.1. Единый источник данных для цвета

Все элементы интерфейса, использующие цвет состояния (`state.color`), должны работать по единому принципу:

**До получения AJAX-ответа:**
- Все элементы используют предварительный `state`, определённый в JavaScript
- Цвета синхронизированы между всеми элементами

**После получения AJAX-ответа:**
- Все элементы ПЕРЕКЛЮЧАЮТСЯ на финальный `state` с сервера
- Все цвета обновляются одновременно и синхронно
- Предварительные данные полностью заменяются серверными

**Цель:** Пользователь не должен видеть рассинхронизацию цветов между элементами интерфейса.

**6.4.2. Синхронное цветовое кодирование**

Три элемента должны использовать ОДИН И ТОТ ЖЕ цвет состояния синхронно:

1. **Фон метки над слайдером** - цвет состояния
2. **Заливка слайдера** (слева от ползунка) - тот же цвет
3. **Цветная плашка состояния в блоке результатов** - тот же цвет

**Принцип:** Когда меняется состояние (из-за изменения концентрации или грунта), 
все три элементы меняют цвет ОДНОВРЕМЕННО и на ОДИН И ТОТ ЖЕ цвет.

**Цель:** Визуальная связь между выбором (слайдер), индикацией (метка) и результатом (блок).

### 6.5. Двухуровневая система данных

#### 6.5.1. Предварительные данные (клиент)
- Определяются в JavaScript для мгновенной обратной связи
- Включают: предварительный `state`, упрощённую массу
- Используются ТОЛЬКО для UX, не для принятия решений
- Могут незначительно отличаться от точных данных

#### 6.5.2. Точные данные (сервер)
- Определяются в `Calculation_Engine`
- Включают: финальный `state`, точную массу, подтверждённые значения
- Являются источником истины
- Всегда заменяют предварительные данные при получении

#### 6.5.3. Приоритетность
 **Приоритетность и синхронизация**

   1. При отсутствии точных данных → все элементы используют предварительные данные
   2. При получении точных данных → ВСЕ элементы одновременно переключаются на точные данные
   3. **Синхронность:** Обновление цвета всех элементов должно происходить в один момент времени
   4. При конфликте → точные данные имеют приоритет для ВСЕХ элементов

## 11. WORDPRESS ЖИЗНЕННЫЙ ЦИКЛ И ПОРЯДОК ВЫПОЛНЕНИЯ

### 11.1. Обязательная последовательность инициализации:

1. ✅ plugins_loaded (самый ранний) - загрузка плагина
2. ✅ init (ранний) - регистрация шорткода
3. ✅ wp_enqueue_scripts (ранний, приоритет 1) - регистрация скриптов
4. ⏳ Парсинг контента страницы - вызов шорткода
5. ✅ wp_enqueue_scripts (стандартный) - enqueue скриптов
6. ⏳ wp_footer - выполнение скриптов

### 11.2. Правило регистрации vs enqueue:

- **Регистрация (register)** - ВСЕГДА на wp_enqueue_scripts с приоритетом 1
- **Enqueue** - ТОЛЬКО если шорткод используется на странице

### 11.3. Критическое требование:

Скрипты ДОЛЖНЫ быть ЗАРЕГИСТРИРОВАНЫ ДО того, как WordPress начнёт парсить контент.
Если wp_enqueue_scripts() вызывается после парсинга шорткода - плагин не работает.
