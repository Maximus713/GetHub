В WordPress есть несколько способов отключить или ограничить сохранение редакций (ревизий) страниц и записей. Вот основные методы:

## **1. Через wp-config.php (Самый эффективный способ)**

1.  Подключитесь к сайту по FTP или через файловый менеджер хостинга.
2.  Найдите в корне сайта файл **`wp-config.php`**.
3.  **Перед строкой** `/* That's all, stop editing! Happy publishing. */` добавьте одну из следующих строк:

### **Полностью отключить ревизии:**
```php
define('WP_POST_REVISIONS', false);
```

### **Ограничить количество хранимых ревизий (рекомендуется):**
```php
// Сохранять только 3 последние редакции
define('WP_POST_REVISIONS', 3);
```

### **Отключить ревизии только для определенных типов записей:**
```php
// В functions.php вашей темы
add_filter('wp_revisions_to_keep', 'custom_revisions_to_keep', 10, 2);
function custom_revisions_to_keep($num, $post) {
    if ($post->post_type == 'page') {
        return 0; // Для страниц
    }
    if ($post->post_type == 'post') {
        return 3; // Для записей
    }
    return $num;
}
```

---

## **2. Через плагины (Для новичков)**

### **Плагин Revision Control:**
1.  Установите плагин **"Revision Control"** или **"WP Revisions Control"**.
2.  В настройках плагина можно указать количество ревизий для:
    - Записей (Posts)
    - Страниц (Pages)
    - Произвольных типов записей (Custom Post Types)
3.  Можно установить `0` для полного отключения.

### **Плагин Advanced Database Cleaner:**
Позволяет очистить существующие ревизии и настроить их ограничение.

---

## **3. Очистка уже существующих ревизий**

Если ревизии уже накопились и занимают место в базе данных:

### **Через плагин:**
- **WP-Sweep**
- **Advanced Database Cleaner**
- **Optimize Database after Deleting Revisions**

### **Вручную SQL-запросом (для опытных):**
```sql
-- Удалить все ревизии
DELETE FROM wp_posts WHERE post_type = 'revision';

-- Удалить автосохранения
DELETE FROM wp_posts WHERE post_type = 'revision' OR post_status = 'auto-draft';
```
**Внимание:** Сделайте резервную копию базы данных перед выполнением SQL-запросов!

---

## **4. Дополнительные настройки в wp-config.php**

```php
// Отключить автосохранения
define('AUTOSAVE_INTERVAL', 3600); // Раз в час вместо 60 секунд

// Удалять корзину через 7 дней вместо 30
define('EMPTY_TRASH_DAYS', 7);

// Отключить создание миниатюр изображений
define('MEDIA_TRASH', false);
```

---

## **5. Через functions.php темы**

Добавьте в файл `functions.php` вашей темы:

```php
// Полное отключение ревизий
add_filter('wp_revisions_to_keep', '__return_zero');

// Или для конкретных типов записей
add_filter('wp_revisions_to_keep', function($num, $post) {
    if ('page' === $post->post_type) {
        return 0;
    }
    return $num;
}, 10, 2);
```

---

## **Рекомендации:**

1.  **Не устанавливайте `WP_POST_REVISIONS = false`** — лучше ограничьте количество до **3-5**. Ревизии полезны, если нужно откатить изменения.
2.  **Перед редактированием wp-config.php** сделайте его копию.
3.  **Используйте плагины для очистки** существующих ревизий, если база данных раздулась.
4.  **Проверьте влияние на производительность** — отключение ревизий может ускорить работу админки, особенно на больших сайтах.

---

## **Проверка результата:**
После настройки:
1.  Отредактируйте любую страницу несколько раз.
2.  В правой колонке редактора нажмите **"Редакции"** (Revisions).
3.  Если настройки применились, вы увидите ограниченное количество версий или сообщение, что ревизии отключены.

**Важно:** Эти настройки не удаляют уже существующие ревизии, а только предотвращают создание новых сверх лимита. Для удаления старых используйте плагины очистки базы данных.
