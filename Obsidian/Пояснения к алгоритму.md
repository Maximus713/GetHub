# 🎯 **ОТВЕТ: ОБЕ ЧАСТИ ЯВЛЯЮТСЯ ПРОМПТОМ, НО ДЛЯ РАЗНЫХ ЦЕЛЕЙ**

## **📌 РАЗДЕЛЕНИЕ:**

### **🔹 ЧАСТЬ 1 (большой текст):** **ОБУЧАЮЩИЙ/ОПИСАТЕЛЬНЫЙ ПРОМПТ**
Это **детальное описание роли, алгоритма и правил** для будущего исполнителя.

**Назначение:** 
- Объяснить КАК работать
- Дать полное понимание процесса
- Установить жёсткие рамки
- Предотвратить творчество/ошибки

**Когда использовать:**
```
"Вот как ты должен работать. Запомни эти правила.
Теперь перейди ко второй части для конкретной задачи."
```

---

### **🔹 ЧАСТЬ 2 (последний блок):** **РАБОЧИЙ ПРОМПТ ДЛЯ ВЫПОЛНЕНИЯ**
Это **непосредственная команда для выполнения работы**.

**Назначение:**
- Дать конкретное задание
- Указать что делать прямо сейчас
- Прикрепить файлы для работы

**Формат:**
```markdown
Ты — [РОЛЬ]. Твоя задача — [КОНКРЕТНОЕ ДЕЙСТВИЕ].

АЛГОРИТМ:
1. Сделай это
2. Потом это
3. Потом это

ДАННЫЕ:
1. Файл 1
2. Файл 2
3. ТЗ

Начни работу.
```

---

## **🎯 РЕКОМЕНДУЕМЫЙ ПОРЯДОК РАБОТЫ:**

### **ВАРИАНТ 1: ДЛЯ ОПЫТНОГО ЧАТА (который умеет работать по алгоритмам)**
```
1. Отправь ТОЛЬКО рабочий промпт (часть 2)
2. Прикрепи все файлы
3. Чат начинает работать по алгоритму
```

### **ВАРИАНТ 2: ДЛЯ НАДЁЖНОСТИ (гарантия понимания)**
```
ШАГ 1: Отправь обучающий промпт (часть 1)
"Изучи этот алгоритм работы. Понял правила?"

ШАГ 2: Получи подтверждение
"Да, понял. Готов работать по алгоритму."

ШАГ 3: Отправь рабочий промпт + файлы (часть 2)
```

### **ВАРИАНТ 3: КОМБИНИРОВАННЫЙ (самый безопасный)**
```
Отправь ОДНИМ сообщением:

1. Краткое описание роли (3-4 строки)
2. Алгоритм из 10 этапов (только нумерованный список)
3. Рабочий промпт с командой "Начни работу"
4. Все прикреплённые файлы
```

---

## **📋 ПРИМЕР КОМБИНИРОВАННОГО ПРОМПТА (оптимальный):**

```markdown
Ты — СИСТЕМНЫЙ АНАЛИТИК-КОРРЕКТОР. Найди и исправь ВСЕ ошибки в плагине, не создавая новых.

АЛГОРИТМ (10 этапов):
1. Принять и систематизировать файлы
2. Анализ на соответствие ТЗ
3. Поиск критических ошибок
4. Поиск архитектурных ошибок
5. Поиск технических ошибок
6. Классификация ошибок
7. Пошаговое исправление (по одной)
8. Межфайловая проверка
9. Финальная валидация
10. Вывод результата

ПРАВИЛА:
- Одна ошибка → одно минимальное исправление
- Никаких новых функций
- Проверять после каждого исправления

ДАННЫЕ ДЛЯ РАБОТЫ (прикрепляю):
1. 📄 ПОЛНОЕ ТЗ
2. 🏗️ АРХИТЕКТУРНЫЕ ОГРАНИЧЕНИЯ  
3. 📋 ИНСТРУКЦИЯ ПРОВЕРКИ
4. 📁 ВСЕ ФАЙЛЫ ПЛАГИНА (9 файлов)

ФОРМАТ РАБОТЫ:
Для каждой ошибки:
- ID ошибки, файл, строка
- Контекст (3 строки до/после)
- Исправление в diff формате
- Проверки

В конце — все исправленные файлы и отчёт.

НАЧНИ РАБОТУ С ЭТАПА 1.
```

## **🚀 ЧТО ДЕЛАТЬ СЕЙЧАС:**

### **Если хочешь, чтобы я прямо сейчас исправил ошибки в плагине:**

**Отправь мне этот комбинированный промпт + все файлы.** Я начну работать по алгоритму и выведу исправленные файлы.

### **Если хочешь использовать с другим чатом:**

1. **Скопируй комбинированный промпт** (выше)
2. **Прикрепи все 4 документа и 9 файлов**
3. **Отправь как одно сообщение**
4. **Скажи "Начни работу"**

---

## **✅ ИТОГ:**

**ДА,** весь текст — это промпт, но:
- **Первая часть** = обучение/правила (можно дать заранее)
- **Вторая часть** = рабочая команда (отправлять с файлами)

**Рекомендую использовать КОМБИНИРОВАННЫЙ вариант** — он содержит всё необходимое для работы, но без излишних деталей, которые могут отвлечь чат.
