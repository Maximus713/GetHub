# **ТЗ ДЛЯ ПОЛНОЙ СИСТЕМЫ КАЧЕСТВЕННОГО АУДИТА КОДА**

## **АРХИТЕКТУРА (5 этапов):**

```
ЭТАП 0: ПОЛЬЗОВАТЕЛЬ → загружает код + команда
    ↓
ЭТАП 1: КОНТРОЛЛЕР-АНАЛИТАТОР → анализ + сжатие + первичный поиск
    ↓ (рабочий пакет ~20% объёма)
ЭТАП 2: ДЕТЕКТОР-ВЕРИФИКАТОР → глубокий поиск проблем
    ↓ (подробный список проблем)
ЭТАП 3: ФИЛЬТР-ВАЛИДАТОР → строгая проверка каждой проблемы
    ↓ (подтверждённые проблемы)
ЭТАП 4: МИНИМАЛИСТ-ИСПРАВИТЕЛЬ → безопасные исправления
    ↓ (исправленный код + diff)
ЭТАП 5: АНАЛИТИК-ДОКУМЕНТАТОР → финальный отчёт + статистика
```

## **ПОДРОБНОЕ ТЗ ДЛЯ КАЖДОГО ЭТАПА:**

### **ЭТАП 1: КОНТРОЛЛЕР-АНАЛИТАТОР (8-10 минут)**

**ВХОД:** Весь код проекта + команда `"ПОЛНЫЙ АУДИТ [ТИП]"`

**ЗАДАЧИ:**
1. **Анализ структуры (2 мин):**
   - Определить тип: WordPress/React/API/Микросервис
   - Оценить сложность: файлы, строки, зависимости
   - Выявить архитектурные слои

2. **Выбор стратегии (1 мин):**
   - WordPress → безопасность (ABSPATH, SQL, XSS, nonce)
   - React → стабильность (state, hooks, ошибки)
   - API → надёжность (валидация, обработка ошибок, logging)
   - Микросервис → интеграции (таймауты, retry, fallback)

3. **Интеллектуальное сжатие (5 мин):**
   ```
   ВКЛЮЧИТЬ ПОЛНОСТЬЮ (100%):
   - Точки входа (main, index, app, plugin)
   - Конфигурации (config, env, settings)
   - Критические модули (core/, lib/, src/)
   - Файлы с потенциальными проблемами (база, шаблоны)
   
   ВКЛЮЧИТЬ ЧАСТИЧНО (30-50%):
   - Вспомогательные функции (первые 50 строк)
   - UI компоненты (props, state, эффекты)
   - Утилиты (санитизация, валидация)
   
   ИСКЛЮЧИТЬ (0%):
   - Ресурсы (CSS, images, fonts)
   - Документацию
   - Тесты
   - Внешние зависимости
   ```

4. **Первичный поиск "красных флагов" (2 мин):**
   - Очевидные синтаксические ошибки
   - Отсутствие обязательных проверок (ABSPATH)
   - Критические security issues (eval, shell_exec)

**ВЫХОД: РАБОЧИЙ ПАКЕТ**
```
РАБОЧИЙ ПАКЕТ ДЛЯ ПОЛНОГО АУДИТА:
• Метаданные: [тип, размер, стратегия]
• Полные файлы: [5-7 ключевых файлов]
• Фрагменты: [15-20 релевантных фрагментов]
• Красные флаги: [3-5 очевидных проблем]
• Контекст: [архитектура, зависимости, риски]
• Инструкция: "Передайте этот пакет в Детектор-Верификатор"
```

### **ЭТАП 2: ДЕТЕКТОР-ВЕРИФИКАТОР (10-12 минут)**

**ВХОД:** Рабочий пакет от Контроллера

**ЗАДАЧИ:**
1. **Глубокий статический анализ (8 мин):**
   ```
   ДЛЯ КАЖДОГО файла/фрагмента в пакете:
   
   2. СИНТАКСИЧЕСКИЙ УРОВЕНЬ:
      - Парсинг ошибки
      - Undefined переменные/функции
      - Неимпортированные модули
   
   3. СЕМАНТИЧЕСКИЙ УРОВЕНЬ:
      - Неиспользуемый код (dead code)
      - Недостижимые ветки (unreachable)
      - Бесконечные циклы
   
   4. БЕЗОПАСНОСТЬ (если в стратегии):
      - SQL инъекции
      - XSS/CSRF
      - Path traversal
      - Insecure deserialization
   
   5. НАДЁЖНОСТЬ:
      - Необработанные исключения
      - Отсутствие null checks
      - Утечки ресурсов (открытые файлы, соединения)
   
   6. ПРОИЗВОДИТЕЛЬНОСТЬ (опционально):
      - N+1 queries
      - Квадратичные алгоритмы в циклах
      - Лишние ререндеры (для React)
   ```

7. **Категоризация проблем (2 мин):**
   ```
   КАТЕГОРИИ:
   • КРИТИЧЕСКИЕ (P0): ломают работу/безопасность
   • ВЫСОКИЕ (P1): влияют на стабильность/данные
   • СРЕДНИЕ (P2): потенциальные проблемы
   • НИЗКИЕ (P3): оптимизация/стиль/архитектура
   ```

8. **Подготовка детального отчёта (2 мин):**

**ВЫХОД: ПОЛНЫЙ СПИСОК ПРОБЛЕМ**
```
ПОЛНЫЙ ОТЧЁТ ДЕТЕКТОРА:
• Проанализировано: X файлов, Y строк
• Найдено проблем: Z

ДЕТАЛЬНЫЙ СПИСОК (макс 20 проблем):

1. [ID: P0-001] КРИТИЧЕСКАЯ
   • Тип: SQL инъекция
   • Файл: database.php:42
   • Код: `"SELECT * FROM users WHERE id = $id"`
   • Описание: Прямая подстановка переменной в SQL
   • Уверенность: 95%
   • Тест: `$id = "1 OR 1=1"` → нарушит запрос

2. [ID: P1-005] ВЫСОКАЯ
   • Тип: Необработанное исключение
   • Файл: api.php:88
   • Код: `file_get_contents($url)` без try-catch
   • Описание: При недоступности $url скрипт упадёт
   • Уверенность: 85%

3. [ID: P3-012] НИЗКАЯ
   • Тип: Дублирование кода
   • Файл: helpers.php:30, utils.php:45
   • Код: Одинаковая функция validate_email()
   • Описание: Можно вынести в общий модуль
   • Уверенность: 100%

СЛЕДУЮЩИЙ ШАГ: "Передайте этот отчёт в Фильтр-Валидатор"
```

### **ЭТАП 3: ФИЛЬТР-ВАЛИДАТОР (6-8 минут)**

**ВХОД:** Полный отчёт Детектора + Рабочий пакет

**ФИЛОСОФИЯ:** "Лучше пропустить 10 реальных проблем, чем принять 1 ложную"

**ЗАДАЧИ:**
1. **Жёсткая фильтрация (5 мин):**
   ```
   ДЛЯ КАЖДОЙ проблемы из отчёта Детектора:
   
   ТЕСТ 1: СУЩЕСТВУЕТ ЛИ КОНТЕКСТ?
   • Файл существует? ДА/НЕТ → если НЕТ → ОТКЛОНИТЬ
   • Строка существует? ДА/НЕТ → если НЕТ → ОТКЛОНИТЬ
   • Контекст совпадает (5 строк)? ДА/НЕТ → если НЕТ → ОТКЛОНИТЬ
   
   ТЕСТ 2: МОЖНО ЛИ СОЗДАТЬ ВОСПРОИЗВОДИМЫЙ ТЕСТ?
   • "При [условия] → произойдёт [проблема]"
   • Если нельзя создать конкретный тест → ОТКЛОНИТЬ
   
   ТЕСТ 3: ТЕСТ ПАДАЕТ НА ТЕКУЩЕМ КОДЕ?
   • Мысленно выполнить тест
   • Если тест проходит (нет проблемы) → ОТКЛОНИТЬ
   • Если невозможно определить → ОТКЛОНИТЬ (консервативно)
   
   ТЕСТ 4: КРИТИЧНОСТЬ ДОСТАТОЧНА?
   • P0 (критические) → всегда проверять
   • P1 (высокие) → проверять, если уверенность > 80%
   • P2-P3 (средние-низкие) → ОТКЛОНИТЬ (не для автоматического исправления)
   ```

2. **Сбор статистики ложных срабатываний (1 мин):**
   - Какие типы проблем Детектор часто ошибается?
   - Какие файлы дают много ложных срабатываний?

3. **Подготовка финального списка (2 мин):**

**ВЫХОД: ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ**
```
ОТЧЁТ ФИЛЬТРА-ВАЛИДАТОРА:
• Получено от Детектора: X проблем
• Подтверждено: Y проблем (Z%)
• Отклонено: W проблем (V%)

ПРИЧИНЫ ОТКЛОНЕНИЯ:
• Контекст не найден: A проблем
• Нельзя воспроизвести: B проблем
• Тест проходит: C проблем
• Недостаточно критично: D проблем

ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ (для исправления):

1. [ID: P0-001] КРИТИЧЕСКАЯ ✓
   • SQL инъекция в database.php:42
   • Уверенность: 100%
   • Исправление: `$wpdb->prepare("... WHERE id = %d", $id)`
   • Тест: `$id = "1' OR '1'='1"` → падает

2. [ID: P1-003] ВЫСОКАЯ ✓
   • XSS в template.php:15
   • Уверенность: 95%
   • Исправление: `esc_html($user_input)`
   • Тест: `$user_input = "<script>alert()</script>"` → XSS

СТАТИСТИКА ТОЧНОСТИ ДЕТЕКТОРА:
• Precision (точность): Y/X = 75%
• Recall (полнота): неизвестно (нужны ручные проверки)

СЛЕДУЮЩИЙ ШАГ: "Передайте этот список в Минималист-Исправитель"
```

### **ЭТАП 4: МИНИМАЛИСТ-ИСПРАВИТЕЛЬ (8-10 минут)**

**ВХОД:** Подтверждённые проблемы + Рабочий пакет (с полными файлами)

**ПРИНЦИПЫ:**
1. **Не навреди** — если сомневаешься, не исправляй
2. **Минимальные изменения** — 1 проблема = 1-3 строки
3. **Лимиты безопасности** — макс 7 исправлений за сеанс

**АЛГОРИТМ:**
1. **Приоритизация (1 мин):**
   ```
   СОРТИРОВКА:
   2. P0 (критические) — сначала
   3. P1 (высокие) — потом
   4. Ограничение: макс 7 исправлений
   ```

5. **Пошаговое исправление с проверкой (6 мин):**
   ```
   ДЛЯ КАЖДОЙ проблемы (по одной):
   
   ШАГ 1: Найти точное место в коде
   ШАГ 2: Применить исправление ИЗ ОТЧЁТА ВАЛИДАТОРА
   ШАГ 3: ПРОВЕРИТЬ:
     • Синтаксис (парсится ли?)
     • Не сломались ли импорты?
     • Не изменилась ли сигнатура функции?
     • Не задели ли соседний код?
   ШАГ 4: Если проверка провалена → ОТКАТ и записать причину
   ШАГ 5: Перейти к следующей
   ```

6. **Подготовка diff (1 мин):**

**ВЫХОД: ИСПРАВЛЕННЫЙ КОД + DIFF**
```

DIFF ИЗМЕНЕНИЙ:

+    $result = $wpdb->get_row($wpdb->prepare("SELECT * FROM users WHERE id = %d", $id));

=== template.php ===  
@@ -13,4 +13,4 @@
-    echo $user_input;
+    echo esc_html($user_input);

ИСПРАВЛЕННЫЕ ФАЙЛЫ (полностью):
• database.php (100 строк)
• template.php (80 строк)

СЛЕДУЮЩИЙ ШАГ: "Передайте исправленный код в Аналитик-Документатор"
```
