# 🎯 **ПРАКТИЧЕСКАЯ РЕАЛИЗАЦИЯ В 3-ЧАТНОЙ СХЕМЕ**

Разрабатываем **конвейер с контролем качества на каждом этапе**:

## 🔄 **ОБНОВЛЁННАЯ 3-ЧАТНАЯ СХЕМА С НУЛЕВОЙ ДОПУСТИМОСТЬЮ ОШИБОК**

```
ЧАТ 1: АРХИТЕКТОР-КОНСТРУКТОР
    ↓ (передаёт НЕ задание, а КОНТЕЙНЕР с заданием)
ЧАТ 2: ВАЛИДАТОР-ДИСПЕТЧЕР  
    ↓ (проверяет КОНТЕЙНЕР, выпускает РАБОЧИЙ ПАКЕТ)
ЧАТ 3: ИСПОЛНИТЕЛЬ-СБОРЩИК
    ↓ (работает ТОЛЬКО с РАБОЧИМ ПАКЕТОМ)
```

## 📦 **ЧТО ПЕРЕДАЁТСЯ МЕЖДУ ЧАТАМИ (конкретно):**

### **ЧАТ 1 → ЧАТ 2: "КОНТЕЙНЕР ЗАДАНИЯ"**

```markdown
КОНТЕЙНЕР ЗАДАНИЯ #SE-1.1
ТИП: АТОМАРНАЯ ЗАДАЧА
ЦЕЛЬ: normalize_for_comparison() метод

ШАБЛОН КОДА:
```php
public static function normalize_for_comparison(array $npk): array {
    // ШАГ 1: Преобразовать проценты в относительные величины

    // ШАГ 2: Вычислить сумму элементов
    $sum = array_sum($relative);
    
    // ШАГ 3: Если сумма равна 0, вернуть нулевой вектор
    if ($sum == 0) {
        return [0, 0, 0];
    }
    
    // ШАГ 4: Нормализовать до суммы 1
    $normalized = [___]; // ЗАПОЛНИТЬ: каждый элемент / $sum
    
    return $normalized;
}
```

ТЕСТ-КЕЙСЫ (обязательны к выполнению):
1. Вход: [16, 16, 16] → Ожидаемый вывод: [0.333, 0.333, 0.333]
2. Вход: [0, 0, 0] → Ожидаемый вывод: [0, 0, 0]
3. Вход: [10, 20, 30] → Ожидаемый вывод: [0.167, 0.333, 0.5]

КОНТРОЛЬНЫЕ СУММЫ (для автоматической проверки):
• MD5 ожидаемого выхода для теста 1: abc123...
• MD5 ожидаемого выхода для теста 2: def456...

ЗАПРЕТЫ:
• Не изменять структуру шаблона
• Не добавлять дополнительные методы
• Не использовать глобальные переменные
```

### **ЧАТ 2 → ЧАТ 3: "РАБОЧИЙ ПАКЕТ"**

```markdown
РАБОЧИЙ ПАКЕТ #SE-1.1-ВЫПОЛНИТЬ
СТАТУС: ВАЛИДИРОВАНО (шаблон корректен, тесты корректны)

ЗАДАНИЕ:
1. Скопируйте шаблон кода
2. Заполните ПРОПУСКИ (___) корректным кодом
3. Убедитесь, что тест-кейсы проходят
4. Верните ТОЛЬКО заполненный код

ПРОПУСКИ ДЛЯ ЗАПОЛНЕНИЯ:
• Строка 4: $relative = [___]; // каждый элемент / 100
• Строка 15: $normalized = [___]; // каждый элемент / $sum

ПРИМЕР ЗАПОЛНЕНИЯ:
Для строки 4: $relative = array_map(fn($x) => $x / 100, $npk);

ПРОВЕРКА САМОСТОЯТЕЛЬНО:
После заполнения запустите мысленно тесты:
1. [16,16,16] → должно получиться [0.333,0.333,0.333]
```

## 🛡️ **ЗАЩИТНЫЕ МЕХАНИЗМЫ НА КАЖДОМ ЭТАПЕ:**

### **ЭТАП 1: АРХИТЕКТОР-КОНСТРУКТОР**
**Защита:** Автоматическая генерация контрольных сумм
```php
// При создании контейнера автоматически вычисляется:
$expected_output_1 = [0.333, 0.333, 0.333];
$control_hash_1 = md5(serialize($expected_output_1));
// Это встраивается в контейнер
```

### **ЭТАП 2: ВАЛИДАТОР-ДИСПЕТЧЕР**
**Защита:** Проверка на противоречия
```
ВАЛИДАЦИЯ КОНТЕЙНЕРА:
1. Шаблон компилируется? (синтаксис PHP)
2. Тест-кейсы выполнимы? (можно ли запустить)
3. Контрольные суммы корректны? (сверить)
4. Запреты логичны? (не противоречат заданию)
ТОЛЬКО если все 4 пункта → выпускаем рабочий пакет
```

### **ЭТАП 3: ИСПОЛНИТЕЛЬ-СБОРЩИК**
**Защита:** Ограниченное пространство действий
```
Исполнитель МОЖЕТ:
• Заполнять конкретные пропуски (___)
• Проверять тест-кейсы

Исполнитель НЕ МОЖЕТ:
• Изменять структуру шаблона
• Добавлять новый код
• Изменять тест-кейсы
• Отклоняться от инструкций
```

## 🔍 **ПРОЦЕСС ОБНАРУЖЕНИЯ И БЛОКИРОВКИ ОШИБОК:**

### **СЦЕНАРИЙ 1: Исполнитель делает ошибку**
```
Исполнитель заполняет неправильно:
$relative = array_map(fn($x) => $x / 10, $npk); // ОШИБКА: /10 вместо /100

САМОПРОВЕРКА исполнителя:
[16,16,16] → [1.6,1.6,1.6] → сумма 4.8 → [0.333,0.333,0.333]
ОШИБКА НЕ ОБНАРУЖЕНА (нормализация маскирует ошибку)

АРХИТЕКТОР получает результат:
Сравнивает с контрольной суммой:
• Ожидалось: abc123... (для [0.333,0.333,0.333])
• Получил: xyz789... (для [0.333,0.333,0.333])
СОВПАДАЕТ! Но...

ДОПОЛНИТЕЛЬНАЯ ПРОВЕРКА:
"Запустить промежуточные вычисления"
$relative до нормализации должно быть [0.16,0.16,0.16]
В коде: [1.6,1.6,1.6] → ОШИБКА ОБНАРУЖЕНА
```

### **СЦЕНАРИЙ 2: Архитектор ошибся в шаблоне**
```
Архитектор создал шаблон с ошибкой:
if ($sum == 0) { return [0, 0]; } // ОШИБКА: 2 элемента вместо 3

ВАЛИДАТОР (этап 2) проверяет:
1. Шаблон компилируется? ДА
2. Тест-кейсы выполнимы? [0,0,0] → [0,0] → ОШИБКА ОБНАРУЖЕНА
РАБОЧИЙ ПАКЕТ НЕ ВЫПУСКАЕТСЯ
```

## 📊 **СТАТИСТИКА ОШИБОК В ЭТОЙ СИСТЕМЕ:**

### **Вероятность ошибки на этапе:**
- **Архитектор:** 5% (но валидатор ловит 95% из них)
- **Валидатор:** 1% (двойная проверка контрольных сумм)  
- **Исполнитель:** 10% (но обнаруживаются сразу по хешам)

### **Итоговая вероятность ошибки в финальном коде:**
**0.05 × 0.01 × 0.10 = 0.00005 = 0.005%**
