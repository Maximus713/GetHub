# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

На разработку плагина для Wordpress с установленным Element pro
## Калькулятор концентрации рабочего раствора

_(самостоятельный модуль, этап разработки)_

---

## 1. НАЗНАЧЕНИЕ И ГРАНИЦЫ ОТВЕТСТВЕННОСТИ

### 1.1. Назначение калькулятора

Калькулятор предназначен **исключительно** для расчёта:

- безопасной концентрации рабочего раствора,
    
- массы удобрения в граммах,
    
- визуальной оценки риска выбранной концентрации
    

**с учётом влажности грунта перед подкормкой**.

### 1.2. Что калькулятор НЕ делает (критично)

Калькулятор концентрации:

- ❌ не подбирает удобрения,
    
- ❌ не анализирует состав NPK,
    
- ❌ не рассчитывает элементы N, P, K,
    
- ❌ не оценивает культуру или фазу роста.
    

Он работает **с абстрактным удобрением**, где важна только концентрация раствора.

---

## 2. ИСТОЧНИК ДАННЫХ (ОБЯЗАТЕЛЬНО)

### 2.1. Единый источник истины

Все данные берутся **ТОЛЬКО** из файла:

```
config/npk-database.php
```

Калькулятор обращается к методу:

```
NPK_Database::get_concentration_profiles()
```

### 2.2. Запрещено

- Дублировать агрономические данные в JavaScript
    
- Вычислять диапазоны или градиенты «на глаз»
    
- Интерпретировать данные иначе, чем описано ниже
    

---

## 3. ИНТЕРПРЕТАЦИЯ ДАННЫХ ПРОФИЛЯ (КРИТИЧЕСКИЙ РАЗДЕЛ)

### 3.1. Структура профиля грунта (обобщённо)

Каждый профиль содержит:

- `ranges`
    
- `states`
    
- `warning` (опционально)
    

---

### 3.2. Роли полей `ranges` (ЖЁСТКО ФИКСИРОВАНО)

|Поле|Назначение|Используется|
|---|---|---|
|`absolute_min`|Физически допустимый минимум|**min ползунка**|
|`absolute_max`|Физически допустимый максимум|**max ползунка**|
|`min / max`|Рабочий диапазон|Информационно|
|`default`|Стартовое значение|Инициализация|
|`optimal_min / optimal_max`|Справочные данные|**НЕ используются**|

❗ `optimal_*` **игнорируются полностью** и не участвуют в логике.

---

### 3.3. Роли `states` (КЛЮЧЕВАЯ ЛОГИКА)

Каждый `state` содержит:

- `range` → диапазон концентраций
    
- `color` → цвет состояния
    
- `name` → текстовое название
    
- `description` → пояснение
    
- `emoji` → визуальный маркер (если есть)
    

#### Определение состояния:

Текущая концентрация относится к тому `state`,  
в диапазон `range` которого она попадает.

---

## 4. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС

---

### 4.1. Выбор состояния грунта (ОБЯЗАТЕЛЬНО)

```
🏜️ СОСТОЯНИЕ ГРУНТА ПЕРЕД ПОДКОРМКОЙ
[🔴 СУХОЙ] [🟡 СЛАБО ВЛАЖНЫЙ] [🟢 ВЛАЖНЫЙ]
```

- Формат: кнопки
    
- По умолчанию: **ВЛАЖНЫЙ**
    
- При смене:
    
    - обновляется диапазон концентрации,
        
    - обновляется цвет шкалы,
        
    - обновляется предупреждение.
        

---

### 4.2. Блок «Параметры раствора»

#### 4.2.1. Поле «Объём воды»

- Тип: number + стрелки
    
- Минимум: **0.5 л**
    
- Максимум: **`water_volume_max` из базы**
    
- Логика шага:
    
    - до 10 л → шаг **0.5 л**
        
    - после 10 л → шаг **1 л**
        

---

#### 4.2.2. Поле «Концентрация раствора»

- Тип: number
    
- Диапазон:
    
    - min = `absolute_min`
        
    - max = `absolute_max`
        
- Шаг: 0.01
    
- Связано со слайдером
    

##### Цвет фона поля:

- Меняется **динамически**
    
- От белого → к цвету текущего `state.color`
    
- Источник цвета — `states[].color`
    

---

### 4.3. Шкала концентрации (ЕДИНСТВЕННАЯ)

#### 4.3.1. Общие требования

- Одна шкала
    
- Ползунок поверх шкалы
    
- **Никаких текстовых меток** («низкая», «средняя» и т.п.)
    

---

#### 4.3.2. Градиент шкалы (КРИТИЧЕСКОЕ ПРАВИЛО)

- Градиент формируется **ТОЛЬКО по данным из PHP**
    
- JavaScript **НЕ вычисляет проценты**
    

##### Нормализация:

- `absolute_min` → 0%
    
- `absolute_max` → 100%
    

##### Для каждого `state` PHP передаёт:

```
startPercent
endPercent
color
```

JS только применяет:

```
linear-gradient(...)
```

---

## 5. БЛОК РЕЗУЛЬТАТА

### 5.1. Расчёт массы удобрения

Формула:

```
масса (г) = (концентрация / 100) × объем воды × 1000
```

- Масса: 1 знак после запятой
    
- Концентрация: 2 знака
    

---

### 5.2. Отображение результата

```
[ Удобрения нужно: 50.0 г ]
[ Концентрация: 0.50% ] ← цвет как у шкалы
[ Состояние: Рабочая норма 🟢 ]
```

- Цвет концентрации = цвет текущего `state`
    
- Состояние:
    
    - `name`
        
    - `emoji`
        
    - цвет `state.color`
        

---

### 5.3. Блок комментариев

- Визуально присутствует
    
- Пока без логики
    
- Может быть `textarea` или `div`

## 1. КРИТИЧЕСКИЕ НЕСООТВЕТСТВИЯ В ДАННЫХ

---

### 1.1. `water_volume_max` — где брать?

**Факт:**

- В `npk-database.php` поле есть:
    

```php
get_constants()['thresholds']['water_volume_max']
```

**РЕШЕНИЕ (ОКОНЧАТЕЛЬНОЕ):**

✅ Использовать **ТОЛЬКО**:

```php
NPK_Database::get_constants()['thresholds']['water_volume_max']
```

❌ **НЕ переносить** `water_volume_max` в профили концентрации  
❌ **НЕ дублировать** в других местах

**Логика:**

- Объём воды — **глобальный параметр калькулятора**
    
- Он **не зависит от типа грунта**
    

👉 Это **нормативное ограничение**, а не агрономический профиль.

---

### 1.2. `startPercent / endPercent` — их нет в базе

Ты абсолютно прав: **их нет и быть не должно** в базе.

**ИСПРАВЛЕНИЕ ФОРМУЛИРОВКИ ТЗ:**

❌ Неверно:

> «PHP передаёт startPercent / endPercent как часть базы»

✅ Верно:

> **PHP вычисляет startPercent / endPercent на лету на основе ranges и states**

---

#### Окончательная формула (ОБЯЗАТЕЛЬНАЯ):

```php
$startPercent = (
    ($state['range'][0] - $ranges['absolute_min'])
    / ($ranges['absolute_max'] - $ranges['absolute_min'])
) * 100;

$endPercent = (
    ($state['range'][1] - $ranges['absolute_min'])
    / ($ranges['absolute_max'] - $ranges['absolute_min'])
) * 100;
```

📌 **Где происходит расчёт:**  
✅ В PHP  
❌ Не в JavaScript

📌 **Что хранится в базе:**

- только `range`
    
- только «чистые данные»
    

---

### 1.3. Единицы измерения концентрации (КРИТИЧЕСКИ ВАЖНО)

Это **самый важный вопрос**, ты абсолютно правильно его поднял.

#### ОТВЕТ (ЖЁСТКО ФИКСИРУЕМ):

> **Все значения концентрации в `npk-database.php` — в ПРОЦЕНТАХ.**

То есть:

|Значение|Интерпретация|
|---|---|
|`0.05`|**0.05%**|
|`0.2`|**0.2%**|
|`0.8`|**0.8%**|

❌ Это **НЕ доли**  
❌ Это **НЕ 5%**

---

#### Следствия (обязательные):

- Формула массы:
    

```text
масса = (концентрация / 100) × объем × 1000
```

— **корректна без изменений**

- Поле ввода концентрации показывает именно `%`
    
- Слайдер работает в диапазоне `%`

## 2. ВОПРОСЫ ПО ЛОГИКЕ

---

### 2.1. Границы диапазонов (`range`)

**РЕШЕНИЕ:**

Используется **включение по нижней границе, исключение по верхней**, кроме последнего диапазона.

```php
if ($value >= $start && $value < $end)
```

Для последнего состояния:

```php
$value <= $end
```

📌 Это исключает двойное попадание  
📌 Это стандартная практика диапазонов

---

### 2.2. Цвет поля концентрации — как считать?

❌ НЕ просто `state.color`  
❌ НЕ фиксированный цвет

✅ **ЛИНЕЙНАЯ ИНТЕРПОЛЯЦИЯ**

---

#### Алгоритм (обязательный):

- Начальный цвет: `#ffffff`
    
- Конечный цвет: `state.color`
    
- Коэффициент:
    

```text
(value - state.range[0]) / (state.range[1] - state.range[0])
```

📌 В начале диапазона — почти белый  
📌 В конце — чистый `state.color`

---

### 2.3. Градиент шкалы — какие состояния?

**Ответ:**

✅ Градиент строится **ТОЛЬКО из состояний текущего профиля**

- `dry` → только его `states`
    
- `wet` → только его `states`
    

❌ Никаких «общих» цветов  
❌ Никаких переходов между профилями
