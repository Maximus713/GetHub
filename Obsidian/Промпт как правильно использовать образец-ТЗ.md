# ПРОМПТ ДЛЯ ПРОДОЛЖЕНИЯ РАБОТЫ НАД ТЗ КАЛЬКУЛЯТОРА ПОДБОРА УДОБРЕНИЙ

## КОНТЕКСТ ДЛЯ ЧАТА

Ты продолжаешь работу над созданием ТЗ для модуля "Калькулятор подбора удобрений по составу NPK" (Модуль 2). Только что тебе предоставили ОБРАЗЕЦ ТЗ для Модуля 1 ("Калькулятор концентрации рабочего раствора").

## КРИТИЧЕСКАЯ ИНФОРМАЦИЯ ОБ ОБРАЗЦЕ

### 1. ЦЕННОСТЬ ОБРАЗЦА (ГЛАВНОЕ!)
Этот образец НЕ ПРОСТО пример структуры. Это **ВЫВЕРЕННЫЙ НА ПРАКТИКЕ ДОКУМЕНТ**, где:
- **Каждое требование** прошло проверку реальной разработкой
- **Каждое ограничение** — это исправленная ошибка
- **Каждая контрольная точка** — это предотвращённая проблема

**ЭТО НЕ ТЕОРИЯ — ЭТО ПРАКТИЧЕСКИЙ ОПЫТ, УПАКОВАННЫЙ В ТЗ.**

### 2. КЛЮЧЕВЫЕ ПРИНЦИПЫ ИЗ ОБРАЗЦА, КОТОРЫЕ НЕЛЬЗЯ ТЕРЯТЬ:
- **Архитектурная чистота** (MVC-подобная структура, разделение слоёв)
- **Защитные механизмы** (контрольные точки проверки кода, явные запреты)
- **WordPress-специфика** (полный жизненный цикл, правильные хуки, регистрация скриптов)
- **Технические паттерны** (FormData() для AJAX, requestAnimationFrame() для UI)
- **Чёткая иерархия** (от критически важного к второстепенному)

### 3. ЧТО НЕ ТРОГАТЬ В СТРУКТУРЕ:
- Общую архитектуру (слои данных/логики/представления)
- Систему запретов и контрольных точек
- WordPress-интеграцию (жизненный цикл, хуки)
- Технические требования (FormData, requestAnimationFrame)
- Стиль и тон документа

## ТВОЯ ЗАДАЧА СЕЙЧАС

### 1. ИЗУЧИТЬ ОБРАЗЕЦ И РЕАЛЬНУЮ БД
Сначала внимательно изучи оба документа:
1. **ОБРАЗЕЦ ТЗ** (модуль концентрации) — понять СТРУКТУРУ и ПРИНЦИПЫ
2. **npk-database.php** (реальная БД) — понять ФАКТИЧЕСКИЕ ДАННЫЕ

### 2. АНАЛИЗ КЛЮЧЕВЫХ РАЗЛИЧИЙ МЕЖДУ МОДУЛЯМИ
Модуль 1 (концентрация) vs Модуль 2 (подбор):
- **Модуль 1:** Расчёт масс и концентраций, работа с типами грунта
- **Модуль 2:** Подбор готовых удобрений, сравнение NPK, работа с культурами/фазами
- **ОБЩЕЕ:** Использование одной БД, архитектура, WordPress-интеграция

### 3. СОЗДАТЬ ТЗ ДЛЯ МОДУЛЯ 2 ПО АНАЛОГИИ С ОБРАЗЦОМ

**ШАГИ:**
1. **Взять СТРУКТУРУ образца** (разделы, последовательность, тон)
2. **Заменить специфику Модуля 1 на специфику Модуля 2:**
   - Источник данных: `get_crops()` вместо профилей концентраций
   - Логика: алгоритм Отиаи вместо расчёта массы
   - Интерфейс: кнопки культур/фаз вместо слайдера концентрации
   - Результаты: таблица с прогресс-барами вместо расчёта массы
3. **Сохранить ВСЕ защитные механизмы:**
   - Контрольные точки проверки кода
   - Явные запреты (URLSearchParams и т.д.)
   - WordPress жизненный цикл
   - Архитектурные требования

### 4. УЧЕСТЬ СПЕЦИФИКУ ДАННЫХ ИЗ РЕАЛЬНОЙ БД
В npk-database.php:
- Культуры: ключи `tomato`, `cucumber`, `pepper`, `eggplant`, `zucchini`
- Фазы: ключи `seedling`, `vegetation`, `blooming`, `fruiting`
- Данные: NPK культур [1.0, 2.0, 1.0] vs NPK удобрений [16, 16, 16] → нужна обработка масштаба

## КРИТИЧЕСКИЕ ТРЕБОВАНИЯ К НОВОМУ ТЗ

1. **НЕ ИЗОБРЕТАТЬ ВЕЛОСИПЕД** — использовать проверенные решения из образца
2. **НЕ ТЕРЯТЬ ЗАЩИТНЫЕ МЕХАНИЗМЫ** — каждый запрет в образце там не просто так
3. **СОХРАНИТЬ АРХИТЕКТУРНУЮ ЧИСТОТУ** — тот же подход к слоям данных/логики/представления
4. **УЧЕСТЬ РЕАЛЬНЫЕ ДАННЫЕ БД** — но через призму структур из образца

## ФИНАЛЬНЫЙ РЕЗУЛЬТАТ ДОЛЖЕН БЫТЬ

**ТЗ для Модуля 2, которое:**
- По структуре и тону НЕОТЛИЧИМО от образца (Модуль 1)
- По содержанию точно описывает Калькулятор подбора удобрений
- Использует реальные данные из npk-database.php
- Сохраняет ВСЕ защитные механизмы и лучшие практики из образца
