# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Калькулятор концентрации рабочего раствора (WordPress)

---

## 1. ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК РАБОТЫ

1.1. Перед началом разработки исполнитель обязан:

- полностью изучить ТЗ;
    
- выявить противоречия или нехватку данных;
    
- **приостановить разработку и задать вопросы**, если требуется предположение.
    

1.2. Начало кодинга без полного понимания ТЗ запрещено.

---

## 2. НАЗНАЧЕНИЕ КАЛЬКУЛЯТОРА

Калькулятор предназначен для:

- расчёта концентрации рабочего раствора;
    
- расчёта массы удобрения (г);
    
- визуальной оценки уровня риска концентрации;
    
- учёта состояния грунта перед подкормкой.
    

---

## 3. ИСТОЧНИК ДАННЫХ (КРИТИЧЕСКОЕ ТРЕБОВАНИЕ)

### 3.1. Единый источник данных

Все справочные данные берутся **ИСКЛЮЧИТЕЛЬНО** из файла:

```
config/npk-database.php
```

Допустимые методы доступа:

- `NPK_Database::get_fertilizers()`
    
- `NPK_Database::get_concentration_profiles()`
    
- `NPK_Database::get_constants()`
    

❌ Запрещено:

- дублировать данные в JavaScript;
    
- изменять данные базы;
    
- интерпретировать данные «по-своему».
    

---

### 3.2. Разделение данных и логики

- **База данных (`npk-database.php`)**:
    
    - содержит справочные данные;
        
    - может содержать технические ошибки (0, NULL, >100).
        
- **Calculation_Engine**:
    
    - содержит ВСЕ формулы расчёта;
        
    - является **ЕДИНСТВЕННЫМ источником истины** для итоговых расчётов;
        
    - не обращается напрямую к `NPK_Database`.
        
- **JavaScript**:
    
    - выполняет предварительный локальный расчёт ТОЛЬКО для UI-отклика;
        
    - не считается источником корректного результата;
        
    - итоговые данные подтверждаются PHP.
        

---

### 3.3. Единицы измерения

- Все концентрации в базе — в процентах.
    
- `0.05` = `0.05%`
    
- В формулах используется `(концентрация / 100)`.
    

---

## 4. ВЫБОР УДОБРЕНИЯ (КРИТИЧЕСКОЕ ТРЕБОВАНИЕ)

### 4.1. Обязательность

Калькулятор **НЕ МОЖЕТ работать без выбранного удобрения**.  
Отсутствие выбора = некорректная реализация.

---

### 4.2. Сущность «Удобрение»

Каждое удобрение содержит:

- `id`
    
- `name`
    
- `npk`
    
- `solubility_total` (общая растворимость, %)
    
- `type`
    
- `notes`
    

Источник — ТОЛЬКО база данных.

---

### 4.3. Учёт растворимости

Расчёт ОБЯЗАТЕЛЬНО учитывает `solubility_total`.

❌ Расчёт без учёта `solubility_total` запрещён.

---

### 4.4. Валидация solubility_total (ЕДИНАЯ ЛОГИКА)

**Ответственный класс:** `Data_Adapter`

Правило обработки:

```php
protected function validate_solubility_total($value) {
    if ($value === null || $value === 0) return 100;
    if ($value < 1) return 1;
    if ($value > 100) return 100;
    return (float)$value;
}
```

Требования:

- база НЕ изменяется;
    
- логика используется ВО ВСЕХ местах;
    
- `Calculation_Engine` получает ТОЛЬКО валидированные данные.
    

---

### 4.5. Интерфейс выбора удобрения

- `<select>` под выбором грунта;
    
- выбор обязателен;
    
- значение по умолчанию — первое удобрение из базы;
    
- формат списка:  
    `Название [N-P-K]`;
    
- сортировка по `id`;
    
- при изменении — немедленный перерасчёт.
    

---

## 5. ПРОФИЛИ ГРУНТА

### 5.1. Типы

- `dry`
    
- `medium`
    
- `wet` (по умолчанию)
    

---

### 5.2. Глобальный диапазон концентрации

Единый для всех грунтов:

- min: `0.05%`
    
- max: `1.5%`
    
- default: `0.3%`
    

❌ `min/max` из профилей НЕ используются для ограничений.

---

### 5.3. States

- используются для интерпретации концентрации;
    
- диапазоны включают границы;
    
- при совпадении — берётся первый state;
    
- вне диапазона — крайние состояния.
    

---

## 6. АРХИТЕКТУРА ПЛАГИНА (ОБЯЗАТЕЛЬНО)

### 6.1. Принцип

Калькулятор концентрации — **изолированный модуль**, готовый к объединению с другими калькуляторами без переписывания логики.

---

### 6.3. Разделение ответственности

|Класс|Ответственность|
|---|---|
|Data_Adapter|Валидация + подготовка данных|
|Calculation_Engine|Все расчёты и финальная логика|
|Shortcode|HTML|

❌ Обращение `Calculation_Engine` напрямую к базе запрещено.

---

## 7. ЦВЕТОВАЯ ЛОГИКА

- один state = один цвет;
    
- без градиентов и сегментов;
    
- цвет определяется ТОЛЬКО state.
    

---

## 8. ПОВЕДЕНИЕ ИНТЕРФЕЙСА

- первый расчёт выполняется автоматически;
    
- кнопка «Рассчитать» не используется;
    
- смена грунта меняет ТОЛЬКО интерпретацию;
    
- концентрация и вода не изменяются автоматически.
    

---

## 9. ФОРМУЛА (ЕДИНСТВЕННЫЙ ИСТОЧНИК)

```
масса_г = (концентрация_% / 100) × объем_л × 1000 × (100 / solubility_total_%)
```

Финальный расчёт выполняется ТОЛЬКО в `Calculation_Engine`.
