# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Калькулятор концентрации рабочего раствора (WordPress)

---

## 1. ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК РАБОТЫ

Перед началом кодинга разработчик обязан:

- полностью изучить ТЗ
- выявить противоречия или нехватку данных
- **приостановить разработку и задать вопросы**, если требуется предположение

Начало кодинга без полного понимания ТЗ запрещено.

---

## 2. НАЗНАЧЕНИЕ КАЛЬКУЛЯТОРА

Калькулятор предназначен для:

- расчёта **концентрации рабочего раствора**
- расчёта **массы удобрения (г)**
- визуальной оценки **уровня риска концентрации**
- учёта **состояния грунта перед подкормкой**

---

## 3. ИСТОЧНИК ДАННЫХ (КРИТИЧЕСКИ ВАЖНО)

### 3.1. Единый источник данных
Все справочные данные берутся **ТОЛЬКО** из:

```
config/npk-database.php
```

Используются методы:
- `NPK_Database::get_concentration_profiles()`
- `NPK_Database::get_fertilizers()`
- `NPK_Database::get_constants()`

❌ Запрещено дублировать данные в JS  
❌ Запрещено интерпретировать данные «по-своему»

### 3.2. Хранение формул и данных
**Данные** (справочные) хранятся в базе `npk-database.php`:
- Профили концентраций и состояния грунта
- Список удобрений с NPK и растворимостью
- Константы, ограничения, цветовые схемы

**Формулы расчёта** хранятся в коде класса `Calculation_Engine`:
- Основная формула расчёта массы (Раздел 9.1)
- Все расчётные алгоритмы
- Логика определения состояния раствора

### 3.3. Единицы измерения
- Все концентрации в базе — **проценты**
- `0.05` = **0.05%**
- В формулах используется `(концентрация / 100)`

---

## 4. ВЫБОР УДОБРЕНИЯ (КРИТИЧЕСКОЕ ТРЕБОВАНИЕ)

### 4.1. Обязательность выбора

Калькулятор **НЕ МОЖЕТ работать без выбора удобрения**.

> Калькулятор без учёта удобрения считается **некорректным**.

### 4.2. Сущность «Удобрение»
Каждое удобрение содержит:
- `id`
- `name`
- `npk` (N–P–K)
- `solubility_total` — общая растворимость удобрения (%)
- `type` — тип удобрения
- `notes` — описание

Все удобрения берутся **из базы данных**.

### 4.3. Модель расчёта

Концентрация раствора зависит от:
- выбранного удобрения и его `solubility_total`
- желаемой концентрации растворённых веществ
- объёма воды

❌ Запрещён расчёт без учёта `solubility_total`


### 4.4. Валидация solubility_total

**Значение `solubility_total` в базе данных должно быть в диапазоне 1-100%.**

**В случае некорректных данных:**
1. **На стороне PHP (Data_Adapter):**
   - Значения < 1% → корректируются до 1%
   - Значения > 100% → корректируются до 100%
   - Значения NULL или 0 → устанавливаются 100%

2. **На стороне JavaScript:**
   - Проверка перед расчётом: `Math.max(1, Math.min(100, solubility_total || 100))`
   - Деление на ноль невозможно

**Безопасные значения по умолчанию:**
- Минимальное: 1% (избегает деления на ноль)
- Максимальное: 100% (полная растворимость)
- По умолчанию: 100% (если данные отсутствуют)



**Пример кода валидации:**
```php
// PHP
$solubility = max(1, min(100, $fertilizer['solubility_total'] ?? 100));
```

### 4.4. Интерфейс выбора удобрения

- **Элемент:** выпадающий список (`<select>`)
- **Расположение:** под кнопками выбором грунта
- **Обязательность:** обязательно для расчёта
- **Значение по умолчанию:** первое удобрение из базы данных
- **Формат отображения в списке:**
    ```
    [Название] [NPK в формате N-P-K]
    ```
    Пример: `Азофоска (Нитроаммофоска) [16-16-16]`
- **Дополнительная информация:**
    - При выборе удобрения НЕ показывать подробную информацию
    - При наведении (hover) можно показывать `notes` из базы данных
    - Сортировка: по `id` (как в базе данных)
- **Валидация:**
    - При отсутствии выбора — блокировать расчёт
    - При изменении выбора — пересчитывать результат

### 3.5. Ответственность за корректность данных

**Иерархия ответственности:**

1. **База данных — источник данных:**
   - Содержит "сырые" данные об удобрениях
   - Не гарантирует семантическую корректность значений
   - Может содержать технические ошибки (0, NULL, >100%)

2. **Data_Adapter — валидатор и адаптер:**
   - Обязан проверять и корректировать значения перед использованием
   - Защищает UI и расчётные формулы от некорректных данных
   - Не изменяет базу данных, только адаптирует данные для использования

3. **Calculation_Engine — расчёт с защитой:**
   - Использует уже валидированные данные от Data_Adapter
   - Содержит дополнительную защиту "на всякий случай"
   - Не обращается напрямую к NPK_Database


#### 3.5.1 Единая логика обработки некорректных значений solubility_total

**Иерархия обработки (от более к менее критичным):**

1. **Значение = 0 или NULL:**
   - Устанавливается **100%** (полная растворимость)
   - Обоснование: Безопаснее предположить полную растворимость, чем рисковать делением на ноль
   - Логирование: Запись в лог для администратора об ошибке в базе

2. **Значение < 1% (например, 0.5):**
   - Корректируется до **1%** (минимально возможное)
   - Обоснование: Сохранение семантики "некоторое количество растворимого вещества"

3. **Значение > 100% (например, 150):**
   - Корректируется до **100%** (максимально возможное)
   - Обоснование: Не может быть растворимости более 100%

**Код реализации (Data_Adapter):**
```php
protected function validate_solubility_total($value) {
    if ($value === null || $value === 0) {
        return 100; // Полная растворимость при отсутствии данных
    }
    if ($value < 1) {
        return 1;   // Минимальная растворимость
    }
    if ($value > 100) {
        return 100; // Максимальная растворимость
    }
    return (float)$value;
}
```
**Требование:** Использовать эту единую логику во всех классах, работающих с solubility_total.








**Правило обработки некорректных данных:**

```php
// Data_Adapter обязан:
if ($solubility_total <= 0 || $solubility_total > 100) {
    // Исправляем ошибку базы, не ломаем калькулятор
    $solubility_total = 100; // безопасное значение по умолчанию
    // Можно добавить логгирование для администратора
}

```




#### 3.6. Защита от некорректных данных в будущем

**Требование:** Реализовать полную защиту от некорректных значений `solubility_total`, даже если текущая база содержит только корректные данные.

**Причины:**
1. **База данных может измениться:** При добавлении новых удобрений возможны ошибки ввода
2. **Обновления базы:** Администратор может вручную изменить значения
3. **Будущие интеграции:** Данные могут поступать из внешних источников
4. **Принцип защиты:** Код должен быть устойчив к ошибкам в данных

**Минимальная защита:**
```php
// Data_Adapter обязан выполнять:
$solubility = max(1, min(100, $fertilizer_data['solubility_total'] ?? 100));
```



## 5. ПРОФИЛИ ГРУНТА

### 5.1. Типы грунта

- dry — сухой
- medium — слабо влажный
- wet — влажный

По умолчанию: **wet**

### 5.2. Глобальный диапазон концентраций

**Для слайдера концентрации используются ЕДИНЫЕ значения для всех грунтов:**
- `absolute_min = 0.05%` (нижний предел)
- `absolute_max = 1.5%` (верхний предел)
- `default = 0.3%` (значение по умолчанию)

**Поля `min`, `max`, `optimal_min`, `optimal_max` в базе — информационные, не используются в логике.**

❌ Запрещено использовать `min`/`max` из профилей для ограничений слайдера

### 5.3. Состояния (`states`)

Различия между грунтами определяются **только через states**.

**Структура состояния:**
- `id` — идентификатор
- `name` — название состояния
- `emoji` — визуальный индикатор
- `color` — цвет состояния
- `range [start, end]` — диапазон концентрации
- `description` — описание

**Правило попадания:**
- `[start, end]` — для **ВСЕХ** состояний (включая границы)
- **Нет "дыр"** между состояниями
- **Последнее state** = последний элемент массива `states`

**Обработка граничных значений:**
- Значение 0.15 попадает в ОБА диапазона: `[0.05, 0.15]` и `[0.15, 0.25]`
- **Приоритет:** первый подходящий диапазон в массиве

**Значения вне диапазонов:**
- Ниже `states[0].range[0]` → первое состояние
- Выше последнего `range[1]` → последнее состояние

**Пример корректных диапазонов:**
```php
'states' => [
    ['range' => [0.05, 0.15]],   // 0.05 ≤ X ≤ 0.15
    ['range' => [0.15, 0.25]],   // 0.15 ≤ X ≤ 0.25
    ['range' => [0.25, 0.35]],   // 0.25 ≤ X ≤ 0.35
]
```
### 5.4. Требование к совместимости калькуляторов (уточнение)

**Текущая реализация:**
- Классы напрямую обращаются к `NPK_Database::get_*()` методам
- Файл базы: `npk-concentration/config/npk-database.php`

**Будущая миграция в shared/:**
- Изменится только путь подключения файла базы
- Интерфейс класса `NPK_Database` останется неизменным
- Все вызовы `NPK_Database::get_*()` продолжат работать

**Запрещено:**
- Создавать лишние абстракции для доступа к данным
- Предусматривать несуществующие будущие изменения




### 6.4.1. Источник данных и адаптер

**Иерархия доступа к данным:**

1. **Единственный источник данных:**
   - Класс `NPK_Database` (`config/npk-database.php`)
   - Методы: `get_fertilizers()`, `get_concentration_profiles()`, `get_constants()`

2. **Адаптер формата (Data_Adapter):**
   - **Не является источником данных**
   - **Не скрывает доступ к `NPK_Database`**
   - Только преобразует данные из формата БД в формат для JavaScript

**Правила использования:**

php
// Правильно:
$fertilizers = NPK_Database::get_fertilizers(); // прямой доступ

// Data_Adapter ТОЛЬКО для подготовки данных для JS:
$js_data = Data_Adapter::prepare_fertilizers_for_js($fertilizers);

// Неправильно:
$fertilizers = Data_Adapter::get_fertilizers(); // НЕТ такого метода!



### Функционал Data_Adapter

**Data_Adapter выполняет ДВЕ функции:**

1. **Валидация и защита:**
   - Проверяет корректность данных из базы
   - Исправляет технические ошибки (например, solubility_total = 0)
   - Защищает UI и расчётные формулы от некорректных данных

2. **Преобразование формата:**
   - Конвертирует данные из формата PHP в формат JavaScript
   - Оптимизирует структуру для фронтенда
   - Убирает лишние поля, добавляет необходимые

**Пример:**
```php
class Data_Adapter {
    public static function prepare_fertilizer($data_from_db) {
        // 1. ВАЛИДАЦИЯ (защита)
        $solubility = $data_from_db['solubility_total'];
        if ($solubility <= 0 || $solubility > 100) {
            $solubility = 100; // исправляем ошибку базы
        }
        
        // 2. ПРЕОБРАЗОВАНИЕ ФОРМАТА
        return [
            'id' => $data_from_db['id'],
            'name' => $data_from_db['name'],
            'npk' => $data_from_db['npk'],
            'solubility' => $solubility, // уже валидированное значение
            'color' => self::get_color_by_type($data_from_db['type'])
        ];
    }
}

```

## 6. АРХИТЕКТУРА ПЛАГИНА

### 6.1. Обязательное архитектурное требование

Калькулятор концентрации **должен разрабатываться как изолированный модуль**, рассчитанный на последующее объединение с другими калькуляторами (в том числе калькулятором выбора удобрений) **без переписывания логики и интерфейса**.

Архитектура плагина, структура папок и разделение ответственности файлов **являются обязательной частью ТЗ** и не могут изменяться исполнителем по своему усмотрению.


### 6.1.1. Уточнение концепции "изолированного модуля"

**Изолированный модуль означает:**

1. **Архитектурная изоляция:**
   - Собственная структура папок и файлов
   - Независимая регистрация в WordPress
   - Отдельные шорткоды, хуки, стили, скрипты

2. **Функциональная целостность:**
   - Модуль содержит ВСЕ необходимое для своей работы
   - Включая выбор удобрения из общей базы данных
   - Имеет полноценный UI для всех своих функций

3. **Что НЕ означает изоляция:**
   - Отсутствие зависимости от общей базы данных
   - Дублирование данных удобрений
   - Возможность работы без данных об удобрениях

**Пример аналогии:** 
"Кухня в квартире — изолированное помещение с собственной сантехникой, электропроводкой и мебелью, но подключенное к общим системам водоснабжения и электричества."

**Реализация:**
- Модуль концентрации СОДЕРЖИТ интерфейс выбора удобрения
- Использует ОБЩУЮ базу данных удобрений
- Может работать НЕЗАВИСИМО от других будущих калькуляторов


### 6.1.2. Реализация выбора удобрения в текущем модуле

**Текущий модуль концентрации ДОЛЖЕН содержать:**

1. **Полноценный интерфейс выбора удобрения:**
   - Выпадающий список (`<select>`) со всеми удобрениями из `NPK_Database::get_fertilizers()`
   - Отображение NPK состава выбранного удобрения
   - Информация о `solubility_total` для пользователя

2. **Архитектурная обязанность модуля:**
   - Модуль концентрации НЕ зависит от других (несуществующих) модулей
   - Содержит весь необходимый UI для своей работы
   - Может работать автономно со встроенным выбором удобрения

3. **Будущая эволюция:**
   - При появлении отдельного модуля выбора удобрения текущий интерфейс может быть заменён
   - API взаимодействия будет описан отдельно
   - До этого момента модуль концентрации полностью самодостаточен

**Требование:** Реализовать выбор удобрения как неотъемлемую часть интерфейса калькулятора концентрации.

3. **Папка конфигурации:** `config/`
4. **Файл базы данных:** `npk-database.php`

**Пример подключения в коде:**
php
// В npk-concentration.php или классе-загрузчике:

### 6.3. Разделение ответственности

Исполнитель обязан строго соблюдать следующие границы:

**Один класс = один файл:**

| Файл | Класс | Ответственность |
|------|-------|----------------|
| `class-data-adapter.php` | `Data_Adapter` | Подготовка данных из БД для JS |
| `class-calculation-engine.php` | `Calculation_Engine` | Расчётные формулы и логика |
| `class-shortcode.php` | `Shortcode` | Вывод HTML через шорткод |
| `class-ajax-handler.php` | `AJAX_Handler` | Обработка AJAX-запросов |

**Запрещено:**
- Объединять несколько классов в одном файле
- Создавать один "мега-класс" со всеми методами
- Менять названия классов или файлов

### 6.4. Требование к совместимости калькуляторов

**Текущее расположение базы данных:**
- `npk-concentration/config/npk-database.php` — основной файл

**Для будущей интеграции:**
- База будет перемещена в `shared/config/`
- Доступ через общий API, а не напрямую к файлу

Калькулятор концентрации **не должен**:
- напрямую обращаться к данным другого калькулятора,
- содержать жёсткие зависимости от выбора удобрения,
- содержать зашитые значения состава удобрений.

Вся интеграция между калькуляторами должна осуществляться:
- через **общую базу данных** (`npk-database.php`),
- через **единый адаптер данных**,
- через **публичный API (PHP / JS)**.

### 6.5. Обязательное условие при разработке

Если в процессе реализации выясняется, что:
- структура папок недостаточна,
- требуется новый общий модуль,
- требуется изменение архитектуры,

исполнитель **обязан приостановить разработку и запросить изменение ТЗ**.  
Самовольное изменение структуры считается нарушением ТЗ.

## 8. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС

Начальное состояние интерфейса

**При загрузке калькулятора:**
1. **Удобрение:** автоматически выбирается первое из списка `get_fertilizers()` (Азофоска 16-16-16)
2. **Расчёт:** выполняется немедленно с параметрами по умолчанию
3. **Интерфейс:** всегда показывает рабочий пример, никогда не бывает пустым

**Техническая реализация:**
- `<select>` с выбором удобрения имеет предустановленное значение
- Изменение выбора удобрения мгновенно запускает перерасчёт
- Кнопка "Рассчитать" не требуется — расчёт происходит автоматически

**Цель:** Пользователь сразу видит работу калькулятора, не требуется дополнительных действий для первого расчёта.

### 8.1. Выбор грунта

- Кнопки
- При смене:
    - концентрация **не меняется**
    - слайдер **не двигается**
    - цвет и состояние **меняются**

**Пример изменения состояния при смене грунта:**
- Концентрация 0.5% для dry грунта → состояние "high" (жёлтый, ⚠️)
- Та же концентрация 0.5% для wet грунта → состояние "optimal" (зелёный, ✅)

**Правило:** При смене типа грунта меняется ТОЛЬКО интерпретация концентрации (состояние, цвет, описание), но НЕ сама концентрация.

**Безопасность:** Пользователь сам отвечает за выбор концентрации для нового типа грунта.

### 8.2. Объём воды

- min: **0.5 л**
- max: `get_constants()['thresholds']['water_volume_max']`
- шаг:
    - <10 л → 0.5
    - ≥10 л → 1.0

### 8.3. Концентрация

- min: 0.05
- max: 1.5
- шаг: 0.01
- двусторонняя связь со слайдером

## 9. РЕЗУЛЬТАТ

### 9.1. Формула

```
масса_удобрения_г = (желаемая_концентрация_% / 100) × объем_воды_л × 1000 × (100 / solubility_total_%)
```

**Где:**
- `желаемая_концентрация_%` — концентрация **всех растворённых веществ** (NPK + растворимый балласт)
- `solubility_total_%` — общая растворимость удобрения из базы данных

### 9.2. Отображение

- масса (г)
- концентрация (%)
- состояние (name + emoji)
- цвет = цвет state
