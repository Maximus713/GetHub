## 2. ПОРЯДОК СОЗДАНИЯ КОМПОНЕНТОВ

   1. [fertilizer-selector-module.php] → Точка входа. Регистрирует модуль в ядре, 
      подключает все классы в правильном порядке. Без этого файла модуль не будет загружен.

   2. [includes/class-selection-engine.php] → Ядро логики. Реализует алгоритм Отиаи, 
      определение порога 75%, fallback-режим, генерацию подсказок. 
      АБСОЛЮТНЫЙ ИСТОЧНИК ИСТИНЫ для всех расчётов.

   3. [includes/class-cache-manager.php] → Кеширование. Хранит результаты работы 
      Selection_Engine (1 час). ДОЛЖЕН БЫТЬ СОЗДАН ДО Data_Adapter и AJAX_Handler, 
      которые его используют.

   4. [includes/class-data-adapter.php] → Подготовка данных для UI. Использует 
      Cache_Manager (№3) для кеширования справочников из БД. 
      Единственный выход — wp_localize_script(). НИКАКОЙ логики расчётов.

   5. [includes/class-ajax-handler.php] → Транспортный слой. Принимает AJAX-запросы, 
      проверяет кеш (№3), при отсутствии вызывает Selection_Engine (№2), 
      сохраняет в кеш и возвращает JSON.

   6. [includes/class-shortcode.php] → Шорткод. Регистрирует [npk_fertilizer_selector], 
      подключает скрипты и стили, передаёт данные из Data_Adapter (№4) в JS.

   7. [templates/selector-template.php] → HTML-шаблон. Чистое отображение, 
      только echo и циклы. НИКАКОЙ логики расчётов, 0 вызовов классов.

   8. [assets/css/selector.css] → Централизованные стили. Все статические стили 
      ТОЛЬКО здесь. Все селекторы с префиксом .npk-. 0 глобальных селекторов.

   9. [assets/js/selector.js] → UX/UI. Обработка событий, Instant Preview, 
      AJAX-запросы к №5, обновление DOM. Все обновления через requestAnimationFrame().
      ФИНАЛЬНЫЙ КОМПОНЕНТ — требует всего: API, данных, DOM, стилей.

## 5. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ
   **Почему алгоритм Отиаи ТОЛЬКО в Selection_Engine:**  
   Это единственный источник истины для соответствия NPK. Любой другой слой, вычисляющий совпадение, создаст рассинхронизацию и сделает систему непредсказуемой.  
   
   **Почему Instant Preview — исключение из правила:**  
   Preview — это UX-эвристика, а не бизнес-логика. Её результат всегда перезаписывается серверным расчётом, не сохраняется и не влияет на смежные системы. ADR-2024-001 явно разрешает такие клиентские оптимизации при маркировке «Preview».  
   
   **Почему Fallback — архитектура, а не баг:**  
   Отсутствие удобрений ≥75% — штатная ситуация. Система не должна показывать пустой экран. 3 лучших варианта с явным флагом «fallback» — это контролируемое поведение, дающее пользователю прозрачность и выбор.
