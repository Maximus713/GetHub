## **ЧАТУ-КОДЕР НУЖНО ТОЛЬКО ЭТО:**

### **1. КОНКРЕТНАЯ ЗАДАЧА «В РАМКАХ ОДНОГО ФАЙЛА»**
- **Что:** «Создай файл X, который делает Y»

### **2. ПОЛНЫЙ КОНТЕКСТ «ЧТО УЖЕ ЕСТЬ»**
- Готовые файлы, которые уже созданы и проверены
- **Точно указанные точки подключения:**
  - «Этот файл будет вызываться из файла A в строке 45»
  - «Используй константу MY_PLUGIN_PATH из plugin.php»
  - «Хук `init` уже зарегистрирован в Core классе»

### **3. ТОЧНЫЕ ТЕХНИЧЕСКИЕ СПЕЦИФИКАЦИИ**
- **Имена:** классов, методов, хуков, констант — без вариантов
- **Параметры:** какие аргументы принимают функции
- **Возвращаемые значения:** что должны возвращать методы
- **Обработка ошибок:** как реагировать на сбои

### **4. ГОТОВЫЕ ФРАГМЕНТЫ СЛОЖНОГО КОДА**
- SQL-запросы с плейсхолдерами
- Обработка AJAX с nonce
- Работа с WP_Error

### **5. ГРАНИЧНЫЕ УСЛОВИЯ И КЕЙСЫ**
- «Если опции нет в БД — использовать значения по умолчанию»
- «При удалении плагина — очищать таблицу X»
- «Кэшировать результат на 1 час»

---

## **ЧЕГО НЕ НУЖНО ЧАТУ-КОДЕРУ:**

1. **Общей картины** — он не должен понимать весь плагин
2. **Принятия решений** — «как лучше сделать» решено до него
3. **Проверки совместимости** — это сделает проверяющий
4. **Оптимизации архитектуры** — она уже задана

---

## **ПРАКТИЧЕСКИЙ ВЫВОД:**

**Чат-кодер — это «идеальный исполнитель», который получает:**  
1. Файл для создания  
2. Точные инструкции «что писать в каждой строке»  
3. Контекст «куда этот файл встроится»

**Он не думает, не проектирует, не проверяет — только переводит инструкции в код.**




Это возможно? **Да**, если:
- Чат 1 (Архитектор) сделал детальнейший пошаговый план
- Чат 3 (Контролёр) разбил этот план на микро-задания
- Каждое задание — это практически готовый код, который нужно лишь правильно оформить
