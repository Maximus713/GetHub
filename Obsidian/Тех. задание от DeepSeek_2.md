# Техническое задание на создание плагина WordPress: «Калькулятор рассады LedGreen»

## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1 Назначение и цель
**Калькулятор рассады LedGreen** - это интерактивный инструмент для садоводов и огородников, выращивающих рассаду под световыми системами **LedGreen Box**.

**Основная цель**: 
- Помочь пользователю определить, какая система освещения подходит для его количества рассады (малая или большая)
- Наглядно показать, когда количество рассады превышает допустимую площадь
- Объяснить логику временного перегруза (агротехническую норму избыточной посадки с последующей выбраковкой)

**Ключевой принцип**: Калькулятор не продает напрямую, а обучает и подсказывает правильное агротехническое решение.

## 2. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 2.1 Платформа и интеграция
- **Платформа**: WordPress 5.0+
- **Интеграция**: 
  - Через шорткод `[ledgreen_calculator]`
  - Поддержка Elementor (виджет)
  - Плагин должен работать автономно, без подключения к `functions.php` темы

### 2.2 Архитектура
- **Логика**: Вся бизнес-логика внутри плагина
- **Данные**: Без использования базы данных, без сохранения состояний
- **Расчеты**: Клиентские на JavaScript
- **Шаблоны**: PHP для генерации HTML
- **Без AJAX**: Все расчеты выполняются на стороне клиента

### 2.3 Структура файлов плагина
```

├── ledgreen-plant-calculator.php     # Главный файл плагина
├── assets/
│   ├── css/

│   └── js/
```

- Процент отображения = `(площадь / 1.8) × 100`

- Фон текста состояния: темно-зеленый (`#b8d8be`)

**Логика расчета процента**:
- 100% шкалы = 2.8 м²
- Процент отображения = `(площадь / 2.8) × 100`
- **Критически важно**: цвет шкалы меняется МГНОВЕННО при пересечении границы 1.8 м²

#### 🟡 **СОСТОЯНИЕ 3 - Временный перегруз (агротехническая норма)**
**Условие**: `2.8 < площадь ≤ 3.08 м²`

**Визуальные индикаторы**:
- Цвет заполнения шкалы: желтый (`#fbc02d`)
- Фон текста состояния: светло-желтый (`#fff3cd`)
- Граница слева: желтый (`#ffc107`)

**Текст состояния**:

```
На поздних этапах роста рассады её количество нужно сократить.
```

**Пояснение**:
Это НЕ ошибка, а объяснение агротехнической логики:
- Для садоводов нормально сажать рассаду с запасом
- Расчет ведется по растениям, дошедшим до финальной стадии
- Избыточное количество допустимо временно
- По мере роста слабые растения нужно убрать

**Логика расчета процента**:
- 100% шкалы = 2.8 м² (показываем относительно большой системы)
- Процент отображения = `(площадь / 2.8) × 100`

#### 🟠 **СОСТОЯНИЕ 4 - Критическое превышение**
**Условие**: `площадь > 3.08 м²`

**Визуальные индикаторы**:

- Фон текста состояния: светло-оранжевый (`#ffe5d0`)
- Граница слева: оранжевый (`#fd7e14`)

**Текст состояния**:


**Логика расчета процента**:
- Шкала визуально показывает 100% (ограничена)
- Реальный процент в блоке метрик: `(площадь / 2.8) × 100` (может быть >100%)
- Шкала останавливается на 100% от 3.08 м²

### 4.2 Динамическое изменение текста метрики

## 6. ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ

### 6.1 JavaScript логика (основные функции)

#### Алгоритм расчета:
```javascript
1. Собрать значения из всех 6 полей ввода
2. Рассчитать общую площадь: сумма(count × area_m2)
3. Определить текущее состояние:
   - if area = 0 → состояние 0
   - if 0 < area ≤ 1.8 → состояние 1
   - if 1.8 < area ≤ 2.8 → состояние 2
   - if 2.8 < area ≤ 3.08 → состояние 3
   - if area > 3.08 → состояние 4
4. Рассчитать процент для отображения:
   - Состояние 1: (area / 1.8) × 100
   - Состояния 2-4: (area / 2.8) × 100
5. Рассчитать позицию на шкале (относительно 3.08 м²):
   - if area ≤ 3.08: (area / 3.08) × 100
   - else: 100
6. Обновить визуальные элементы:
   - Ширину и цвет шкалы (мгновенно)
   - Текст состояния и его фон (мгновенно)
   - Текст метрики заполнения
   - Числовые значения площади и процента
   - Видимость вертикальных рисок
```

#### Критические требования к JavaScript:
- **Мгновенная смена цветов** при пересечении границ состояний
- **Динамическое обновление** всех элементов без перезагрузки
- **Автоматический расчет** без кнопки "Рассчитать"
- **Плавная анимация** ширины шкалы
- **Обработка всех событий ввода** (включая клавиатуру)

## 9. ОГРАНИЧЕНИЯ И ГРАНИЧНЫЕ СЛУЧАИ

- **Очень большие числа** → показывать реальный процент (может быть >1000%)

- Все расчеты на клиенте, без запросов к серверу
- Оптимизированные обновления DOM
- Минимальное количество перерисовок
