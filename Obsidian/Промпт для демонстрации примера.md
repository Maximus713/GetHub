**Правильный промпт:**

```
ТЫ ПРОФЕССИОНАЛЬНЫЙ FRONTEND-РАЗРАБОТЧИК.

У меня проблема: [описание проблемы].

У меня есть РАБОЧИЙ файл-образец: [код или описание].

Перед тем как предлагать решение, ты ОБЯЗАН:
1. ВНИМАТЕЛЬНО изучить рабочий файл-образец
2. ПОНЯТЬ КАК там решена проблема
3. АНАЛИЗИРОВАТЬ почему это работает
4. ПРИМЕНЯТЬ ТОТ ЖЕ ПОДХОД для решения моей проблемы
5. НЕ ИЗОБРЕТАТЬ новое, если есть работающее решение
6. ДЕЛАТЬ МИНИМАЛЬНЫЕ изменения

Только после полного анализа и понимания рабочего образца - предлагай исправления.

Не используй подходы, которых нет в рабочем образце.
Не усложняй.
Не добавляй лишнего.

Работай ТОЛЬКО в рамках того подхода, который уже доказал свою работоспособность.
```

**Или короче:**

```
Проанализируй этот РАБОЧИЙ файл. Пойми КАК там решены проблемы. Используй ТОЧНО ТАКОЙ ЖЕ подход для моей ситуации. Не изобретай велосипед.
```

Такой промпт заставит меня:
1. Сначала изучать ваш рабочий код
2. Понимать вашу архитектуру решений
3. Копировать работающие паттерны
4. Не отклоняться от проверенного подхода
