## 1. НАЗНАЧЕНИЕ И ГРАНИЦЫ ОТВЕТСТВЕННОСТИ

### 1.1. Назначение калькулятора
Калькулятор предназначен **исключительно** для расчёта:
- безопасной концентрации рабочего раствора,
- массы удобрения в граммах,
- визуальной оценки риска выбранной концентрации

**с учётом влажности грунта перед подкормкой**.

### 1.2. Что калькулятор НЕ делает (критично)
Калькулятор концентрации:
- ❌ не подбирает удобрения,
- ❌ не анализирует состав NPK,
- ❌ не рассчитывает элементы N, P, K,
- ❌ не оценивает культуру или фазу роста.

Он работает **с абстрактным удобрением**, где важна только концентрация раствора.

## 3. ИНТЕРПРЕТАЦИЯ ДАННЫХ ПРОФИЛЯ

### 3.1. Структура профиля грунта
Каждый профиль содержит:
- `ranges` - диапазоны концентраций
- `states` - состояния/уровни безопасности
- `warning` - предупреждение (опционально)

### 3.2. Роли полей `ranges` (ЖЁСТКО ФИКСИРОВАНО)

#### **Ключевое правило:** Единый диапазон для всех типов грунта
Все три типа грунта (dry, medium, wet) используют **одинаковые** значения:

| Поле | Значение | Назначение | Используется для |
|------|----------|------------|------------------|
| `absolute_min` | **0.05** (для всех) | Глобальный физически допустимый минимум | **min ползунка и поля ввода (единый для всех)** |
| `absolute_max` | **1.5** (для всех) | Глобальный физически допустимый максимум | **max ползунка и поля ввода (единый для всех)** |
| `default` | **0.3** (для всех) | Единое стартовое значение | Инициализация при загрузке калькулятора |

#### **Важные правила:**
1. ❌ `absolute_min` и `absolute_max` **не могут отличаться** между профилями
2. ❌ `default` **не может отличаться** между профилями  
3. ✅ Различия между грунтами определяются **ТОЛЬКО через `states`**

### 3.3. Различия между грунтами определяются `states`

#### **3.3.1. Принцип работы:**
- **Одинаковый слайдер** для всех грунтов (0.05% - 1.5%)
- **Разная безопасность** одной и той же концентрации для разных грунтов
- **Бегунок не двигается** при смене грунта

#### **3.3.2. Пример:**
Концентрация **0.6%** для разных грунтов:

| Грунт | Состояние | Цвет | Объяснение |
|-------|-----------|------|------------|
| **Сухой** | 🔴 ОПАСНО | Красный | Для сухого грунта 0.6% - риск ожога |
| **Слабо влажный** | 🟡 ПОВЫШЕННАЯ | Желтый | На грани безопасного диапазона |
| **Влажный** | 🟢 РАБОЧАЯ НОРМА | Зеленый | Идеальная концентрация |

### 3.4. Роли `states` (КЛЮЧЕВАЯ ЛОГИКА)
Каждый `state` определяет уровень безопасности в пределах глобального диапазона.

#### **3.4.1. Структура состояния:**
```php
[
    'id' => 'optimal',                    // Уникальный ID
    'name' => 'Рабочая норма',            // Название для пользователя
    'emoji' => '✅',                      // Визуальный индикатор
    'color' => '#28a745',                 // Цвет в HEX
    'range' => [0.4, 0.8],                // Диапазон в процентах (0.4% - 0.8%)
    'description' => 'Стандарт для влажной почвы' // Пояснение
]
```

#### **3.4.2. Логика попадания в состояние:**
Для определения, к какому `state` относится текущая концентрация:
- **Для всех состояний, кроме последнего:** `start <= value < end`
- **Для последнего состояния:** `start <= value <= end`

#### **3.4.3. Обработка граничных и исключительных случаев**

**Правила для значений вне стандартных диапазонов:**

1. **Значения ниже первого состояния:**
   - Если `концентрация < states[0].range[0]`
   - → Считать, что значение попадает в первое состояние
   - → Использовать `state[0]` для всех расчетов

2. **Значения выше последнего состояния:**
   - Если `концентрация > states[последний].range[1]`
   - → Считать, что значение попадает в последнее состояние
   - → Использовать последний `state` для всех расчетов

3. **Точное соответствие границам:**
   - Если `концентрация == state.range[1]` (кроме последнего состояния)
   - → Считать, что значение попадает в СЛЕДУЮЩЕЕ состояние
   - Пример: для сухого грунта 0.15% → состояние `low` (а не `very_low`)

**Важно:** База данных должна обеспечивать непрерывное покрытие всего диапазона 0.05-1.5% без пропусков.

**3.4.4. Плавные цветовые переходы между состояниями**

> Для обеспечения плавных визуальных переходов при изменении концентрации:
> 
> 1. **Цвет поля ввода концентрации** интерполируется от белого (#ffffff) к цвету текущего состояния
>     
> 2. **При переходе между состояниями** цвет меняется плавно, без резких скачков
>     
> 3. **Последовательность цветов** соответствует последовательности состояний в базе данных:
>     
>     - Серый → Светло-зелёный → Тёмно-зелёный → Жёлтый → Красный
>         
>     - (для сухого грунта: #6c757d → #90EE90 → #28a745 → #FFD700 → #dc3545)
>         
> 
> **Алгоритм плавного перехода:**
> 
> - При подходе к границе состояния (в пределах 0.01%) начинается плавный переход к цвету следующего состояния
>     
> - Внутри состояния цвет интерполируется от белого к цвету этого состояния
>     
> - На границах состояний выполняется интерполяция между цветами соседних состояний
>

### 3.5. Определение состояния и цвета шкалы

#### **3.5.1. Алгоритм определения состояния:**
1. Для текущего типа грунта берется массив `states` из базы данных
2. Проверяется, в какой диапазон попадает текущая концентрация
3. Применяется правило из раздела 3.4.2
4. Определяется `state` (со всеми полями: name, emoji, color, description)

#### **3.5.2. Окрашивание шкалы:**
- **Шкала окрашивается СПЛОШНЫМ ОДНОРОДНЫМ ЦВЕТОМ**
- **Цвет шкалы = цвет текущего состояния** (`state['color']`)
- При изменении концентрации или смене грунта **вся шкала перекрашивается** в новый цвет
- **Нет градиентов или разноцветных сегментов** на шкале

### 3.6. Логика смены грунта (КРИТИЧЕСКОЕ ПРАВИЛО)

#### **Что меняется при смене грунта:**
| Элемент | Меняется? | Причина |
|---------|-----------|---------|
| Значение концентрации | ❌ НЕТ | Пользователь сам выбирает концентрацию |
| Положение бегунка | ❌ НЕТ | Слайдер общий для всех грунтов |
| Цвет шкалы | ✅ ДА | Окрашивается в цвет нового состояния |
| Состояние | ✅ ДА | "Опасность"/"Безопасно" |
| Цвет поля ввода | ✅ ДА | Интерполяция от белого к цвету состояния |
| Предупреждение | ✅ ДА | Особые риски для сухого грунта |

#### **3.6.1. Пример поведения:**
1. Пользователь выбирает 0.6%
2. Слайдер устанавливается на 0.6%
3. Пользователь переключает грунты:
   - **Сухой:** 🔴 Вся шкала КРАСНАЯ, состояние "ОПАСНО!"
   - **Влажный:** 🟢 Вся шкала ЗЕЛЁНАЯ, состояние "Рабочая норма"
   - **Слабо влажный:** 🟡 Вся шкала ЖЁЛТАЯ, состояние "Повышенная"
4. Положение слайдера остается на 0.6%

### 3.7. Важные уточнения

#### **3.7.1. Единицы измерения:**
- Все значения в `range` - **проценты** (0.05 = 0.05%)
- `absolute_min` и `absolute_max` - также в процентах
- Формула массы использует проценты: `(концентрация / 100) × объем × 1000`

#### **3.7.2. Запрещенные поля:**
```php
// НЕ ИСПОЛЬЗУЮТСЯ в логике калькулятора:
'optimal_min'   // Только справочная информация
'optimal_max'   // Только справочная информация
'min'           // Рабочий минимум (информационно)
'max'           // Рабочий максимум (информационно)
```

#### **3.7.3. Ключевой принцип:**
> **Один слайдер, три интерпретации.**  
> Одна и та же концентрация может быть опасной для сухого грунта и безопасной для влажного.  
> Калькулятор показывает это через цветовую индикацию, не двигая бегунок.

### 4.2. Блок «Параметры раствора»

#### **4.2.1. Поле «Объём воды»**
- **Тип:** `number` со стрелками
- **Минимум:** **0.5 л**
- **Максимум:** **`water_volume_max` из базы (1000 л)**
- **Логика шага:**
  - При значении **МЕНЬШЕ 10 л** → шаг **0.5 л**
  - При значении **10 л и более** → шаг **1 л**
  
**Важно:** Переход с шага 0.5 на шаг 1 происходит на значении **10.0 л**

**Пример корректной последовательности:**
0.5, 1.0, 1.5, 2.0, ..., 9.0, 9.5, 10.0, 11.0, 12.0, 13.0

**Некорректная последовательность (запрещена):**
..., 9.5, 10.0, 10.5, 11.5, 12.5

**Динамический шаг:**
```javascript
// Реализация динамического шага:
waterInput.addEventListener('input', function(e) {
    let value = parseFloat(this.value);
    
    // Валидация шага
    if (value < 10) {
        // Для значений <10 л: шаг должен быть кратен 0.5
        if ((value * 10) % 5 !== 0) {
            // Округлить до ближайшего кратного 0.5
            value = Math.round(value * 2) / 2;
            this.value = value.toFixed(1);
        }
    } else {
        // Для значений ≥10 л: шаг должен быть кратен 1
        if (value % 1 !== 0) {
            value = Math.round(value);
            this.value = value;
        }
    }
});

// HTML5 атрибуты:
// <input type="number" step="0.5" ...>
// Использовать step="0.5" для поддержки стрелочек

**Поведение стрелочек:**

- При значении 9.5: ↑→ 10.0 (не 10.5)
    
- При значении 10.0: ↑→ 11.0 (не 10.5)
  
  
#### **4.2.2. Поле «Концентрация раствора»**
- **Тип:** `number`
- **Диапазон:**
  - min = `absolute_min` (0.05 для всех грунтов)
  - max = `absolute_max` (1.5 для всех грунтов)
- **Шаг:** 0.01
- **Связано со слайдером** (двусторонняя связь)


**Цвет фона поля концентрации:**

text

ratio = (концентрация - state.range[0]) / (state.range[1] - state.range[0])
base_color = get_state_color(концентрация, state_index)
color = interpolate(#ffffff, base_color, ratio)

**Где:**

- `get_state_color()` возвращает цвет состояния, соответствующего концентрации
    
- `state_index` - индекс текущего состояния в массиве `states`
    
- Интерполяция выполняется от белого (#ffffff) к цвету текущего состояния
    
- При переходе между состояниями изменение цвета происходит плавно
  
  

##### **Технические детали интерполяции цвета:**

**Защита от нулевого диапазона:**
```javascript
// Проверка перед расчетом ratio:
if (state.range[1] - state.range[0] === 0) {
    ratio = 0.5; // Центр диапазона
} else {
    ratio = (value - state.range[0]) / (state.range[1] - state.range[0]);
}
```

**Метод интерполяции цветов:**
- Использовать **линейную интерполяцию RGB-компонентов**
- Формат цветов: HEX (#ffffff, #28a745)
- Без поддержки альфа-канала
- Пример функции:
```javascript
function interpolateColor(color1, color2, factor) {
    const r1 = parseInt(color1.substr(1, 2), 16);
    const g1 = parseInt(color1.substr(3, 2), 16);
    const b1 = parseInt(color1.substr(5, 2), 16);
    const r2 = parseInt(color2.substr(1, 2), 16);
    const g2 = parseInt(color2.substr(3, 2), 16);
    const b2 = parseInt(color2.substr(5, 2), 16);
    
    const r = Math.round(r1 + factor * (r2 - r1));
    const g = Math.round(g1 + factor * (g2 - g1));
    const b = Math.round(b1 + factor * (b2 - b1));
    
    return `#${((1 << 24) + (r << 16) + (g << 8) + b).toString(16).slice(1)}`;
}
```
```



### 4.3. Шкала концентрации (ЕДИНСТВЕННАЯ)

#### **4.3.1. Общие требования**
- Одна шкала с ползунком поверх
- Ползунок (бегунок) имеет стандартный вид (серый/черный кружок)
- **Шкала всегда однородного цвета** (без градиентов и сегментов)
- **Никаких текстовых меток** на шкале («низкая», «средняя» и т.п.)

#### **4.3.2. Мгновенное окрашивание шкалы**
- При выборе типа грунта шкала **немедленно перекрашивается** в цвет соответствующего состояния
- При изменении концентрации шкала **меняет цвет** на цвет нового состояния
- Пользователь видит **единый цвет**, соответствующий уровню риска
  
  
  #### **4.3.3. Реализация окрашивания шкалы**

**Использование цветов из базы данных:**
1. **CSS Custom Properties** для динамического изменения:
```css
.npk-calculator {
    --slider-color: #28a745; /* Базовый цвет */
}

.npk-slider-track {
    background-color: var(--slider-color);
    transition: background-color 0.3s ease;
}


#### **4.3.3. Визуализация шкалы**
Шкала выполняет роль **"индикатора риска"**, где:
- **Цвет шкалы** = текущий уровень безопасности
- **Ползунок** = указатель выбранной концентрации
- **При смене грунта** шкала перекрашивается, показывая новую оценку риска

**При смене грунта:**
1. Меняется цвет всей шкалы
2. Ползунок остается на прежней позиции
3. Пользователь видит, в каком состоянии новая "карта риска" он находится



### 4.4. Валидация и ограничения полей ввода

#### 4.4.1. Поле "Объём воды"
- **HTML5 атрибуты:** `min="0.5" max="1000" step="0.5"`
- **JavaScript валидация:** 
  - Меньше 10 л: шаг 0.5
  - 10 л и больше: шаг 1
  - При вводе 9.5 → 10.0 → 11.0 (не 10.5)
- **Минимальное значение:** 0.5 л (приоритет ТЗ над `water_volume_min` в базе)

- **Минимум:** **0.5 л** (приоритет ТЗ над `water_volume_min` в базе данных)
- **Причина:** Для практического использования меньше 0.5 л не имеет смысла
- **База данных:** Значение `water_volume_min` = 0.1 игнорируется в пользу ТЗ

#### 4.4.2. Поле "Концентрация раствора"
- **HTML5 атрибуты:** `min="0.05" max="1.5" step="0.01"`
- **JavaScript валидация:**
  - Округление до 2 знаков после запятой
  - При вводе < 0.05 → устанавливать 0.05
  - При вводе > 1.5 → устанавливать 1.5
  - При вводе значения между состояниями → оставлять как есть (обработка в 3.4.3)

#### 4.4.3. Обратная связь при валидации
- Некорректные значения подсвечиваются красной рамкой
- Показывается подсказка с допустимым диапазоном
- Значения автоматически корректируются при потере фокуса

### Б.5. Функция интерполяции цветов (JavaScript)

javascript

/**
 * Интерполяция HEX-цветов
 * @param {string} color1 - Начальный цвет (#ffffff)
 * @param {string} color2 - Конечный цвет (#28a745)
 * @param {number} factor - Коэффициент 0-1
 * @returns {string} HEX-цвет
 */
function interpolateColor(color1, color2, factor) {
    // Удаляем символ #
    const c1 = color1.substring(1);
    const c2 = color2.substring(1);
    
    // Парсим RGB компоненты
    const r1 = parseInt(c1.substr(0, 2), 16);
    const g1 = parseInt(c1.substr(2, 2), 16);
    const b1 = parseInt(c1.substr(4, 2), 16);
    
    const r2 = parseInt(c2.substr(0, 2), 16);
    const g2 = parseInt(c2.substr(2, 2), 16);
    const b2 = parseInt(c2.substr(4, 2), 16);
    
    // Линейная интерполяция
    const r = Math.round(r1 + factor * (r2 - r1));
    const g = Math.round(g1 + factor * (g2 - g1));
    const b = Math.round(b1 + factor * (b2 - b1));
    
    // Обратно в HEX
    const hex = ((1 << 24) + (r << 16) + (g << 8) + b).toString(16).slice(1);
    return `#${hex}`;
}

/**
 * Получение цвета для интерполяции с учетом плавных переходов между состояниями
 * @param {number} concentration - Текущая концентрация
 * @param {Array} states - Массив состояний текущего профиля грунта
 * @returns {string} Цвет для интерполяции
 */
function getInterpolationColor(concentration, states) {
    // Находим текущее состояние
    const currentState = getCurrentState(concentration, states);
    const currentIndex = states.findIndex(s => s.id === currentState.id);
    
    // Если это не последнее состояние и мы близко к границе
    if (currentIndex < states.length - 1) {
        const nextState = states[currentIndex + 1];
        const [currentStart, currentEnd] = currentState.range;
        const [nextStart, nextEnd] = nextState.range;
        
        // Проверяем близость к границе (в пределах 0.01%)
        if (Math.abs(currentEnd - concentration) < 0.01) {
            // Плавный переход между цветами состояний
            const borderRatio = (concentration - currentStart) / (currentEnd - currentStart);
            return interpolateColor(currentState.color, nextState.color, borderRatio);
        }
    }
    
    // Внутри состояния - используем цвет текущего состояния
    return currentState.color;
}

---

## 🔹 ОБЯЗАТЕЛЬНЫЙ РАЗДЕЛ ТЗ

### Выбор удобрения и модель расчёта концентрации

### 1. Принципиальное требование

Калькулятор концентрации **обязан учитывать выбранное удобрение**.  
Расчёт концентрации **НЕ МОЖЕТ выполняться без указания конкретного удобрения**.

> Калькулятор, не учитывающий состав удобрения, считается **некорректным и нерабочим**.

---

### 2. Сущность «Удобрение»

Каждое удобрение описывается как отдельная сущность со следующими обязательными параметрами:

- `id` — уникальный идентификатор
    
- `name` — название удобрения
    
- `npk` — содержание макроэлементов (N–P–K) в процентах
    
- `density_factor` или иной коэффициент, определяющий вклад удобрения в концентрацию раствора
    
- `description` (опционально)
    

Удобрения хранятся в конфигурации и доступны для выбора пользователем.

---

### 3. Пользовательский ввод (обязательные параметры)

Для любого расчёта пользователь **обязан задать**:

1. выбранное удобрение
    
2. объём воды
    
3. массу удобрения **или** целевую концентрацию (в зависимости от режима калькулятора)
    

Без выбора удобрения расчёт **не выполняется**.

---

### 4. Модель расчёта (фиксируется жёстко)

Концентрация раствора определяется **на основе свойств выбранного удобрения**, а не абстрактной массы вещества.

Общая логика:

- масса удобрения × коэффициенты выбранного удобрения → вклад в раствор
    
- объём воды → нормализация


### Связь калькулятора с базой данных удобрений

Калькулятор **не содержит встроенных данных об удобрениях**. Список удобрений, их наименование, состав (N:P:K), плотность/коэффициенты пересчёта и все параметры, влияющие на расчёт концентрации и массы удобрения, **берутся исключительно из файла базы данных** (например, `config/npk-database.php`). Калькулятор обязан использовать **единый источник данных** и пересчитывать концентрацию и итоговую массу **в зависимости от выбранного пользователем удобрения**. Любые изменения состава или параметров удобрений выполняются **только в базе данных**, без правок логики калькулятора.
