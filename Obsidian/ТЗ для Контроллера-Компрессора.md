# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: КОНТРОЛЛЕР-КОМПРЕССОР

## **1. ЦЕЛЬ И НАЗНАЧЕНИЕ**

**Контроллер-компрессор** — это **первый и самый важный** этап системы. Его задача:
1. **Принять весь код проекта** (любого размера)
2. **Проанализировать и сжать** до релевантных частей
3. **Подготовить рабочие пакеты** для следующих этапов
4. **Уменьшить объём передаваемых данных** в 2-10 раз

## **2. ВХОДНЫЕ ДАННЫЕ**

```
ВХОД:
- Весь код проекта (все файлы)
- Команда: "АНАЛИЗИРУЙ И ПОДГОТОВЬ ДЛЯ АУДИТА [ТИП]"
  где [ТИП] = "безопасность" / "стабильность" / "WordPress" / "React"

ПРИМЕР:
[код из 50 файлов]
АНАЛИЗИРУЙ И ПОДГОТОВЬ ДЛЯ АУДИТА БЕЗОПАСНОСТИ
```

## **3. АЛГОРИТМ РАБОТЫ (4 ШАГА)**

### **ШАГ 1: БЫСТРЫЙ АНАЛИЗ СТРУКТУРЫ (2 минуты)**

```
АНАЛИЗИРУЕТ:
1. **Тип проекта:**
   - WordPress (есть plugin.php, ABSPATH)
   - React (есть package.json, компоненты)
   - API (есть роуты, контроллеры)
   - Утилита (скрипты, CLI)

2. **Размер и сложность:**
   - Всего файлов: X
   - Всего строк: Y
   - Языки: PHP (A%), JS (B%), CSS (C%)

3. **Критические точки:**
   - Точки входа (index.php, app.js, main.py)
   - Конфигурации (config/, .env)
   - Основные модули (core/, lib/, src/)
```

### **ШАГ 2: ВЫДЕЛЕНИЕ КРИТИЧЕСКИХ ЧАСТЕЙ (3 минуты)**

#### **ДЛЯ WordPress (аудит безопасности):**
```
ВЫБИРАЕТ:
1. **Точки входа (100%):**
   - plugin.php, index.php, main-file.php

2. **Файлы с SQL (выборочно):**
   - database.php, db-class.php (первые 50 строк каждой функции)
   - Файлы с "query", "select", "insert", "update" в названии

3. **Файлы с выводом (выборочно):**
   - template.php, render.php (функции echo, print)
   - Файлы в папках views/, templates/

4. **Конфиги (100%):**
   - config.php, settings.php

ИГНОРИРУЕТ:
- CSS, изображения, документацию
- Тесты, node_modules, vendor
- Вспомогательные скрипты
```

#### **ДЛЯ React (аудит стабильности):**
```
ВЫБИРАЕТ:
1. **Компоненты (первые 100 строк каждого):**
   - App.js, MainComponent.js
   - Файлы с "useState", "useEffect"

2. **Обработчики ошибок:**
   - Файлы с try/catch, error boundaries

3. **Маршруты (роуты):**
   - AppRouter.js, routes.js
```

## **5. КРИТЕРИИ КАЧЕСТВА КОМПРЕССОРА**

### **МЕТРИКИ ЭФФЕКТИВНОСТИ:**

#### **Метрика 1: Степень сжатия**
```
ЦЕЛЬ: 20-30% от исходного объёма
ФОРМУЛА: (размер пакета) / (исходный размер) × 100%
ПРИМЕР: 1500 строк → 300-450 строк
```

#### **Метрика 2: Полнота критических частей**
```
ЦЕЛЬ: 100% критического кода в пакете
ПРОВЕРКА: Если есть SQL/XSS/ABSPATH ошибка в исходнике,
          она ДОЛЖНА быть в пакете
```

#### **Метрика 3: Скорость работы**
```
ЦЕЛЬ: < 10 минут на проект до 5000 строк
ШАГИ:
- Анализ: 2-3 минуты
- Выделение: 3-4 минуты
- Компрессия: 2-3 минуты
```

#### **Метрика 4: Точность классификации**
```
ЦЕЛЬ: 95% правильного определения типа проекта
ТЕСТ: 10 проектов → 9 правильно классифицированы
```

## **6. ПРАВИЛА КОМПРЕССИИ**

### **ЧТО ВКЛЮЧАТЬ ВСЕГДА (100%):**
1. **Точки входа:** index.php, app.js, main.py
2. **Конфигурации:** config.php, .env, package.json
3. **Основные классы/компоненты:** App.js, Core.php
4. **Файлы с проблемами:** где явно видна ошибка

### **ЧТО ВКЛЮЧАТЬ ЧАСТИЧНО (30-50%):**
1. **Вспомогательные файлы:** первые 50 строк каждой функции
2. **Шаблоны:** ключевые функции рендеринга
3. **Модели:** методы работы с данными

### **ЧТО ИСКЛЮЧАТЬ (0%):**
1. **Ресурсы:** CSS, изображения, шрифты
2. **Документация:** README, CHANGELOG, docs/
3. **Тесты:** /tests/, /spec/, test*.js
4. **Зависимости:** /vendor/, /node_modules/, /dist/
5. **Сгенерированный код:** минифицированные файлы

## **7. АДАПТАЦИЯ ПОД ТИП АУДИТА**

### **ДЛЯ АУДИТА БЕЗОПАСНОСТИ:**
```
АКЦЕНТ НА:
- Ввод/вывод данных (echo, print, return)
- SQL запросы (query, execute, prepare)
- Валидация (sanitize, validate, escape)
- Проверки прав (current_user_can, is_admin)

ИСКЛЮЧАЕМ:
- Алгоритмы, математику
- UI/UX логику
- Оптимизацию
```

### **ДЛЯ АУДИТА СТАБИЛЬНОСТИ:**
```
АКЦЕНТ НА:
- Обработка ошибок (try/catch, error handling)
- Граничные условия (if, else, null checks)
- Зависимости (import, require, include)
- Циклы и рекурсия

ИСКЛЮЧАЕМ:
- Стили, оформление
- Конфигурации (если не влияют на стабильность)
```

```
Контроллер → Валидатор:
- Передаёт: РАБОЧИЙ ПАКЕТ (450 строк)

- Валидатор анализирует ТОЛЬКО пакет
```

### **СВЯЗЬ С ИСПРАВИТЕЛЕМ:**
```
Валидатор → Исправитель:
- Передаёт: подтверждённые проблемы + ПОЛНЫЕ файлы этих проблем
- Пример: "database.php:42 — SQLi" → весь database.php (100 строк)
```

### **СВЯЗЬ С ВЕРИФИКАТОРОМ:**
```
Исправитель → Верификатор:
- Передаёт: DIFF изменений (50 строк) + изменённые файлы
- Не передаёт: весь проект
```

## **10. ОГРАНИЧЕНИЯ И РИСКИ**

### **РИСК 1: Пропуск критического кода**
```
СЦЕНАРИЙ: Контроллер исключил файл как "неважный",
          но там была критическая уязвимость.

МИНИМИЗАЦИЯ:
1. Всегда включать файлы с:
   - "config", "setting", "database" в названии
   - Точки входа
   - Основные модули
2. Консервативный подход: лучше включить лишнее
```

### **РИСК 2: Потеря контекста**
```
СЦЕНАРИЙ: Валидатор получает фрагмент функции
          без видимости, как она вызывается.

МИНИМИЗАЦИЯ:
1. Всегда включать заголовки вызывающих функций
2. Добавлять комментарии-контекст:
   "Эта функция вызывается из admin-page.php:30"
```

### **РИСК 3: Слишком большое сжатие**
```
СЦЕНАРИЙ: Пакет 5% от исходного, утеряна важная информация.

МИНИМИЗАЦИЯ:
1. Минимальный порог: 20% от исходного
2. Если проект < 500 строк → не сжимать
```

## **11. ПРАКТИЧЕСКАЯ РЕАЛИЗАЦИЯ**

### **ПРОМПТ КОНТРОЛЛЕРА-КОМПРЕССОРА ДОЛЖЕН:**

1. **Быстро анализировать** структуру проекта
2. **Интеллектуально выбирать** что важно
3. **Формировать компактный, но полный пакет**
4. **Давать чёткие инструкции** следующему этапу

### **КОМАНДА ДЛЯ РАЗРАБОТЧИКА ПРОМПТА:**

```
Создай промпт "Контроллер-компрессор", который:

1. Принимает весь код проекта + команду "АНАЛИЗИРУЙ И ПОДГОТОВЬ"
2. За 8-10 минут создаёт рабочий пакет в 20-30% от исходного объёма
3. Включает в пакет ВСЁ критическое, исключает всё неважное
4. Формирует отчёт в формате выше

Фокус на:
- WordPress плагины (безопасность)
- Выявление SQLi, XSS, отсутствия ABSPATH
- Сжатие данных без потери критической информации
```
