# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Плагин WordPress: «Калькулятор рассады LedGreen»

---

## 1. НАЗНАЧЕНИЕ И ЦЕЛЬ

### 1.1 Основная задача
Калькулятор предназначен для **садоводов и огородников**, выращивающих рассаду под световыми системами **LedGreen Box**. 

**Цель**: помочь пользователю понять:
- Какая система освещения подходит (малая или большая)
- Когда количество рассады превышает допустимую площадь
- Объяснить логику временного перегруза (избыточная посадка с последующей выбраковкой)

### 1.2 Ключевой принцип
Калькулятор **не продает напрямую**, а **обучает и подсказывает правильное агротехническое решение**.

---

## 2. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 2.1 Платформа
- WordPress плагин
- Работает через **шорткод** `[ledgreen_calculator]`
- Поддержка **Elementor** (виджет)
- **Не требует** подключения к `functions.php` темы

### 2.2 Архитектура
- Вся логика внутри плагина
- Без AJAX, без базы данных, без сохранения состояний
- Клиентские расчеты на JavaScript
- PHP для шаблонов и конфигурации

## 4. ЛОГИКА РАБОТЫ (КЛЮЧЕВАЯ ЧАСТЬ)

### 4.1 Четыре состояния калькулятора

#### 🟢 СОСТОЯНИЕ 1 — Малая система
**Условие**: `общая площадь ≤ 1.8 м²`

**Визуальные индикаторы**:
- Цвет шкалы: светло-зеленый (`#81c784`)
- Фон текста состояния: светло-зеленый (`#d4edda`)
- Граница слева: зеленый (`#28a745`)

**Текст состояния**:
```
Растения помещаются в малую систему.
```

**Логика расчета**:
- 100% шкалы = 1.8 м²
- Процент отображения = `(площадь / 1.8) × 100`

---

#### 🟢🟢 СОСТОЯНИЕ 2 — Требуется большая система
**Условие**: `1.8 < площадь ≤ 2.8 м²`

**Визуальные индикаторы**:
- Цвет шкалы: темно-зеленый (`#2e7d32`)
- Фон текста состояния: зеленый темнее (`#b8d8be`)
- Граница слева: темно-зеленый (`#1e7e34`)

**Текст состояния**:
```
Количество растений превышает площадь малой системы. 
Необходима большая система.
```

**Логика расчета**:
- 100% шкалы = 2.8 м²
- Процент отображения = `(площадь / 2.8) × 100`
- **Важно**: цвет шкалы меняется МГНОВЕННО при пересечении 1.8 м²

---

#### 🟡 СОСТОЯНИЕ 3 — Временный перегруз (агротехническая норма)
**Условие**: `2.8 < площадь ≤ 3.08 м²`

**Визуальные индикаторы**:
- Цвет шкалы: желтый (`#fbc02d`)
- Фон текста состояния: светло-желтый (`#fff3cd`)
- Граница слева: желтый (`#ffc107`)

**Текст состояния**:
```
Количество растений превышает площадь большой системы.
Для комфортного состояния на поздних этапах роста рассады 
её количество нужно сократить.
```

**Важное пояснение**:
Это НЕ ошибка, а объяснение агротехнической логики:
- Для садоводов нормально сажать рассаду с запасом
- Расчет ведется по растениям, дошедшим до финальной стадии
- Избыточное количество допустимо временно
- По мере роста слабые растения нужно убрать

**Логика расчета**:
- 100% шкалы = 3.08 м²
- Процент отображения = `(площадь / 3.08) × 100`

---

#### 🟠 СОСТОЯНИЕ 4 — Критическое превышение
**Условие**: `площадь > 3.08 м²`

**Визуальные индикаторы**:
- Цвет шкалы: оранжевый (`#f57c00`)
- Фон текста состояния: светло-оранжевый (`#ffe5d0`)
- Граница слева: оранжевый (`#fd7e14`)

**Текст состояния**:
```
Превышение площади более чем на 10%. 
Рекомендуется значительно сократить количество растений.
```

**Логика расчета**:
- Шкала показывает 100% (максимум)
- Процент отображения = 100%

## 6. ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ

### 6.1 JavaScript логика (main.js)

#### Алгоритм расчета:
```javascript
1. Собрать значения из всех полей ввода
2. Рассчитать общую площадь (сумма count × area_m2)
3. Определить текущее состояние по границам:
   - if area ≤ 1.8 → состояние 1
   - if 1.8 < area ≤ 2.8 → состояние 2
   - if 2.8 < area ≤ 3.08 → состояние 3
   - if area > 3.08 → состояние 4
4. Рассчитать процент для шкалы:
   - Состояние 1: (area / 1.8) × 100
   - Состояние 2: (area / 2.8) × 100
   - Состояния 3-4: (area / 3.08) × 100
5. Обновить визуальные элементы:
   - Ширину и цвет шкалы
   - Текст состояния и его фон
   - Числовые значения
```

#### Критические требования:
- **Цвет шкалы меняется мгновенно** при пересечении границ
- **Фон текста состояния меняется мгновенно** при пересечении границ
- **Текст состояния меняется мгновенно** при пересечении границ
- **Автоматический расчет** без кнопки "Рассчитать"

### 6.2 Передача данных в JavaScript
```php
// В ledgreen-plant-calculator.php
wp_localize_script('ledgreen-plant-calculator', 'LedGreenConfig', [
    'plants' => [...],      // Массив растений
    'systems' => [          // Границы систем
        'small' => 1.8,
        'big'   => 2.8,
        'max'   => 3.08
    ]
]);
```

### 6.3 CSS требования
- **Адаптивность**: работа на мобильных устройствах
- **Плавные переходы**: для анимации шкалы
- **Четкие состояния**: явное визуальное различие между состояниями
- **Читаемость**: черный текст на светлых фонах должен быть четко виден

## **7. КРИТИЧЕСКО ВАЖНАЯ ЛОГИКА ИЗМЕНЕНИЯ СОСТОЯНИЙ**

### 7.1 Проблема текущей реализации
В существующей реализации обнаружена критическая ошибка в логике визуальных изменений:

**НЕПРАВИЛЬНО (текущее поведение):**
- Цвет шкалы и фон текста меняются только когда анимированная шкала достигает 100% заполнения
- При пересечении границы системы (например, 1.8 м²) визуальные изменения НЕ происходят мгновенно
- Пользователь видит несоответствие: числовое значение уже превысило границу, но визуальные индикаторы показывают старое состояние

**ПРАВИЛЬНО (требуемое поведение):**
- Все визуальные изменения должны происходить **МГНОВЕННО** при фактическом пересечении числовых границ
- Анимация шкалы должна быть отделена от логики смены состояний

### 7.2 Алгоритм мгновенного переключения

**Шаг 1: Определение состояния (на каждом расчете)**
```javascript
if (площадь ≤ 1.8 м²) → состояние "Малая система"
if (1.8 < площадь ≤ 2.8 м²) → состояние "Большая система"  
if (2.8 < площадь ≤ 3.08 м²) → состояние "Перегруз"
if (площадь > 3.08 м²) → состояние "Критическое"
```

**Шаг 2: МГНОВЕННОЕ визуальное обновление**
- При смене состояния НЕМЕДЛЕННО:
  - Меняется цвет шкалы
  - Меняется фон текста состояния
  - Меняется текст сообщения
  - Сбрасывается/пересчитывается процент шкалы

**Шаг 3: Анимация шкалы**
- Шкала плавно анимируется к новому значению
- Анимация НЕ блокирует визуальные изменения

### 7.3 Конкретные сценарии работы

**Сценарий А: Пересечение границы малой системы**
- Исходно: 1.5 м² (83% заполнения, светло-зеленый)
- Пользователь добавляет растения до 1.9 м²
- **МГНОВЕННО должно произойти:**
  1. Цвет шкалы → темно-зеленый
  2. Фон текста → зеленый темнее
  3. Текст → "Необходима большая система"
  4. Шкала начинает заполняться с 68% (1.9/2.8×100)

**Сценарий Б: Пересечение границы большой системы**
- Исходно: 2.5 м² (89% заполнения, темно-зеленый)
- Пользователь добавляет растения до 2.9 м²
- **МГНОВЕННО должно произойти:**
  1. Цвет шкалы → желтый
  2. Фон текста → светло-желтый
  3. Текст → "Превышение большой системы"
  4. Шкала начинает заполняться с 94% (2.9/3.08×100)

### 7.4 Технические требования к реализации

1. **Разделение логики:**
   - Функция определения состояния (чистая математика)
   - Функция визуального обновления (мгновенная)
   - Функция анимации шкалы (плавная)

2. **Отслеживание предыдущего состояния:**
```javascript
let previousState = null;
if (currentState !== previousState) {
    // МГНОВЕННОЕ обновление визуальных элементов
    updateColors(currentState);
    updateText(currentState);
    previousState = currentState;
}
```

3. **Корректный расчет процентов:**
   - Для "Малой системы": 100% = 1.8 м²
   - Для "Большой системы": 100% = 2.8 м²  
   - Для "Перегруза" и "Критического": 100% = 3.08 м²

### 7.5 Критерии проверки

**Тест 1: Быстрое переключение**
- Ввод 1.9 м² → немедленное появление темно-зеленого цвета
- НЕТ задержки до заполнения шкалы до 100%

**Тест 2: Обратное переключение**  
- Уменьшение с 2.0 м² до 1.5 м² → немедленный возврат к светло-зеленому
- НЕТ необходимости ждать опустошения шкалы

**Тест 3: Пограничные значения**
- Ровно 1.8 м² → состояние "Малая система"
- 1.8001 м² → состояние "Большая система"
- Разница в 0.0001 м² должна мгновенно менять визуальное состояние

### 7.6 Запрещенные реализации

❌ **НЕДОПУСТИМО:**
- Привязывать изменение цвета к анимации шкалы
- Использовать setTimeout/delay для визуальных изменений
- Ждать достижения шкалой 100% для смены состояния
- Делать "откат" шкалы перед сменой цвета

✅ **ОБЯЗАТЕЛЬНО:**
- Визуальные изменения по событию `input` без задержек
- Независимость цвета шкалы от ее текущей ширины
- Мгновенная реакция на пересечение числовых границ
