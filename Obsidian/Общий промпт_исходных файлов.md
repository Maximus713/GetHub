2. **Формат NPK:** Относительные пропорции (N=1.0 или 0), например `[1.0, 2.0, 1.0]`
3. **Преобразование данных:** Удобрения из процентов → относительные пропорции перед расчётом
4. **Архитектура:** Полная аналогия с модулем 1 (хуки, жизненный цикл, регистрация)

## **3. ЯДРО ЛОГИКИ: `Selection_Engine`**

### **3.1. Алгоритм Отиаи (коэффициент перекрытия)**

**Шаги:**
1. **Преобразование данных удобрений:**
   ```php
   // Проценты → относительные пропорции
   // [16, 16, 16] → [0.16, 0.16, 0.16]
   $fert_relative = array_map(fn($p) => $p / 100, $fertilizer_npk);
   ```

2. **Нормализация до суммы 1:**
   ```php
   // Используем метод из БД!
   $norm_target = NPK_Database::normalize_npk($target_npk);    // [1.0, 2.0, 1.0] → [0.25, 0.5, 0.25]
   $norm_fert = NPK_Database::normalize_npk($fert_relative);   // [0.16, 0.16, 0.16] → [0.333, 0.333, 0.333]
   ```

3. **Расчёт перекрытия:**
   ```php
   $overlap = 0;
   for ($i = 0; $i < 3; $i++) {
       $overlap += min($norm_target[$i], $norm_fert[$i]);
   }
   $match_percentage = $overlap * 100;
   ```

**Свойство:** Составы с одинаковыми пропорциями (10-15-30 и 20-30-60) дают 100% соответствие.

### **3.2. Основной метод:**
```php
/**
 * Подбор удобрений для культуры на фазе роста
 * @param string $crop_id Идентификатор культуры ('tomato')
 * @param string $phase_id Идентификатор фазы ('blooming')
 * @return array Структурированные результаты
 */
public static function find_matching_fertilizers($crop_id, $phase_id): array
```

### **3.3. Логика обработки:**
1. **Получить эталон:** `NPK_Database::get_crop_phase_requirements()`
2. **Получить все удобрения:** `NPK_Database::get_fertilizers()`
3. **Преобразовать проценты удобрений** в относительные величины
4. **Рассчитать соответствие** для каждого удобрения
5. **Фильтровать по порогу 75%** (из `get_constants()['thresholds']['min_match_percentage']`)
6. **Fallback режим:** Если проходных < 1 → вернуть 3 лучших с флагом `'fallback' => true`
7. **Сортировать:** По убыванию соответствия, при равенстве → по алфавиту
8. **Генерация подсказок:** Если `additives` ∩ `priority` ≠ ∅

1. `npk-calculators.php` → конструктор `NPK_Calculators`
2. → `load_database()` (сразу)
3. → `load_concentration_module()` (сразу)

### 6.2. В конструкторе `NPK_Concentration_Module`:
1. Регистрация скриптов: `add_action('wp_enqueue_scripts', 'register_assets', 1)`
2. Подключение классов: `load_dependencies()`
3. Инициализация: `add_action('init', 'init')`

### 6.3. В методе `init()` модуля:
1. Регистрация шорткода
2. Регистрация AJAX

### 6.4. При вызове шорткода (в момент парсинга контента):
1. `enqueue_assets()` (гарантированно, без проверок)
2. Возврат HTML

### 6.5. Критическое правило для скриптов:

**Регистрация ≠ Enqueue**

- **Регистрация** (wp_register_script) - ВСЕГДА в конструкторе модуля
- **Enqueue** (wp_enqueue_script) - ТОЛЬКО в шорткоде, БЕЗ условий

❌ **НЕДОПУСТИМО:**
- Проверять `wp_script_is()` в шорткоде
- Регистрировать скрипты внутри шорткода  
- Использовать `wp_enqueue_scripts` без приоритета 1

✅ **ОБЯЗАТЕЛЬНО:**
- Скрипты зарегистрированы ДО парсинга шорткода
- Шорткод ВСЕГДА вызывает `wp_enqueue_script()` без условий
- WordPress сам решает, выводить скрипт или нет

Так сохраняется **сквозная нумерация** (1, 2, 3, 4, 5, 6) и документ остаётся целостным.

### B.2. JavaScript (UI) — UX логика без бизнес-логики

JavaScript:
- ✅ **МОЖЕТ ДЛЯ UX:**
    - определять **предварительный `state`** по правилам п.4.3
    - сравнивать концентрацию с диапазонами для определения предварительного `state`
    - выполнять **упрощённый расчёт массы** для мгновенного отображения
    - интерполировать цвет внутри `state.range`
    - отображать предварительные данные до получения ответа сервера

- ❌ **НЕ ИМЕЕТ ПРАВА:**
    - изменять алгоритм определения `state` (правила п.4.3)
    - игнорировать финальный `state` с сервера
    - быть источником истины для финальных данных
    - принимать решения о безопасности

**Разрешённая логика для мгновенного UX:**
```js
// Для определения предварительного state (те же правила что и сервер)
function getPreviewState(concentration, profile) {
    for (let state of profile.states) {
        if (concentration >= state.range[0] && concentration < state.range[1]) {
            return state;
        }
    }
    return profile.states[profile.states.length - 1]; // последний state
}
```

## ПРАВИЛО ДВУХУРОВНЕВОГО STATE
#### C.1. Источники состояния

- **ФИНАЛЬНЫЙ `state`** ВСЕГДА определяется:

     * ВСПОМОГАТЕЛЬНЫЕ МЕТОДЫ ДЛЯ МОДУЛЯ ПОДБОРА УДОБРЕНИЙ
     * (Добавлены в версии 4.0)

    /**
     * Нормализует вектор NPK (сумма компонентов = 1)
     * Вспомогательный метод для расчёта коэффициента Отиаи
     * 
     * @param array $npk Вектор NPK [N, P, K]
     * @return array Нормализованный вектор
     */
    private static function normalize_npk($npk) {
        if (!is_array($npk) || count($npk) !== 3) {
            return [0, 0, 0];
        }
        
        $sum = array_sum($npk);
        
        // Избегаем деления на ноль
        if ($sum == 0) {
            return [0, 0, 0];
        }
        
        return [
            $npk[0] / $sum,
            $npk[1] / $sum,
            $npk[2] / $sum
        ];
    }

     */

    }
