# 📋 **ИНСТРУКЦИЯ ПО ЗАПУСКУ СИСТЕМЫ**

```markdown
# ИНСТРУКЦИЯ: ЗАПУСК СИСТЕМЫ ИЗ 6 ЧАТОВ

## ⚡ ПЕРЕД НАЧАЛОМ

У тебя есть 6 промптов для 6 разных чатов. Это НЕ линейная цепочка, а СИСТЕМА с перекрёстным контролем.

## 📦 ЧТО У ТЕБЯ ЕСТЬ

1. **Чат 1 — АРХИТЕКТОР** (создаёт поэтапный план)
2. **Чат 2 — СТРАТЕГИЧЕСКИЙ АУДИТОР** (проверяет план)
3. **Чат 3 — КООРДИНАТОР** (создаёт задания)
4. **Чат 4 — ТАКТИЧЕСКИЙ АУДИТОР** (контролирует координатора)
5. **Чат 5 — КОДЕР** (пишет код)
6. **Чат 6 — ОПЕРАЦИОННЫЙ АУДИТОР** (проверяет код)

## 🚀 ПОШАГОВЫЙ ЗАПУСК

### ФАЗА 0: ПОДГОТОВКА (1 РАЗ)
1. Скопируй все 6 промптов в отдельные чаты
2. Убедись, что каждый чат имеет ТОЛЬКО свой промпт
3. Подготовь папку `npk-calculators/module-fertilizer-selector/`

### ФАЗА 1: СОЗДАНИЕ ПЛАНА
1. Запусти Чат 1 (Архитектор) → получи план
2. Отправь план в Чат 2 (Страт.аудитор) → получи подтверждение
3. Если Чат 2 отклонил → верни в Чат 1 на доработку

### ФАЗА 2: ЦИКЛ ПО КАЖДОМУ ЭТАПУ (ПОВТОРЯТЬ N РАЗ)
1. Утверждённый план → в Чат 3 (Координатор) → получи задание для ЭТАПА 1
2. Задание → в Чат 4 (Такт.аудитор) → получи подтверждение
3. Утверждённое задание → в Чат 5 (Кодер) → получи код
4. Код → в Чат 3 (промежуточная проверка) → если ОК → в Чат 6
5. Код → в Чат 6 (Опер.аудитор) → получи вердикт
6. Если вердикт ❌ → код назад в Чат 5, иначе → ЭТАП ГОТОВ
7. Чат 4 проверяет весь процесс → разрешает переход к ЭТАПУ 2

### ФАЗА 3: ЗАВЕРШЕНИЕ
- После последнего этапа → финальный отчёт от Чат 4

## ⚠️ КРИТИЧЕСКИЕ ПРАВИЛА

- **НИКОГДА** не давай следующий этап, пока текущий не принят
- **ЛЮБОЕ** отклонение → полная остановка до исправления
- **КАЖДАЯ** ошибка фиксируется в "исторической памяти"
- **ЕСЛИ** Чат 6 отклонил код 3 раза подряд → СТОП всей системы

## 📊 ТАБЛИЦА КОНТРОЛЯ (заполняй по ходу)

| Этап | Файлы | Статус | Кто проверил | Ошибки |
|------|-------|--------|--------------|--------|
| 1 | ... | ⏳ | - | - |
| 2 | ... | ⏳ | - | - |
```

```

Если ❌ → возвращаешь Чату 3 с пояснением.

### ЗАДАЧА 2: КОНТРОЛЬ ПРОЦЕССА
Ты следишь за метриками:

```

📊 ОШИБКИ: Какие ошибки повторяются?
📊 БУТЫЛОЧНОЕ ГОРЛЫШКО: Кто тормозит процесс?
```

### ЗАДАЧА 3: РАНДОМНЫЙ АУДИТ (НЕФОРМАЛЬНОСТЬ!)
Раз в 2-3 этапа ты:

```
1. Берёшь случайное уже ПРИНЯТОЕ задание
2. САМ независимо проверяешь код по оригинальному ТЗ
3. Сравниваешь со своим выводом и вердиктом Чата 6
4. Если расхождение → СТОП и разбор полётов
```

### ЗАДАЧА 4: РЕТРОСПЕКТИВА
Каждые 5 этапов ты собираешь всех:

```
- Чат 1: что в архитектуре мешало?
- Чат 3: какие задания были сложными?
- Чат 5: какие запреты нарушали чаще?
- Чат 6: что пропускали в проверках?

ИТОГ:
1. 5 самых частых ошибок
2. Корректировка промптов
3. Обновление "исторической памяти"
```

🔴 Чат 3 выдаёт задания быстрее, чем их можно выполнить → проверки формальны

## ⚠️ КРИТИЧЕСКИЕ ЗАПРЕТЫ (ИЗ ИСТОРИИ)

Эти запреты могут быть в задании, но запомни их навсегда:

### ДЛЯ PHP:
- ❌ НЕ использовать прямые SQL-запросы (только `NPK_Database::`)
- ❌ НЕ дублировать алгоритмы (используй `normalize_npk()` из БД)

### ДЛЯ JAVASCRIPT:
- ❌ НИКОГДА не использовать `URLSearchParams()` (ошибка модуля 1!)
- ❌ ТОЛЬКО `FormData()` для AJAX
- ❌ НЕ писать статические стили (только динамические значения)
- ❌ ВСЕ UI обновления через `requestAnimationFrame()`
- ❌ Обязательно отменять предыдущие AJAX-запросы (`AbortController`)

### ДЛЯ CSS/HTML:
- ❌ НИКАКИХ глобальных селекторов (только `.npk-префикс`)
- ❌ НИКАКИХ `style=""` в HTML
- ❌ ВСЕ статические стили в `selector.css`
