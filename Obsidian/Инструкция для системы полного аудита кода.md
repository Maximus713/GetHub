# **ИНСТРУКЦИЯ ПО ИСПОЛЬЗОВАНИЮ СИСТЕМЫ ПОЛНОГО АУДИТА КОДА**

## **📋 ОБЩАЯ ИНФОРМАЦИЯ**

**Система состоит из 5 независимых промптов**, которые запускаются в **отдельных чатах**. Каждый промпт получает данные от предыдущего и передаёт результаты следующему.

**Общее время работы:** 30-45 минут на проект среднего размера (~20 файлов)

**Цель системы:** Найти и безопасно исправить критические ошибки безопасности и стабильности.

---

## **🚀 БЫСТРЫЙ СТАРТ (пошаговая инструкция)**

### **ШАГ 0: ПОДГОТОВКА**

1. **Создайте 5 отдельных чатов** с ChatGPT (лучше GPT-4)
2. **Назовите чаты** для удобства:
   - Чат 1: Контроллер
   - Чат 2: Детектор  
   - Чат 3: Валидатор
   - Чат 4: Исправитель
   - Чат 5: Аналитик

### **ШАГ 1: ЗАПУСК КОНТРОЛЛЕРА (Чат 1)**

1. **Скопируйте промпт "Контроллер-Аналитатор"** в Чат 1
2. **Отправьте код проекта** (все файлы) в этот чат
3. **Добавьте команду:** `"ПОЛНЫЙ АУДИТ БЕЗОПАСНОСТИ"`

**Пример сообщения в Чате 1:**
```
[вставляете весь код проекта]

ПОЛНЫЙ АУДИТ БЕЗОПАСНОСТИ
```

**Что получите через 8-10 минут:**
```
РАБОЧИЙ ПАКЕТ от Контроллера (от ======== до ========)
```

**✅ Критерий успеха:** Пакет содержит 20-30% исходного кода + метаданные.

### **ШАГ 2: ЗАПУСК ДЕТЕКТОРА (Чат 2)**

1. **Скопируйте промпт "Детектор-Верификатор"** в Чат 2
2. **Скопируйте ВЕСЬ вывод Контроллера** (от ======== до ========) в Чат 2
3. **Добавьте команду:** `"АНАЛИЗИРУЙ ПАКЕТ: WORDPRESS БЕЗОПАСНОСТЬ"`

**Пример сообщения в Чате 2:**
```
[вставляете ВЕСЬ вывод Контроллера из Шага 1]

АНАЛИЗИРУЙ ПАКЕТ: WORDPRESS БЕЗОПАСНОСТЬ
```

**Что получите через 12-15 минут:**
```
ПОЛНЫЙ ОТЧЁТ ДЕТЕКТОРА (от ======== до ========)
```

**✅ Критерий успеха:** Найдено 5-15 потенциальных проблем с категоризацией.

### **ШАГ 3: ЗАПУСК ВАЛИДАТОРА (Чат 3)**

1. **Скопируйте промпт "Фильтр-Валидатор"** в Чат 3
2. **Скопируйте ДВА документа:**
   - Весь вывод Контроллера (из Шага 1)
   - Весь вывод Детектора (из Шага 2)
3. **Добавьте команду:** `"ВАЛИДИРУЙ ПРОБЛЕМЫ ИЗ ОТЧЁТА ДЕТЕКТОРА"`

**Пример сообщения в Чате 3:**
```
[весь вывод Контроллера]

[весь вывод Детектора]

ВАЛИДИРУЙ ПРОБЛЕМЫ ИЗ ОТЧЁТА ДЕТЕКТОРА
```

**Что получите через 8-10 минут:**
```
ОТЧЁТ ВАЛИДАТОРА (от ======== до ========)
```

**✅ Критерий успеха:** Подтверждено 3-7 проблем для исправления (остальные отклонены как ложные).

### **ШАГ 4: ЗАПУСК ИСПРАВИТЕЛЯ (Чат 4)**

1. **Скопируйте промпт "Минималист-Исправитель"** в Чат 4
2. **Скопируйте ТРИ элемента:**
   - Исходный код проекта (как в Шаге 1)
   - Раздел "✅ ДЛЯ ИСПРАВЛЕНИЯ" из отчёта Валидатора
   - Команда: `"ИСПРАВЬ ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ"`

**Пример сообщения в Чате 4:**
```
[исходный код проекта]

[копируете ТОЛЬКО раздел "✅ ДЛЯ ИСПРАВЛЕНИЯ" из отчёта Валидатора]

ИСПРАВЬ ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ
```

**Что получите через 8-10 минут:**
```
ОТЧЁТ ИСПРАВИТЕЛЯ (от ======== до ========)
+ ИСПРАВЛЕННЫЙ КОД (изменённые файлы)
```

**✅ Критерий успеха:** 80%+ проблем исправлено, код парсится.

### **ШАГ 5: ЗАПУСК АНАЛИТИКА (Чат 5)**

1. **Скопируйте промпт "Аналитик-Документатор"** в Чат 5
2. **Скопируйте ТРИ элемента:**
   - Исходный код проекта
   - Исправленный код из отчёта Исправителя
   - Весь отчёт Исправителя
3. **Добавьте команду:** `"ПРОВЕРЬ КАЧЕСТВО ИСПРАВЛЕНИЙ"`

**Пример сообщения в Чате 5:**
```
[исходный код проекта]

[исправленный код из отчёта Исправителя]

[весь отчёт Исправителя]

ПРОВЕРЬ КАЧЕСТВО ИСПРАВЛЕНИЙ
```

**Что получите через 6-8 минут:**
```
ФИНАЛЬНЫЙ ОТЧЁТ (от ======== до ========)
```

**✅ Критерий успеха:** Полный анализ, конкретные рекомендации, чек-лист для тестирования.

## **🔄 СХЕМА ПЕРЕДАЧИ ДАННЫХ**

```
ПОЛЬЗОВАТЕЛЬ 
    ↓ (код + команда)
ЧАТ 1: КОНТРОЛЛЕР → РАБОЧИЙ ПАКЕТ
    ↓ (пакет + команда)  
ЧАТ 2: ДЕТЕКТОР → ПОЛНЫЙ ОТЧЁТ ПРОБЛЕМ
    ↓ (пакет + отчёт + команда)
ЧАТ 3: ВАЛИДАТОР → ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ
    ↓ (код + подтверждённые проблемы + команда)
ЧАТ 4: ИСПРАВИТЕЛЬ → ИСПРАВЛЕННЫЙ КОД + ОТЧЁТ
    ↓ (исходный код + исправленный код + отчёт + команда)
ЧАТ 5: АНАЛИТИК → ФИНАЛЬНЫЙ ОТЧЁТ + РЕКОМЕНДАЦИИ
```

## **⚠️ КРИТИЧЕСКИЕ ПРАВИЛА БЕЗОПАСНОСТИ**

### **ПРАВИЛО 1: НИКОГДА НЕ СМЕШИВАЙТЕ ЧАТЫ**
- Каждый промпт — в отдельном чате
- Не пытайтесь запустить два промпта в одном чате
- Если ошиблись — начните чат заново с чистого промпта

### **ПРАВИЛО 2: СОХРАНЯЙТЕ БЭКАП**
**Перед Шагом 4 (Исправитель):**
1. Сохраните исходный код в отдельном месте
2. Создайте git commit: `git commit -am "Before automated audit"`
3. Или сделайте ZIP-архив

### **ПРАВИЛО 3: ПРОВЕРЯЙТЕ РЕЗУЛЬТАТЫ МЕЖДУ ЭТАПАМИ**
После каждого этапа убедитесь:
- Этап завершился успешно (есть полный отчёт)
- Данные выглядят корректно
- Нет явных ошибок в выводе

### **ПРАВИЛО 4: НЕ ПРОПУСКАЙТЕ РУЧНОЕ ТЕСТИРОВАНИЕ**
**После получения финального отчёта:**
1. Выполните чек-лист из отчёта Аналитика
2. Протестируйте основные функции
3. Только после тестирования — в продакшен

## **🛠️ РЕШЕНИЕ ПРОБЛЕМ**

### **ПРОБЛЕМА: "Промпт не понимает, что делать"**
**Решение:**
1. Убедитесь, что скопировали ВЕСЬ промпт
2. Проверьте формат ввода (см. примеры выше)
3. Если не помогло — перезапустите чат с чистым промптом

### **ПРОБЛЕМА: "Этап занимает слишком много времени"**
**Решение:**
1. Остановите генерацию (если возможно)
2. Проверьте размер проекта (>50 файлов — слишком много)
3. Разбейте проект на модули, анализируйте по частям

### **ПРОБЛЕМА: "Неправильные исправления"**
**Решение:**
1. Используйте git для отката: `git reset --hard`
2. Проанализируйте, на каком этапе ошибка
3. Свяжитесь с разработчиком для ручного исправления

### **ПРОБЛЕМА: "Потеряли данные между этапами"**
**Решение:**
1. Сохраняйте вывод каждого этапа в текстовый файл
2. Используйте названия: `controller_output.txt`, `detector_output.txt`
3. Или просто не закрывайте чаты до завершения всей цепочки

```
Этап 1 (Контроллер): 20-30% сжатие, 3-5 красных флагов
Этап 2 (Детектор): 10-15 потенциальных проблем  
Этап 3 (Валидатор): 5-7 подтверждённых проблем
Этап 4 (Исправитель): 4-6 успешных исправлений
Этап 5 (Аналитик): Отчёт "код безопаснее", чек-лист тестирования
```

### **ДЛЯ ЧИСТОГО КОДА (нет критических проблем):**
```

Этап 2 (Детектор): 2-5 потенциальных проблем (в основном P2/P3)
Этап 3 (Валидатор): 0-1 подтверждённых проблем  
Этап 4 (Исправитель): 0-1 исправлений (или "нет проблем")

```

### **ДЛЯ ОЧЕНЬ БОЛЬШОГО ПРОЕКТА (>50 файлов):**
```

Этап 2 (Детектор): Много ложных срабатываний
```

## **💡 СОВЕТЫ ДЛЯ ЭФФЕКТИВНОЙ РАБОТЫ**

### **СОВЕТ 1: ПОДГОТОВЬТЕ КОД ПЕРЕД АУДИТОМ**
1. Удалите `node_modules/`, `vendor/`, `dist/` — они только мешают
2. Уберите тестовые файлы, документацию, изображения
3. Оставьте только исходный код и конфиги

### **СОВЕТ 2: ИСПОЛЬЗУЙТЕ ПРАВИЛЬНЫЕ КОМАНДЫ**
- Чётко следуйте формату из инструкции
- Копируйте ВЕСЬ вывод предыдущего этапа
- Не редактируйте выводы между этапами

### **СОВЕТ 3: ВЕДИТЕ ЛОГ РАБОТЫ**
Создайте текстовый файл с пометками:
```
[Дата] Аудит проекта [Название]
• Чат 1 запущен: 10:00
• Чат 1 завершён: 10:08 (получен пакет)
• Чат 2 запущен: 10:10
• Чат 2 завершён: 10:22 (14 проблем)
• ...
```

### **СОВЕТ 4: НАЧИНАЙТЕ С МАЛЕНЬКОГО ПРОЕКТА**
Для первого запуска возьмите:
- WordPress плагин из 5-10 файлов
- Или простой React компонент
- Чтобы понять логику работы системы

1. После каждого аудита анализируйте ложные срабатывания
2. Корректируйте промпты на основе статистики
3. Добавляйте специфичные правила для ваших проектов

### **КАК ДОБАВИТЬ ПОДДЕРЖКУ НОВОГО ЯЗЫКА:**
1. Отредактируйте промпт Контроллера (раздел определения типа)
2. Добавьте чек-листы в промпт Детектора
3. Добавьте стандартные исправления в промпт Исправителя

### **КАК СОКРАТИТЬ ВРЕМЯ:**
1. Уменьшите лимиты времени в промптах
2. Увеличьте пороги фильтрации (меньше проверок)
3. Анализируйте только критические файлы

## **🚨 ЧТО ДЕЛАТЬ ПОСЛЕ АУДИТА**

### **ЕСЛИ ВСЁ ХОРОШО (код безопаснее):**
1. Выполните чек-лист из финального отчёта
2. Закоммитьте изменения: `git commit -am "Security fixes from audit"`
3. Выложите на staging, протестируйте
4. Если ок — в прод

### **ЕСЛИ ЕСТЬ ПРОБЛЕМЫ (не всё исправлено):**
1. Исправьте вручную оставшиеся проблемы
2. Запустите повторный аудит для проверки
3. Или протестируйте исправления отдельно

### **ЕСЛИ СИСТЕМА ОШИБЛАСЬ (сломала код):**
1. Откатитесь к бэкапу: `git reset --hard`
2. Проанализируйте, на каком этапе ошибка
3. Сообщите разработчикам системы (если есть)
4. Исправьте проблемы вручную
