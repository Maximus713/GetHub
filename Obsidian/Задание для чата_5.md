ЗАДАНИЕ №1: Фундамент модуля и интеграция с ядром
================================================================================

**ФАЙЛЫ:**
  - СОЗДАТЬ: `module-fertilizer-selector/fertilizer-selector-module.php`
  - СОЗДАТЬ: `module-fertilizer-selector/includes/class-cache-manager.php`

**ТРЕБОВАНИЯ:**

1. **Главный файл модуля (`fertilizer-selector-module.php`):**
   - В самом начале файла выполнить проверку: `if ( ! class_exists( 'NPK_Calculators_Core' ) )`
   - Если класс ядра отсутствует:
     - НЕ инициализировать модуль (прервать выполнение с `return;`)
     - Добавить действие на `admin_notices` с выводом сообщения: 
       `<div class="notice notice-warning is-dismissible"><p>Модуль подбора удобрений требует активации основного плагина NPK Calculators.</p></div>`
   - Если класс ядра существует:
     - Запустить инициализацию модуля (подключение файлов, автозагрузка, хуки)
     - Использовать хук `plugins_loaded` для инициализации, чтобы гарантировать загрузку всех зависимостей

2. **Автозагрузка классов:**
   - Зарегистрировать автозагрузчик через `spl_autoload_register`
   - Префикс классов: `NPK_Selector_`
   - Маппинг: `NPK_Selector_Class_Name` → `includes/class-class-name.php`
   - Пример: `NPK_Selector_Cache_Manager` → `includes/class-cache-manager.php`

3. **Класс `NPK_Selector_Cache_Manager`:**
   - Реализовать методы:
     - `set( $key, $data, $expire = 3600 )` — сохраняет данные в транзиты WordPress
     - `get( $key )` — возвращает данные из кеша или false при отсутствии/истечении
     - `invalidate( $crop_id = null )` — удаляет кеш по конкретной культуре или весь кеш модуля
   - Формирование ключей:
     - Для всех ключей использовать префикс: `'npk_selector_'`
     - Для ключей с параметрами: `'npk_selector_' . md5( $crop_id . '_' . $phase_id )`
   - Внутри использовать нативные функции WordPress: `set_transient()`, `get_transient()`, `delete_transient()`

4. **Интеграция с БД:**
   - НЕ создавать новых таблиц
   - Использовать существующую таблицу `crop_phase_fertilizer` из основной версии 4.0
   - Получать объект БД через глобальную переменную: `global $wpdb; $table = $wpdb->prefix . 'crop_phase_fertilizer';`

**ЗАПРЕТЫ (из истории, актуальные для этапа):**

- ❌ **Неправильные имена файлов (Ошибка 1)** — пример: файл назван `class-cachemanager.php` вместо `class-cache-manager.php` → строго соблюдаем WordPress-стандарт: `class-{имя-класса}.php` с дефисами, все в нижнем регистре

- ❌ **Нарушение порядка загрузки (Ошибка 3)** — пример: попытка использовать классы до их подключения → все инициализации только после `plugins_loaded`, проверка существования ядра до любого кода модуля

- ❌ **Отсутствие префиксов в классах** — пример: класс назван `Cache_Manager` вместо `NPK_Selector_Cache_Manager` → все классы модуля ОБЯЗАНЫ иметь префикс `NPK_Selector_`

- ❌ **Прямое обращение к БД без `global $wpdb`** — пример: использование неподготовленных переменных в SQL → всегда используем `$wpdb->prepare()` для любых запросов с параметрами

- ❌ **Создание дублирующих таблиц** — пример: создание новой таблицы для связей вместо использования существующей → категорически запрещено создавать таблицы, БД версии 4.0 уже содержит все необходимые структуры
