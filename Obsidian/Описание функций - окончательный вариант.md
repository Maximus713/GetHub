# **ФУНКЦИОНАЛЬНОЕ ОПИСАНИЕ ДЛЯ ТЗ**
## Модуль 2: Калькулятор подбора удобрений по составу NPК

---

## **1. НАЗНАЧЕНИЕ И ГРАНИЦЫ СИСТЕМЫ**

### **Цель**
Инструмент для мгновенного подбора готовых коммерческих удобрений, максимально соответствующих пропорциям NPK потребностям сельскохозяйственной культуры на определённой фазе роста.

### **Что система ДЕЛАЕТ**
1. Сравнивает пропорции NPK удобрений с эталонными потребностями культур
2. Выводит отсортированный список удобрений с указанием процента соответствия
3. Предоставляет текстовые подсказки о наличии полезных микроэлементов
4. Работает в режиме реального времени при изменении выбора

### **Что система НЕ ДЕЛАЕТ**
- Не рассчитывает дозы внесения или концентрации растворов
- Не комбинирует несколько удобрений для достижения целевого состава
- Не учитывает наличие товара в магазинах
- Не предоставляет интерфейс для редактирования базы данных

---

## **2. АРХИТЕКТУРНЫЙ КОНТЕКСТ**

### **Место в системе**
Второй модуль в плагине NPK Calculators WordPress. Работает параллельно с первым модулем (калькулятор концентрации).

### **Источники данных**
Все данные берутся из общей базы данных плагина через единый интерфейс доступа.

### **Ограничения совместимости**
1. Не должен влиять на работу первого модуля
2. Должен использовать существующие структуры данных без дублирования
3. Должен регистрироваться через существующий механизм плагина
4. Все идентификаторы (имена функций, хуки, CSS-классы) должны быть уникальными

### **Интеграция с API базы данных:**

1. **Источник данных:** Модуль использует существующий класс `NPK_Database` из общего пространства плагина
2. **Требуемые методы:**
    - Получение списка культур с сортировкой
    - Получение списка фаз роста с сортировкой
    - Получение эталонных потребностей для всех или конкретных пар культура-фаза
    - Получение данных удобрений (минимальный и полный наборы)
        
3. **Ограничения доступа:** Модуль не должен напрямую обращаться к таблицам БД, только через публичный API `NPK_Database`

**Стратегия кеширования:**

1. **Уровень кеширования:** Результаты расчётов кешируются на уровне сервера
2. **Ключ кеша:** Формируется на основе пары "код культуры + код фазы"
3. **Инвалидация кеша:** Кеш автоматически сбрасывается при:
    - Изменении данных в таблице удобрений
    - Изменении эталонных потребностей культур
    - Ручной очистке кеша через административный интерфейс
4. **Время жизни:** Настраиваемый параметр (по умолчанию 1 час)

## **3. ДАННЫЕ**

### **Структура данных**
Система оперирует четырьмя основными сущностями:

1. **Культуры** (растения) — справочник с уникальными идентификаторами и названиями
2. **Фазы роста** — справочник этапов развития культур
3. **Потребности культур** — эталонные составы NPK для каждой пары культура-фаза, включая приоритетные микроэлементы
4. **Удобрения** — коммерческие продукты с составом NPK, типом и списком микроэлементов

### **Форматы данных**

- **Составы NPК:** Все значения хранятся в формате относительных пропорций, где первый элемент (Азот) равен 1.0 (при наличии) или 0 (при отсутствии). Примеры: `[1, 1.5, 3]` (соотношение 1:1.5:3), `[0, 2.6, 1.7]` (без азота, соотношение P:K = 2.6:1.7).

### **Динамичность**
Списки культур, фаз роста и удобрений являются динамическими и управляются через базу данных. Интерфейс автоматически адаптируется к изменениям.


### **Конфигурационные параметры (числовые константы):**

1. **Порог отображения:** 75% соответствия (удобрения с меньшим процентом скрываются в основном режиме)
2. **Границы цветовой индикации:**
    - Зелёный прогресс-бар: ≥85% соответствия
    - Оранжевый прогресс-бар: 75-84% соответствия
    - Серый прогресс-бар: <75% (только в fallback-режиме)
3. **Количественные лимиты:**
    - Fallback-режим: показывать 3 лучших варианта при отсутствии проходных
    - Первичный вид: показывать 5 лучших результатов
    - Расширенный вид: все результаты выше порога
4. **Время жизни кеша:** 1 час для результатов расчёта

## **4. ИНТЕРФЕЙС И ВЗАИМОДЕЙСТВИЕ**

### **Состояния интерфейса**
1. **Начальное** — выбраны культура и фаза по умолчанию (если данные доступны), отображаются результаты
2. **Рабочее** — пользователь выбирает культуру и фазу, видит мгновенное обновление результатов
3. **Ошибка данных** — если для выбранной пары нет эталонных данных, показывается информационное сообщение
4. **Пустая база** — если нет удобрений, показывается предупреждение

### **Поток взаимодействия**
1. Пользователь выбирает культуру (ряд кнопок)
2. Пользователь выбирает фазу роста (ряд кнопок)
3. Система мгновенно показывает preview-результаты
4. В фоне загружаются полные данные с сервера
5. При получении полных данных preview заменяется финальными результатами


### **Механизм Instant Preview:**

1. **Предзагрузка данных:** При первоначальной загрузке страницы на клиент передаются:
    - Списки всех культур и фаз роста
    - Все эталонные составы NPK (потребности для всех пар культура-фаза)
    - Минимальные данные всех удобрений (название и состав NPK)
2. **Клиентский расчёт:** При выборе культуры/фазы клиентская логика:
    - Находит эталонный NPК для выбранной пары
    - Рассчитывает процент соответствия для всех удобрений на предзагруженных данных
    - Немедленно отображает preview-таблицу
3. **Фоновое обновление:** Параллельно отправляется запрос на сервер для получения:
    - Полных данных удобрений (тип, микроэлементы)
    - Точного расчёта с учётом всех данных
    - Генерации текстовых подсказок
4. **Подмена данных:** При получении ответа с сервера preview заменяется финальными данными
    

**Форматы данных обмена:**

_AJAX-запрос содержит:_

- Выбранный код культуры
- Выбранный код фазы роста
- Код безопасности (nonce)

_AJAX-ответ содержит:_

- Флаг успешности выполнения
- Массив результатов (если успешно) или описание ошибки (если неуспешно)
- Флаг fallback-режима (true/false)
- Каждый результат включает:
    
    - Идентификатор удобрения
    - Название и тип
    - Состав NPK
    - Процент соответствия
    - Текстовые подсказки (массив строк)

### **Визуальная обратная связь**
- **Прогресс-бар соответствия:** зелёный (≥85%), оранжевый (75-84%), серый (<75% или fallback-режим)
- **Текстовые подсказки:** под строкой удобрения, курсивом, серым цветом
- **Индикация загрузки:** полупрозрачный оверлей при ожидании данных с сервера
- **Сообщения об ошибках:** стилизованные блоки для разных типов ошибок

## **5. АЛГОРИТМЫ И ЛОГИКА**

### **Основной алгоритм подбора**
Для сравнения пропорций NPK используется **коэффициент Отиаи**:
1. Оба состава (целевой и удобрения) нормализуются до суммы 1
2. Вычисляется степень перекрытия нормализованных векторов через минимумы компонентов
3. Результат преобразуется в процент соответствия (0-100%)
### Преобразование данных
Поскольку база данных хранит составы удобрений в процентном формате, а алгоритм работает с относительными пропорциями, система преобразует данные:

1. **С азотом:** `[N, P, K] → [1, P/N, K/N]`  
   Пример: `[16, 16, 16] → [1, 1, 1]`
2. **Без азота:** `[0, P, K] → [0, P/min(P,K), K/min(P,K)]`  
   Пример: `[0, 52, 34] → [0, 1.53, 1]`

**Свойство алгоритма:** Составы с одинаковыми пропорциями (например, `[1, 1.5, 3]` и `[2, 3, 6]`) дают 100% соответствие.

### **Процесс обработки**
1. **Фильтрация:** Отбираются удобрения с соответствием ≥75%
2. **Режим fallback:** Если таких нет — показываются 3 лучших варианта с соответствующим визуальным обозначением
3. **Сортировка:** По убыванию процента соответствия, при равенстве — по алфавиту названия
4. **Генерация подсказок:** Если у удобрения есть микроэлементы из списка приоритетов культуры — добавляется текстовая подсказка

### **Критерии и пороги**
- **Порог отображения:** 75% соответствия
- **Границы цветов:** зелёный ≥85%, оранжевый 75-84%, серый <75% (только в fallback)
- **Fallback:** показывать 3 лучших варианта при отсутствии проходных
- **Первичный вид:** показывать 5 лучших результатов, остальные — по кнопке "показать все"


### **Обработка особых случаев в данных:**

1. **Нулевые значения NPK:**
    
    - Если все три значения NPК цели равны 0 → пропускать расчёт, показывать сообщение
    - Если одно или два значения NPК цели равны 0 → использовать в расчёте как 0
    - Если значение NPК удобрения равно 0 → использовать в расчёте как 0
2. **Некорректные данные:**
    
    - Некорректный JSON в полях микроэлементов → трактовать как пустой массив
    - Отсутствующие записи в справочниках → исключать из интерфейса выбора
    - Повреждённые данные в БД → пропускать при расчёте с записью в лог
3. **Конфликт имён:** Все идентификаторы модуля (шорткод, CSS-классы, имена функций) должны иметь уникальный префикс, отличный от первого модуля

## **6. ОБРАБОТКА ОШИБОК**

### **Возможные проблемы**
1. **Пустая база удобрений** — нет данных для подбора
2. **Отсутствие эталонных данных** — для выбранной пары культура-фаза нет потребностей
3. **Ошибка связи с сервером** — невозможность получить актуальные данные
4. **Некорректные данные** — ошибки в форматах или значениях

### **Реакция системы**
- **Пустая база:** Показывать сообщение "База удобрений пуста" с рекомендацией обратиться к администратору
- **Нет эталонных данных:** Не позволять выбор такой пары при инициализации, при ручном выборе — сообщение "Рекомендации в разработке"
- **Ошибка связи:** Сохранять последние успешные результаты, показывать неблокирующее уведомление
- **Некорректные данные:** Игнорировать проблемные записи, вести лог для администратора

### **Восстановление работы**
Система должна сохранять работоспособность при любых данных:
- Нулевые значения NPK обрабатываются корректно
- Некорректные форматы игнорируются без падения системы
- При ошибках загрузки остаётся функциональным preview-режим
- Интерфейс всегда остаётся интерактивным

## **1. НАЗНАЧЕНИЕ И ГРАНИЦЫ СИСТЕМЫ**

### **1.1. Цель модуля**
Предоставить конечному пользователю (садоводу, агроному) инструмент для **мгновенного подбора готового коммерческого удобрения** из базы данных, максимально соответствующего по **пропорциям NPK (Азот-Фосфор-Калий)** потребностям конкретной сельскохозяйственной культуры на заданной фазе её роста.

### **1.2. Ключевой принцип**
Система подбирает **готовый продукт**, а не рассчитывает рецептуру смеси. Пользователь получает список конкретных марок удобрений, которые можно приобрести.

### **1.3. Жёсткие ограничения (Чего модуль НЕ делает)**
| Ограничение | Причина |
| :--- | :--- |
| ❌ **Не рассчитывает дозы, нормы внесения, концентрации.** | Это задача **Модуля 1** (калькулятор концентрации). |
| ❌ **Не комбинирует несколько удобрений** для достижения целевого состава. | Выходит за рамки задачи «подбор готового». |
| ❌ **Не предлагает аналоги или замены** при отсутствии конкретного товара в магазине. | Нет данных о наличии на складах. |
| ❌ **Не редактирует базу данных** удобрений и культур. | Это функция администрирования, вынесенная за пределы модуля. |
| ✅ **Только подбор** готового продукта по его паспортному составу. | |

## **2. ДАННЫЕ И ИХ ИСТОЧНИКИ**

### **2.1. Источник данных — Общая база данных плагина**
Все данные модуль получает **исключительно** из общей базы данных плагина, доступной через единый интерфейс **`NPK_Database`** (файл `shared/config/npk-database.php`).

## **3. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС (UX/UI)**

### **3.1. Общий вид и компоновка**
Интерфейс представляет собой **компактный, самодостаточный блок**, выводимый на странице WordPress через шорткод `[npk_calc_fertilizer_selector]`.
Формат: вертикальный поток с заголовком, блоками выбора и таблицей результатов.

### **3.2. Блок выбора данных**
*   **Культура:** Горизонтальный ряд интуитивных кнопок. Надписи — значения `name` из справочника `crops`. **Активная кнопка визуально выделяется.**
*   **Фаза роста:** Второй горизонтальный ряд кнопок. Надписи — значения `name` из справочника `growth_phases`.
*   **Механика выбора:**
    *   Выбор осуществляется нажатием.
    *   Новый выбор в одном ряду **автоматически снимает** предыдущий.
    *   Состояние «ничего не выбрано» **не предусмотрено** — всегда активна одна культура и одна фаза.

### **3.3. Блок отображения результатов**
*   **Заголовок:** Формируется динамически. Пример: *«Для томатов на фазе цветения: Идеальное соотношение: N-P-K 10-15-30»*.
*   **Таблица результатов:** Отображается сразу после выбора второй опции (культуры или фазы).
    *   **Строка = одно удобрение.**
    *   **Колонки:**
        1.  **Удобрение:** Название (`name`) + тип (`type`) меньшим шрифтом.
        2.  **Состав:** NPK в формате `N-P-K` (например, `10-18-32`).
        3.  **Соответствие:** Визуальный прогресс-бар + числовое значение (например, `██████████ 96%`).
    *   **Текстовые подсказки:** Выводятся под строкой удобрения, курсивом, серым цветом. Формат: *«Содержит Ca, B — полезно для этой фазы»*.
*   **Режимы отображения:**
    1.  **По умолчанию:** Показываются **топ-5** удобрений (см. сортировку в п. 4.3).
    2.  **Расширенный:** Под таблицей — кнопка **«Показать все варианты (N)»**. При нажатии отображается весь отфильтрованный список.

### **3.4. Визуальная индикация и цвета**
*   **Прогресс-бар соответствия:** Цвет определяется процентом.
    *   **≥ 85%:** Зелёный (CSS-класс `.match-high`).
    *   **75% — 84%:** Оранжевый/жёлто-зелёный (CSS-класс `.match-medium`).
    *   **< 75% (режим fallback):** Серый (CSS-класс `.match-low`). Используется только при отображении топ-3, если ни одно удобрение не преодолело порог в 75%.
*   **Важно:** Все цвета и стили определяются **исключительно в CSS-файлах** через кастомные свойства (CSS Custom Properties). JS оперирует только классами.

### **3.5. Начальное состояние (пользовательский сценарий)**
1.  **Первый вход:** При загрузке страницы система **автоматически пытается выбрать рабочую пару** «культура-фаза».
2.  **Логика выбора:**
    *   Берутся первые культура и фаза из динамически загруженных списков.
    *   Проверяется наличие записи в `crop_needs` для этой пары.
    *   **Если данные есть** → пара выбирается, производится расчёт, результаты отображаются.
    *   **Если данных нет** → система итерирует по фазам для выбранной культуры (или по культурам), пока не найдёт пару с существующими `needs`.
3.  **Гарантия работы:** В техническом задании будет требование о гарантированном наличии в БД хотя бы одной записи в `crop_needs` (рекомендуемая пара `tomato` + `vegetation`).

### **4.2. Алгоритм расчёта процента соответствия**
Используется **коэффициент Отиаи (Otsuka-Ochiai coefficient)**, измеряющий сходство **пропорций** (отношений N:P:K) между целевым составом и составом удобрения.

**Формула (с нормализацией):**
```python
# ВХОД: target_npk = [Nt, Pt, Kt], fert_npk = [Nf, Pf, Kf]
# 1. Нормализация векторов (приведение суммы к 1)
target_sum = Nt + Pt + Kt
Nt_norm = Nt / target_sum
Pt_norm = Pt / target_sum
Kt_norm = Kt / target_sum

fert_sum = Nf + Pf + Kf
Nf_norm = Nf / fert_sum
Pf_norm = Pf / fert_sum
Kf_norm = Kf / fert_sum

# 2. Расчёт коэффициента Отиаи для нормализованных векторов
numerator = min(Nt_norm, Nf_norm) + min(Pt_norm, Pf_norm) + min(Kt_norm, Kf_norm)
denominator = sqrt(Nt_norm**2 + Pt_norm**2 + Kt_norm**2) * sqrt(Nf_norm**2 + Pf_norm**2 + Kf_norm**2)

similarity = numerator / denominator
match_percent = round(similarity * 100)  # Итоговый процент
```
**Обоснование:** Алгоритм сравнивает именно **пропорции элементов относительно друг друга**, игнорируя общий масштаб. Это правильно для задачи подбора готового удобрения, где `10-15-30` и `1-1.5-3` — это одинаковая рекомендация по соотношению.

### **4.3. Фильтрация, сортировка и пороги**
1.  **Порог соответствия:** Для основного отображения учитываются удобрения с `match_percent >= MIN_MATCH_PERCENT` (по умолчанию 75%).
2.  **Fallback-режим:** Если ни одно удобрение не преодолевает порог, пользователю показываются **топ-N** (`FALLBACK_ITEMS_COUNT`) удобрений с наивысшим процентом. В JSON-ответ AJAX добавляется флаг `"used_fallback": true`.
3.  **Сортировка результатов:**
    *   **Первичный ключ:** `match_percent` (по убыванию).
    *   **Вторичный ключ (при равенстве процентов):** Название удобрения (`name`) по алфавиту (A-Z).
    *   **`priority` и `additives` НЕ влияют на порядок сортировки.**

### **4.4. Генерация текстовых подсказок**
Подсказки носят **строго информационный характер и не влияют на расчёт процента или сортировку**.
- **Логика:** Для каждого кода в массиве `priority` выбранной пары культура-фаза проверяется его наличие в массиве `additives` удобрения.
- **Формат:** При наличии совпадений генерируется фраза: *«Содержит {элементы} — полезно для этой фазы»*, где `{элементы}` — перечисление совпавших кодов через запятую (например, "Ca, B").
- **Системные эвристики (опционально):** Могут добавляться предупреждения. Пример: *«Не содержит азота — может быть недостаточно на стадии роста»*, если `Nf == 0` и фаза связана с активной вегетацией.

    - **Время жизни:** `CACHE_TTL_HOURS` (по умолчанию 1 час).
