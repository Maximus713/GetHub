ПРИМЕНЯЙТЕ ЭТИ КОЭФФИЦИЕНТЫ:

## ФОРМУЛА ПРИОРИТЕТА:
ПРИОРИТЕТ = (БАЗОВЫЙ_УРОВЕНЬ) × (КОЭФФИЦИЕНТ_ТИПА) × (КОЭФФИЦИЕНТ_ФАЙЛА)

- Дублирование кода (уровень 1) в style-helper.css

## **Этап 4: Практическая реализация "Тестового движка"**

**Создайте отдельный промпт для сложных случаев:**

```markdown
# ПРОМПТ X: ТЕСТ-ВЕРИФИКАТОР

ТЫ — ТЕСТ-ИНЖЕНЕР. Твоя задача — подтвердить или опровергнуть сложные проблемы.

## КОГДА ВЫЗЫВАТЬ ЭТОТ ПРОМПТ:
Только для проблем с приоритетом > 2.5 и неочевидных случаев.

## АЛГОРИТМ:

### 1. СОЗДАЙТЕ МИНИМАЛЬНЫЙ ТЕСТ:
```
ДЛЯ ПРОБЛЕМЫ "Возможная race condition в update_cache()":

ТЕСТОВЫЙ СЦЕНАРИЙ:
1. Два одновременных вызова update_cache() с разными данными
2. Проверить: не перезапишут ли они друг друга?
3. Ожидаемый результат: последнее значение корректно сохраняется

ПСЕВДОКОД ТЕСТА:
function test_race_condition() {
    // Параллельные вызовы (в идеале)
    result1 = update_cache('key', 'value1')
    result2 = update_cache('key', 'value2')
    
    final_value = get_cache('key')
    assert final_value == 'value2'  // или разумное значение
}
```

### 2. ВЫПОЛНИТЕ МЫСЛЕННЫЙ ТЕСТ:
```
АНАЛИЗ КОДА update_cache():
1. Есть ли блокировки (mutex, semaphore)?
2. Используется ли atomic operations?
3. Что происходит при одновременном доступе?

ЕСЛИ КОД:
- Использует file_put_contents() без locks → ДА, race condition
- Использует wp_cache_set() (atomic) → НЕТ, проблемы нет
- Использует transient (WordPress atomic) → НЕТ, проблемы нет
```

### 3. ВЕРДИКТ:
```
ЕСЛИ ТЕСТ ПАДАЕТ → реальная проблема
ЕСЛИ ТЕСТ ПРОХОДИТ → ложное срабатывание
ЕСЛИ НЕВОЗМОЖНО ПРОВЕРИТЬ → пометить как "требует ручной проверки"
```
```

```python
# Псевдокод для автоматизации
def run_audit(project_files):
    # Шаг 1: Контроллер анализирует проект
    prompt = controller_analyze(project_files)
    
    # Шаг 2: Выбираем сканер по типу проекта
    if "wordpress" in prompt:
        scanner = load_prompt("1-scanner-wordpress.md")
    elif "react" in prompt:
        scanner = load_prompt("1-scanner-react.md")
    
    # Шаг 3: Запускаем сканер
    issues = run_chatgpt(scanner, project_files)
    
    # Шаг 4: Фильтруем по весам
    real_issues = filter(issues, weight > 1.5)
    
    return real_issues
```
