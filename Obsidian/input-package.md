2. ПОРЯДОК СОЗДАНИЯ КОМПОНЕНТОВ
   3. [fertilizer-selector-module.php] → Фундамент жизненного цикла. Без регистрации модуля остальные файлы не будут загружены WordPress.
   4. [class-selection-engine.php] → Ядро логики. Все остальные PHP-компоненты зависят от его API; должен существовать до их написания.
   5. [class-data-adapter.php] → Подготовка данных для JS. Требует Selection_Engine для типовой валидации (но НЕ расчётов) и БД для извлечения справочников.
   6. [class-cache-manager.php] → Оптимизация. Зависит от Selection_Engine, который кеширует; Data_Adapter использует кеш для предзагрузки.
   7. [class-ajax-handler.php] → Транспортный слой. Зависит от Selection_Engine и Cache_Manager; должен быть готов до написания JS.
   8. [class-shortcode.php] → Интеграция с темой. Зависит от Data_Adapter (передача данных в JS) и Selection_Engine (косвенно — через кеш); регистрирует шорткод.
   9. [selector-template.php] → HTML-скелет. Создаётся после определения всех данных, которые он отображает (из Data_Adapter).
   10. [assets/js/selector.js + assets/css/selector.css] → Интерфейс. Финал, так как требует готового API (AJAX_Handler), данных (Data_Adapter) и DOM-структуры (template).

7. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ
   **Почему алгоритм Отиаи ТОЛЬКО в Selection_Engine:**  
   Это единственный источник истины для соответствия NPK. Любой другой слой, вычисляющий совпадение, создаст рассинхронизацию и сделает систему непредсказуемой.  
   
   **Почему Instant Preview — исключение из правила:**  
   Preview — это UX-эвристика, а не бизнес-логика. Её результат всегда перезаписывается серверным расчётом, не сохраняется и не влияет на смежные системы. ADR-2024-001 явно разрешает такие клиентские оптимизации при маркировке «Preview».  
   
   **Почему Fallback — архитектура, а не баг:**  
   Отсутствие удобрений ≥75% — штатная ситуация. Система не должна показывать пустой экран. 3 лучших варианта с явным флагом «fallback» — это контролируемое поведение, дающее пользователю прозрачность и выбор.

## **3. ЯДРО ЛОГИКИ: `Selection_Engine`**

### **3.1. Алгоритм Отиаи (коэффициент перекрытия)**

**Шаги:**
1. **Преобразование данных удобрений:**
   ```php
   // Проценты → относительные пропорции
   // [16, 16, 16] → [0.16, 0.16, 0.16]
   $fert_relative = array_map(fn($p) => $p / 100, $fertilizer_npk);
   ```

2. **Нормализация до суммы 1:**
   ```php
   // Используем метод из БД!
   $norm_target = NPK_Database::normalize_npk($target_npk);    // [1.0, 2.0, 1.0] → [0.25, 0.5, 0.25]
   $norm_fert = NPK_Database::normalize_npk($fert_relative);   // [0.16, 0.16, 0.16] → [0.333, 0.333, 0.333]
   ```

3. **Расчёт перекрытия:**
   ```php
   $overlap = 0;
   for ($i = 0; $i < 3; $i++) {
       $overlap += min($norm_target[$i], $norm_fert[$i]);
   }
   $match_percentage = $overlap * 100;
   ```

**Свойство:** Составы с одинаковыми пропорциями (10-15-30 и 20-30-60) дают 100% соответствие.

### **3.2. Основной метод:**
```php
/**
 * Подбор удобрений для культуры на фазе роста
 * @param string $crop_id Идентификатор культуры ('tomato')
 * @param string $phase_id Идентификатор фазы ('blooming')
 * @return array Структурированные результаты
 */
public static function find_matching_fertilizers($crop_id, $phase_id): array
```

### **3.3. Логика обработки:**
1. **Получить эталон:** `NPK_Database::get_crop_phase_requirements()`
2. **Получить все удобрения:** `NPK_Database::get_fertilizers()`
3. **Преобразовать проценты удобрений** в относительные величины
4. **Рассчитать соответствие** для каждого удобрения
5. **Фильтровать по порогу 75%** (из `get_constants()['thresholds']['min_match_percentage']`)
6. **Fallback режим:** Если проходных < 1 → вернуть 3 лучших с флагом `'fallback' => true`
7. **Сортировать:** По убыванию соответствия, при равенстве → по алфавиту
8. **Генерация подсказок:** Если `additives` ∩ `priority` ≠ ∅

### B.2. JavaScript (UI) — UX логика без бизнес-логики

JavaScript:
- ✅ **МОЖЕТ ДЛЯ UX:**

    - интерполировать цвет внутри `state.range`

- ❌ **НЕ ИМЕЕТ ПРАВА:**
    - изменять алгоритм определения `state` (правила п.4.3)
    - игнорировать финальный `state` с сервера
    - быть источником истины для финальных данных
    - принимать решения о безопасности

// Для определения предварительного state (те же правила что и сервер)
function getPreviewState(concentration, profile) {
    for (let state of profile.states) {
        if (concentration >= state.range[0] && concentration < state.range[1]) {
            return state;
        }
    }
    return profile.states[profile.states.length - 1]; // последний state
}

    - финальный `state` как подтверждённый результат

    /**
     * Нормализует вектор NPK (сумма компонентов = 1)
     * Вспомогательный метод для расчёта коэффициента Отиаи
     * 
     * @param array $npk Вектор NPK [N, P, K]
     * @return array Нормализованный вектор
     */
    private static function normalize_npk($npk) {
        if (!is_array($npk) || count($npk) !== 3) {
            return [0, 0, 0];
        }
        
        $sum = array_sum($npk);
        
        // Избегаем деления на ноль
        if ($sum == 0) {
            return [0, 0, 0];
        }
        
        return [
            $npk[0] / $sum,
            $npk[1] / $sum,
            $npk[2] / $sum
        ];
    }

    /**
     * Возвращает список фаз роста для конкретной культуры
     * Формат: ['seedling' => '🌱 Рассада', 'blooming' => '🌸 Цветение', ...]
     * 
     * @param string $crop_id Идентификатор культуры (например, 'tomato')
     * @return array Ассоциативный массив [ID_фазы => "Наименование с эмодзи"] или пустой массив
     */
    public static function get_phases_list($crop_id) {
        $crops = self::get_crops();
        
        if (!isset($crops[$crop_id]) || !isset($crops[$crop_id]['phases'])) {
            return [];
        }
        
        $phases = [];
        foreach ($crops[$crop_id]['phases'] as $phase_id => $phase_data) {
            $phases[$phase_id] = $phase_data['emoji'] . ' ' . $phase_data['name'];
        }
        
        return $phases;
    }
    
    /**
     * Возвращает эталонные потребности культуры на определённой фазе роста

     * @param string $phase_id Идентификатор фазы (например, 'blooming')
     * @return array|false Массив с данными или false если не найдено
     */
    public static function get_crop_phase_requirements($crop_id, $phase_id) {
        $crops = self::get_crops();
        
        // Проверка существования культуры и фазы

        return [
            // Основные данные

            // Идентификаторы
            'crop_id' => $crop_id,
            'phase_id' => $phase_id
        ];
    }
