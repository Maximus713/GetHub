**Теперь я понимаю корень проблемы!** Это не вопрос "с нуля vs исправлять", а **проблема методологии работы с чатами**. Когда ошибки повторяются 5+ раз — это системная проблема.

## 🎯 ГЛАВНАЯ ПРОБЛЕМА

Чат-модели **не умеют читать длинные ТЗ как люди**. Они:
1. **Теряют контекст** после ~4000 токенов
2. **Не запоминают "запреты"** из начала документа к концу
3. **"Лениво" интерпретируют** сложные архитектурные правила
4. **Возвращаются к шаблонам** из тренировочных данных

## 💡 РЕШЕНИЕ: **ЖЕСТКАЯ ПОЭТАПНАЯ МЕТОДОЛОГИЯ**

Вам нужна не новая попытка, а **новая стратегия работы**. Вот пошаговый план:

### **ШАГ 0: Подготовка "оружия"**

1. **Создайте МИНИ-ТЗ для каждого файла** отдельно:
   - `Calculation_Engine-ТЗ.txt` (только для этого файла)
   - `AJAX_Handler-ТЗ.txt`
   - и т.д.

2. **В каждом мини-ТЗ повторите КРИТИЧЕСКИЕ запреты** (да, дублировать!)

### **ШАГ 1: НОВЫЙ ЧАТ + НОВАЯ СТРАТЕГИЯ**

**Сообщение 1 (самое важное):**
```
ЗАПРЕЩЕНО читать дальше пока не подтвердишь!

Ты будешь разрабатывать ОДИН файл за раз. Первый файл: Calculation_Engine.php.

ПРАВИЛА РАБОТЫ:
1. Ты получаешь ТЗ ТОЛЬКО для этого файла
2. Ты НЕ ДОЛЖЕН предполагать, что знаешь другие файлы
3. Перед кодом ты ДОЛЖЕН перечислить ВСЕ требования из ТЗ
4. Если что-то не ясно — СРАЗУ спрашивай

Готов продолжить? Ответь "ГОТОВ К Calculation_Engine.php"
```

### **ШАГ 2: Расчетное ядро (САМОЕ ВАЖНОЕ)**

**Сообщение 2 (отправляете после подтверждения):**
```
# ТЗ ДЛЯ Calculation_Engine.php

## АБСОЛЮТНЫЕ ЗАПРЕТЫ (нарушение = стоп):
1. ❌ НИКАКИХ вызовов других классов модуля (Data_Adapter, AJAX_Handler и т.д.)
2. ❌ НИКАКОЙ логики определения state вне этого класса
3. ❌ НИКАКИХ обращений к БД кроме NPK_Database::методы()

## МЕТОДЫ (только эти):
public static function calculate($fertilizer_id, $concentration, $water_volume, $ground_type): array

protected static function validate_solubility_total($value): float
protected static function find_state_for_concentration($concentration, $states): array

## ФОРМУЛА МАССЫ (точно так):
масса_г = (концентрация/100) × объем_л × 1000 × (100 / solubility_total)

## ВАЛИДАЦИЯ solubility_total (точно так):
if ($value === null || $value === 0) return 100;
if ($value < 1) return 1;
if ($value > 100) return 100;
return (float)$value;

## ОПРЕДЕЛЕНИЕ STATE (алгоритм):
1. Для всех состояний кроме последнего: lower <= conc < upper
2. Для последнего состояния: lower <= conc <= upper
3. Если conc ниже первого диапазона — вернуть первое состояние
4. Если conc выше последнего — вернуть последнее

## ВОЗВРАЩАЕМЫЙ МАССИВ (точно такие ключи):
[
    'fertilizer_mass' => int,
    'concentration'   => float,
    'water_volume'    => float,
    'state' => [
        'id'          => string,
        'name'        => string,
        'color'       => string,
        'emoji'       => string,
        'description' => string,
        'range'       => [float, float]
    ],
    'warnings' => []
]

---

ТВОЯ ЗАДАЧА:
1. Перечисли ВСЕ требования из этого ТЗ
2. Задай вопросы если что-то неясно
3. Только потом напиши код Calculation_Engine.php
```

### **ШАГ 3: Проверка ДО генерации кода**

**Если чат пытается сразу писать код:**
```
СТОП! Ты не выполнил шаг 1. 
Перечисли ВСЕ требования из ТЗ по пунктам.
Только после этого можно писать код.
```

### **ШАГ 4: Изоляция чатов**

**Создайте ОТДЕЛЬНЫЙ чат для каждого файла:**
- Чат 1: Только для `Calculation_Engine.php`
- Чат 2: Только для `AJAX_Handler.php`
- Чат 3: Только для `Data_Adapter.php`
- и т.д.

**В каждом чате — ТОЛЬКО ТЗ для этого файла.**

## 🚨 КАК БОРОТЬСЯ С ТИПИЧНЫМИ ОШИБКАМИ

### **Ошибка 1: "State определяется в JS"**
**Лечение:** В ТЗ для `calculator.js` добавить:
```
ЗАПРЕЩЕНО:
- if (concentration >= range[0]) 
- Любая логика выбора state
- Сравнение концентрации с диапазонами

State приходит ТОЛЬКО из AJAX-ответа.
```

### **Ошибка 2: "Data_Adapter участвует в расчетах"**
**Лечение:** В ТЗ для `Data_Adapter.php`:
```
ЗАПРЕЩЕНО:
- Вызывать Calculation_Engine
- Участвовать в AJAX-цепочке
- Определять state

МОЖНО ТОЛЬКО:
- Готовить данные для wp_localize_script()
- Форматировать данные для отображения
```

### **Ошибка 3: "Нарушение слоев"**
**Лечение:** В начале КАЖДОГО ТЗ:
```
Ты создаешь файл [ИмяФайла.php]. 
Он находится в слое [НазваниеСлоя].
Может вызывать только: [список разрешенных классов]
Не может вызывать: [список запрещенных классов]
```

## 📊 ТАКТИКА "СЛОМАННОГО ТЕЛЕФОНА"

Если чат продолжает ошибаться:

1. **Стоп-слово:** `АРХИТЕКТУРНАЯ ОШИБКА`
2. **Анализ:** "Ты предложил [код]. Это нарушает [правило] потому что [причина]"
3. **Перезапуск:** "Начни заново, но сначала подтверди что понял запрет: [конкретный запрет]"
