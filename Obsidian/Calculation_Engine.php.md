# ФАЙЛ: `includes/class-calculation-engine.php`
# СЛОЙ: Ядро
# НАЗНАЧЕНИЕ: Единственный источник истины для всех расчётов, определения состояния (state) и бизнес-логики модуля.

## 🎯 ОСНОВНАЯ ЦЕЛЬ ЭТОГО ФАЙЛА
Содержит **все формулы** и **алгоритмы** для расчёта массы удобрения и определения состояния (state) раствора на основе данных из БД. Является **абсолютным центром логики** модуля. Не занимается отображением, транспортом данных или адаптацией форматов.

## 📊 МЕСТО В АРХИТЕКТУРЕ
- **Находится в слое:** Ядро (чистая бизнес-логика)
- **Может вызывать:** Только статические методы класса `NPK_Database` из `shared/config/npk-database.php` (`::get_fertilizers()`, `::get_concentration_profiles()`, `::get_constants()`).
- **Не может вызывать:** Любые другие классы модуля (`Data_Adapter`, `AJAX_Handler`, `Shortcode`), функции WordPress, JS-скрипты.
- **Вызывается из:** Любого слоя, отвечающего за транспорт данных (например, `AJAX_Handler`).  
Сам класс **не знает и не зависит** от вызывающей стороны.

## ✅ РАЗРЕШЕНО (явный список)
1.  Получать сырые данные напрямую из `NPK_Database`.
2.  Реализовывать **все формулы** расчёта массы и **все алгоритмы** определения состояния (state) согласно ТЗ п.4.
3.  Содержать внутренние защитные методы (например, валидацию растворимости).
4.  Возвращать структурированный массив с результатами, предупреждениями и скорректированными значениями.
5.  Обрабатывать граничные условия входных данных (корректировать значения, если они вышли за допустимые пределы).

## ❌ ЗАПРЕЩЕНО (явный список, с акцентом на прошлые ошибки)
1.  **НИКАКИХ вызовов других классов модуля** (прошлая ошибка: чаты пытались вызывать `Data_Adapter` для подготовки данных).
2.  Определять state **в любом другом месте** системы (прошлая ошибка: state определялся в JS или `Data_Adapter`).
3.  Участвовать в цепочке AJAX или генерировать HTML/JSON.
4.  Содержать логику, связанную с отображением (интерполяция цветов, формирование строк для UI).
5.  Дублировать данные из БД или хранить жёстко прописанные значения (все данные — только из `NPK_Database`).

## 🔗 ЗАВИСИМОСТИ И ДАННЫЕ
- **Получает данные из:** Статических методов класса `NPK_Database` (`shared/config/npk-database.php`).
- **Передает данные в:** Возвращает массив. Передача данных осуществляется через вызывающий код (`AJAX_Handler`).
- **Использует константы:** `PHP_ROUND_HALF_UP` для округления. Все числовые константы (пороги, пределы) берутся из `NPK_Database::get_constants()`.

## ⚠️ КРИТИЧЕСКИЕ ТРЕБОВАНИЯ (нарушение = неприемка)
1.  **ЕДИНСТВЕННЫЙ ИСТОЧНИК ИСТИНЫ:** Все конечные числовые результаты (масса, state) для UI должны порождаться **только** этим классом.
2.  **НЕЗАВИСИМОСТЬ:** Класс должен быть полностью независим и работоспособен без любого другого файла модуля, кроме `npk-database.php`.
3.  **СТРОГОЕ СОБЛЮДЕНИЕ ФОРМУЛ:** Реализация формул массы и алгоритма определения state должна быть дословной, как описано в ТЗ п.4.1 и п.4.3.
4.  **ПОЛНАЯ ИЗОЛЯЦИЯ ОТ UI:** Класс не должен содержать даже намёков на логику отображения (цвета, эмодзи, тексты описаний — это данные, которые он только передаёт).
