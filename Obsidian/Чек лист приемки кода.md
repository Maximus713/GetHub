# ЧЕК-ЛИСТ ПРИЁМКИ КОДА

## Модуль «Калькулятор концентрации рабочего раствора»

> **Правило:**  
> ❌ Любой пункт со статусом «НЕ ВЫПОЛНЕНО» = модуль **НЕ ПРИНИМАЕТСЯ**, независимо от работоспособности UI.

---

## 1. СТРУКТУРА ПРОЕКТА (КРИТИЧЕСКИ)

### 1.1. Структура папок

-  В корне есть папка `npk-calculators/`
    
-  БД расположена **строго** в `shared/config/npk-database.php`
    
-  Код модуля концентрации находится **только** в `module-concentration/`
    
-  Нет PHP-файлов модуля вне `module-concentration/`
    

❌ Любые классы концентрации вне модуля — **автоотказ**

---

### 1.2. Один класс — один файл

-  `class-calculation-engine.php` → **только** `Calculation_Engine`
    
-  `class-data-adapter.php` → **только** `Data_Adapter`
    
-  `class-ajax-handler.php` → **только** `AJAX_Handler`
    
-  `class-shortcode.php` → **только** `Shortcode`
    
-  Нет объединённых или вспомогательных классов
    

---

## 2. CALCULATION_ENGINE — ЦЕНТР ИСТИНЫ

### 2.1. Формулы

-  Формула массы реализована **только** в `Calculation_Engine`
    
-  В коде нет альтернативных или дублирующих формул
    
-  `solubility_total` учитывается **обязательно**
    

---

### 2.2. Валидация solubility_total

-  В `Calculation_Engine` есть метод:
    

```php
validate_solubility_total()
```

-  Метод используется **перед каждым расчётом**
    
-  БД не изменяется
    
-  Значения 0 / NULL корректируются в 100
    

---

### 2.3. Определение state

-  `state` определяется **только** в `Calculation_Engine`
    
-  Используется правило:
    
    - `start ≤ X < end` для всех, кроме последнего
        
    - `start ≤ X ≤ end` для последнего
        
-  Нет логики state вне `Calculation_Engine`
    

❌ Если state считается в JS — **автоотказ**

---

## 3. DATA_ADAPTER — ТОЛЬКО UI

### 3.1. Допустимые действия

-  Вызывает **только** `NPK_Database::get_*()`
    
-  Подготавливает данные **только** для `wp_localize_script`
    
-  Может валидировать данные **только для отображения**
    

---

### 3.2. Запрещённые действия

-  НЕ вызывает `Calculation_Engine`
    
-  НЕ участвует в AJAX
    
-  НЕ передаёт данные в расчёт
    
-  НЕ определяет state
    
-  НЕ содержит формул
    

❌ Любое участие в расчётной цепочке — **автоотказ**

---

## 4. AJAX_HANDLER — ТРАНСПОРТ, НЕ ЛОГИКА

-  Проверяет **наличие** всех обязательных полей
    
-  НЕ валидирует диапазоны
    
-  НЕ определяет state
    
-  Вызывает **только** `Calculation_Engine::calculate()`
    
-  Возвращает **только JSON**
    

---

## 5. JAVASCRIPT — НЕ ИСТОЧНИК ИСТИНЫ

### 5.1. Допустимо

-  Локальный предварительный расчёт массы
    
-  Анимации и мгновенный UI-отклик
    
-  Интерполяция цвета поля концентрации
    
-  Отображение данных, полученных от сервера
    

---

### 5.2. Запрещено

-  Сравнение концентрации с `state.range`
    
-  Выбор или определение state
    
-  Любая логика вида:
    

```js
if (concentration >= range[0]) { ... }
```

-  Хранение состояния как источника истины
    

❌ Если JS «знает», какой state активен — **автоотказ**

---

## 6. UI-STATE (ЕДИНСТВЕННЫЙ ДОПУСТИМЫЙ)

-  Удобрение выбрано всегда (первое по `id`)
    
-  Нет «пустого» состояния калькулятора
    
-  Любое изменение → перерасчёт
    
-  UI **всегда** отображает рабочий пример
    

---

## 7. ЦВЕТ И ВИЗУАЛ

-  Слайдер — один
    
-  Заливка слайдера = `state.color` (сплошной)
    
-  Нет градиентов на слайдере
    
-  Поле концентрации:
    
    - фон интерполируется от белого к `state.color`
        
    - расчёт **только в JS**
        
-  Сервер **НЕ** возвращает интерполированный цвет
    

---

## 8. ИСТОЧНИК ДАННЫХ

-  Все справочные данные берутся из `npk-database.php`
    
-  Нет жёстко прописанных значений
    
-  `water_volume_max` берётся из `get_constants()`
    
-  Профили грунта используются **только как states**
    

---

## 9. ФИНАЛЬНЫЙ КРИТЕРИЙ

Ответьте **ДА** на все вопросы:

-  Есть ровно **один** источник истины?
    
-  State определяется только на сервере?
    
-  UI не принимает решений?
    
-  Data_Adapter не участвует в расчётах?
    
-  Calculation_Engine можно вызывать без UI?
    

❌ Если хотя бы один ответ «НЕТ» — **МОДУЛЬ НЕ ПРИНЯТ**
