## **КОГДА НУЖЕН 5-Й ПРОМПТ:**

**Промпт 5 нужен ТОЛЬКО в 3 случаях:**

### **СЛУЧАЙ 1: Когда код УСПЕШНО прошёл все этапы**
- Контроллер → настроил
- Детектор → нашёл проблемы  
- Валидатор → отфильтровал
- Исправитель → исправил
- Верификатор → подтвердил, что всё работает

**Тогда Промпт 5:** Создаёт финальный отчёт и ВЫДАЁТ код пользователю.

---

### **СЛУЧАЙ 2: Когда требуется ОТКАТ**
- Верификатор обнаружил критические проблемы
- Риск выпуска > 50 баллов
- Решение: полный откат

**Тогда Промпт 5:** Выполняет откат и создаёт отчёт "почему не получилось".

---

### **СЛУЧАЙ 3: Когда нужна ПАУЗА между итерациями**
- Исправлена часть проблем
- Некоторые отложены
- Требуется "снимок" текущего состояния

**Тогда Промпт 5:** Сохраняет промежуточное состояние для продолжения позже.

---

## **ПРОМПТ 5: ФИНАЛЬНЫЙ ДОКУМЕНТАТОР-АРХИВАТОР**

```markdown
# ПРОМПТ 5: ФИНАЛЬНЫЙ ДОКУМЕНТАТОР-АРХИВАТОР

ТЫ — АРХИВАТОР СИСТЕМЫ. Твоя задача — ЗАВЕРШИТЬ процесс и подготовить ИТОГОВЫЕ МАТЕРИАЛЫ.

## КОГДА ЗАПУСКАТЬ:
ТОЛЬКО по команде от Верификатора:
- "ВЫПУСТИТЬ_КОД" — если всё успешно
- "ВЫПОЛНИТЬ_ОТКАТ" — если критически проблемы
- "СОХРАНИТЬ_СОСТОЯНИЕ" — для паузы

## ВАРИАНТ A: УСПЕШНОЕ ЗАВЕРШЕНИЕ (ВЫПУСТИТЬ_КОД)

### ЗАДАЧИ:
1. Подготовить ИСПРАВЛЕННЫЙ КОД к передаче
2. Создать ПОЛНЫЙ ОТЧЁТ о проделанной работе
3. Сформировать ИНСТРУКЦИИ по использованию
4. Архивировать ВСЮ историю изменений

### ФОРМАТ ВЫВОДА:
```

- Начало аудита: [дата/время]

🔍 ЧТО БЫЛО СДЕЛАНО:

2. ПОИСК ПРОБЛЕМ (Детектор):

   - Найдено потенциальных проблем: Y
   - Основные категории: [список]

3. ВАЛИДАЦИЯ (Валидатор):
   - Передано на проверку: Y проблем

   - Принято к исправлению: Z проблем

   - Отказано: C проблем (причины: ...)

5. ВЕРИФИКАЦИЯ (Верификатор):
   - Протестировано сценариев: N
   - Успешно пройдено: M
   - Обнаружено регрессий: 0
   - Оценка риска: [число] баллов (<20 - безопасно)

✅ ИСПРАВЛЕННЫЕ КРИТИЧЕСКИЕ ОШИБКИ:
1. [Ошибка 1] — [файл:строка] — [что исправлено]
2. [Ошибка 2] — [файл:строка] — [что исправлено]
3. [Ошибка 3] — [файл:строка] — [что исправлено]

⚠️ ОСТАВШИЕСЯ ПРОБЛЕМЫ (не критичные):
- [Проблема 1] — [рекомендация]
- [Проблема 2] — [рекомендация]

📁 ИСПРАВЛЕННЫЙ КОД:
[ПОЛНЫЙ КОД ВСЕХ ИЗМЕНЕННЫХ ФАЙЛОВ]

📄 НЕИЗМЕНЕННЫЕ ФАЙЛЫ:
[список файлов, которые не менялись]

📋 ИНСТРУКЦИИ ПО ИСПОЛЬЗОВАНИЮ:
1. Установка: [шаги]
2. Тестирование: [как проверить исправления]
3. Мониторинг: [на что обратить внимание]

⚠️ ВАЖНЫЕ ПРЕДУПРЕЖДЕНИЯ:
- [Что ещё нужно проверить вручную]
- [Какие риски остались]
- [Когда рекомендован следующий аудит]

🏁 АУДИТ УСПЕШНО ЗАВЕРШЁН. КОД ГОТОВ К ИСПОЛЬЗОВАНИЮ.
```

## **КОГДА ИСПОЛЬЗОВАТЬ КАЖДЫЙ ВАРИАНТ:**

### **Вариант A (ВЫПУСТИТЬ_КОД)** — когда:
- Верификатор дал оценку риска < 20 баллов
- Все критические сценарии работают
- Нет новых уязвимостей безопасности
- Код готов к использованию

### **Вариант B (ОТКАТ)** — когда:
- Верификатор дал оценку риска > 50 баллов
- Критические сценарии не работают
- Обнаружены новые уязвимости безопасности
- Исправления создали больше проблем, чем решили

### **Вариант C (ПАУЗА)** — когда:
- Процесс занял > 1 часа и нужно сделать перерыв
- Обнаружены проблемы, требующие ручного вмешательства
- Нужно согласование с разработчиком
- Достигнут лимит исправлений за одну сессию

## **ПРАВИЛА ИСПОЛЬЗОВАНИЯ ПРОМПТА 5:**

1. **НЕ запускайте напрямую** — только по команде от Верификатора
2. **Сохраняйте все данные** — промпт работает с полной историей
3. **Выводите полный код** — если Variant A, то весь исправленный код
4. **Архивируйте отчёты** — для истории и анализа

## **ПОЧЕМУ ЭТОТ ПРОМПТ ВАЖЕН:**

### **Решает проблему "а что дальше?"**
После 4 этапов система должна ЧТО-ТО сделать:
- Выдать код? → Variant A
- Откатить? → Variant B  
- Сохранить? → Variant C

### **Создаёт accountability**
Полная документация:
- Что было сделано
- Почему такие решения
- Что получилось
- Что не получилось и почему

### **Обеспечивает преемственность**
Можно прервать процесс и продолжить позже.

**Ваша полная система теперь:**
```
0. Контроллер → стратегия
1. Детектор → поиск
2. Валидатор → фильтрация  
3. Исправитель → исправления
4. Верификатор → проверка
5. Документатор → завершение
```

**Это ПОЛНАЯ, самодостаточная система аудита и рефакторинга.** 🚀
