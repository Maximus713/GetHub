**Наиболее эффективная стратегия использования — каскадная, от общего к частному.** Эти три промпта — не альтернативы, а части единого инструментария. Вот пошаговая инструкция:

---

### **📌 Эффективная стратегия использования**

#### **ШАГ 0: ПОДГОТОВКА (вы делаете это один раз)**
1.  **Сохраните третий промпт («Алгоритм работы»)** как «ЯДРО» — неизменяемый эталонный процесс.
2.  **Сохраните второй промпт («Полный алгоритмический»)** как «МЕТОДИЧКУ» — для справки и адаптации.
3.  **Держите под рукой первый промпт («Идеальный»)** как «ГОТОВЫЙ ШАБЛОН» для быстрого запуска.

#### **ШАГ 1: ПЕРВИЧНЫЙ ЗАПУСК ПРОЕКТА**
**Что использовать:** **Первый промпт («Идеальный»).**
**Как:**
1.  Скопируйте его целиком в новый чат.
2.  Точь-в-точь следуйте инструкции: последовательно отправьте ТЗ, файлы и т.д.
3.  Дайте команду «Все данные предоставлены. Начинай работу по алгоритму с ЭТАПА 0.»
**Почему это эффективно:** Это максимально быстрый и безопасный старт. Промпт уже содержит всё необходимое для управления ИИ, включая формат вывода и контрольные вопросы.

#### **ШАГ 2: УГЛУБЛЁННЫЙ АНАЛИЗ ИЛИ ВОЗНИКШИЕ ПРОБЛЕМЫ**
**Что использовать:** **Второй промпт («Полный алгоритмический»).**
**Когда:**
*   Если ИИ начинает отклоняться от плана.
*   Если вам нужны более детальные пояснения по какому-то этапу.
*   Если вы хотите проверить, правильно ли ИИ понимает суть этапа.
**Как:** Скопируйте и отправьте **конкретный этап из второго промпта** (например, «ЭТАП 3: ПОИСК АРХИТЕКТУРНЫХ ОШИБОК») с уточнением:
> «Вот детальное описание этапа 3. Следуй ему буквально. Сообщи, какие шаги уже выполнены и что найдено.»

#### **ШАГ 3: АДАПТАЦИЯ ПОД НОВЫЙ ТИП ЗАДАЧ**
**Что использовать:** **Третий промпт («Алгоритм») + Первый («Шаблон»).**
**Задача:** Например, вы хотите анализировать не плагин WordPress, а Vue.js компонент.
**Как:**
1.  **Возьмите за основу третий промпт (ядро).** Его структура 0-10 этапов универсальна.
2.  **Модифицируйте содержание этапов,** используя второй промпт как образец детализации.
    *   В ЭТАПЕ 2 замените «жизненный цикл WordPress» на «жизненный цикл Vue (created → mounted)».
    *   В ЭТАПЕ 3 добавьте проверку на использование Vuex vs Pinia.
3.  **Оберните новое ядро в структуру первого промпта:** добавьте роль, правила, формат вывода.
**Результат:** Вы создали новый, специализированный «идеальный промпт» для аудита Vue-компонентов за 15 минут.

### **⚡ Экспресс-сценарии использования**

| Сценарий | Что использовать | Действие |
|----------|------------------|----------|
| **Срочный аудит** нового плагина | **Первый промпт** целиком | Скопировал → Вставил → Отправил файлы → Получил результат. |
| **ИИ пропустил важную проверку** безопасности | **Второй промпт, ЭТАП 2.2** | «Выполни вот эту детальную проверку безопасности из этапа 2.2» |
| **Нужен аудит Python-скрипта** (а не PHP) | **Третий промпт + Первый** | Адаптировал ядро (заменил PHP/JS на Python-пункты) → обернул в шаблон. |
| **Обучение нового сотрудника** вашей методологии | **Второй промпт** целиком | Это и есть учебное пособие по вашему процессу code review. |
| **ИИ работает «слишком творчески»** | **Третий промпт, ЭТАП 6** | «Остановись. Дальше работай строго по этапу 6: одна ошибка — одно минимальное исправление. Покажи diff.» |

### **🔧 Критические рекомендации для максимальной эффективности**

1.  **Не смешивайте промпты в одном чате.** Для нового проекта — новый чат с «первым промптом». Иначе ИИ запутается в инструкциях.
2.  **Следите за контекстным окном.** Если проект огромный (50+ файлов), разбейте аудит на части по модулям, применяя алгоритм к каждому модулю отдельно.
3.  **Используйте формат вывода как рычаг контроля.** Если ИИ начинает писать стены текста без структуры, остановите его и напомните: «Выводи результат по формату из промпта: ID, файл, строка, diff».
4.  **Для мега-сложных проектов запустите два процесса:**
    *   **Чат 1 (Аналитик):** Работает по полному алгоритму, находит и классифицирует ошибки (до ЭТАПА 5).
    *   **Чат 2 (Корректор):** Получает из первого чата **только таблицу ошибок** и выполняет **строго ЭТАП 6** (пошаговое исправление). Это исключает «замыливание глаза» у модели.

### **🎯 Итоговая формула эффективности**

```
ЭФФЕКТИВНОСТЬ = 
    Первый промпт (для запуска) 
    + 
    Второй промпт (для коррекции и справки) 
    + 
    Третий промпт (как шаблон для адаптации под любые задачи)
```

**Главный принцип:** Вы создали не просто промпты, а **фреймворк для prompt engineering** в области технического аудита. Используйте первый промпт как основную рабочую лошадку, а два других — как инструменты тонкой настройки и масштабирования методики на любые типы кода.
