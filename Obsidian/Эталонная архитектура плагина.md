# 🔹 ЭТАЛОННАЯ АРХИТЕКТУРА ПЛАГИНА

## 1. УРОВНИ (СЛОИ)

```
[ npk-database.php ]        ← ДАННЫЕ (единственный источник)
        ↑
[ Calculation_Engine ]      ← ЧИСТАЯ ЛОГИКА РАСЧЁТА
        ↑
[ AJAX_Handler ]            ← ТРАНСПОРТ
        ↑
[ JS ]                      ← UI
```

```
[ Data_Adapter ] ─────────→ JS (ТОЛЬКО ДЛЯ ИНИЦИАЛИЗАЦИИ)
```

```
[ Shortcode ] ── HTML ──→ JS
```

---

## 2. РОЛИ ФАЙЛОВ (ЖЁСТКО)

### 2.1 `config/npk-database.php`

**Роль:**  
📦 Хранилище данных  
📌 НИКАКОЙ логики

**Содержит:**

- `get_fertilizers()`
    
- `get_concentration_profiles()`
    
- `get_constants()`
    

**Никого не вызывает**

---

### 2.2 `includes/class-calculation-engine.php`

**Роль:**  
🧠 ЧИСТАЯ логика расчёта

**МОЖЕТ вызывать:**

```php
NPK_Database::get_fertilizers()
NPK_Database::get_concentration_profiles()
NPK_Database::get_constants()
```

**НЕ МОЖЕТ вызывать:**

- Data_Adapter
    
- Shortcode
    
- AJAX
    
- JS
    

**ВОЗВРАЩАЕТ:**

```php
[
  'fertilizer_mass',
  'concentration',
  'state' => [
      'id',
      'name',
      'color',
      'description'
  ],
  'warnings'
]
```

❗ State определяется ТОЛЬКО здесь

---

### 2.3 `includes/class-ajax-handler.php`

**Роль:**  
🚚 Передача данных

**МОЖЕТ вызывать:**

```php
Calculation_Engine::calculate()
```

**НЕ МОЖЕТ:**

- считать
    
- определять state
    
- генерировать HTML
    

**ВОЗВРАЩАЕТ ТОЛЬКО JSON**

---

### 2.4 `includes/class-data-adapter.php`

**Роль:**  
🔁 Адаптация данных для JS

**МОЖЕТ вызывать:**

```php
NPK_Database::get_fertilizers()
NPK_Database::get_concentration_profiles()
NPK_Database::get_constants()
```

**НЕ МОЖЕТ:**

- считать
    
- определять state
    
- участвовать в AJAX
    
- участвовать в расчётах
    

**Единственный выход:**

```php
wp_localize_script()
```


`Data_Adapter`:

- используется ТОЛЬКО для подготовки данных для UI;
    
- может применять ту же логику валидации для отображения;
    
- НЕ участвует в цепочке расчётов;
    
- НЕ передаёт данные в `Calculation_Engine`.
---

### 2.5 `includes/class-shortcode.php`

**Роль:**  
🧱 HTML-разметка

**МОЖЕТ:**

- вывести контейнер
    
- подключить скрипты
    
- передать init-данные
    

**НЕ МОЖЕТ:**

- считать
    
- знать формулы
    
- обращаться к базе
    

---

### 2.6 `assets/js/calculator.js`

**Роль:**  
🎛 UI

**МОЖЕТ:**

- отправлять AJAX
    
- менять цвета
    
- обновлять интерфейс
    

**НЕ МОЖЕТ:**

- определять state
    
- знать диапазоны
    
- иметь бизнес-логику

## 6. ПОРЯДОК ВЫПОЛНЕНИЯ WORDPRESS HOOKS (ЖЁСТКИЙ, НЕЛЬЗЯ НАРУШАТЬ)

### 6.1. При загрузке плагина:
1. `npk-calculators.php` → конструктор `NPK_Calculators`
2. → `load_database()` (сразу)
3. → `load_concentration_module()` (сразу)

### 6.2. В конструкторе `NPK_Concentration_Module`:
1. Регистрация скриптов: `add_action('wp_enqueue_scripts', 'register_assets', 1)`
2. Подключение классов: `load_dependencies()`
3. Инициализация: `add_action('init', 'init')`

### 6.3. В методе `init()` модуля:
1. Регистрация шорткода
2. Регистрация AJAX

### 6.4. При вызове шорткода (в момент парсинга контента):
1. `enqueue_assets()` (гарантированно, без проверок)
2. Возврат HTML

### 6.5. Критическое правило для скриптов:

**Регистрация ≠ Enqueue**

- **Регистрация** (wp_register_script) - ВСЕГДА в конструкторе модуля
- **Enqueue** (wp_enqueue_script) - ТОЛЬКО в шорткоде, БЕЗ условий

❌ **НЕДОПУСТИМО:**
- Проверять `wp_script_is()` в шорткоде
- Регистрировать скрипты внутри шорткода  
- Использовать `wp_enqueue_scripts` без приоритета 1

✅ **ОБЯЗАТЕЛЬНО:**
- Скрипты зарегистрированы ДО парсинга шорткода
- Шорткод ВСЕГДА вызывает `wp_enqueue_script()` без условий
- WordPress сам решает, выводить скрипт или нет

Так сохраняется **сквозная нумерация** (1, 2, 3, 4, 5, 6) и документ остаётся целостным.
