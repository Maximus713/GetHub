

# ИНСТРУКЦИЯ ДЛЯ ЧАТА-ИСПОЛНИТЕЛ


## Исправление калькулятора концентрации NPK

### 🎯 ЦЕЛЬ

Исправить калькулятор концентрации рабочего раствора так, чтобы он **строго соответствовал ТЗ**, корректно работал визуально и логически, а именно:

- менялся **цвет интерфейса** в зависимости от концентрации,
    
- менялся **текст состояния**,
    
- все элементы интерфейса синхронно обновлялись на основе **серверного `state`**,
    
- отсутствовали «мертвые» селекторы, неиспользуемые переменные и догадки.
    

---

## 1️⃣ ОБЩИЕ ПРИНЦИПЫ (ОБЯЗАТЕЛЬНО)

1. **HTML считается эталонным и неизменным**, за исключением случаев, где прямо указано «ДОБАВИТЬ атрибут».
    
2. **Нельзя придумывать новые элементы DOM**, классы или data-атрибуты без явного указания.
    
3. **Единственный источник истины — серверный `state`**, получаемый по AJAX.
    
4. Запрещено:
    
    - дублировать состояние в разных переменных,
        
    - рассчитывать цвет/название состояния на клиенте,
        
    - обновлять UI без опоры на `state`.
        

---

## 2️⃣ СТРУКТУРА `state` (КАК СЧИТАТЬ ОБЯЗАТЕЛЬНО)

Чат должен исходить из того, что сервер возвращает:

```json
state: {
    key: "optimal | weak | strong | dangerous",
    name: "Оптимальная",
    color: "#4CAF50",
    emoji: "✅",
    description: "Безопасная рабочая концентрация",
    warnings: []
}
```

❗ **Нельзя менять структуру `state`**  
❗ **Нельзя вычислять `state` на клиенте**

---

## 3️⃣ КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: ТЕКСТ СОСТОЯНИЯ

### ❌ Проблема

В HTML **несколько элементов** с `data-npk-state-name`, а JS обновляет только первый.

### ✅ Обязательное решение

#### В JS:

- **ЗАПРЕЩЕНО** использовать `querySelector` для `data-npk-state-name`
    
- **ОБЯЗАТЕЛЬНО** использовать `querySelectorAll`
    

```js
this.stateNameElements =
    this.container.querySelectorAll('[data-npk-state-name]');
```

#### При обновлении:

```js
this.stateNameElements.forEach(el => {
    el.textContent = state.name;
});
```

---

## 4️⃣ КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: ЦВЕТ СОСТОЯНИЯ

### ❌ Проблема

JS пытается менять цвет элементов, которые:

- либо не найдены,
    
- либо не предназначены для окрашивания.
    

---

### ✅ ЧТО НУЖНО СДЕЛАТЬ В HTML (МИНИМАЛЬНО)

**ДОБАВИТЬ**, не меняя структуру:

```html
data-npk-color-target="state"
```

к следующим блокам:

- `.npk-state-label`
    
- `.npk-result-item.npk-result-state`
    
- (при необходимости) `.npk-slider-fill`
    

---

### ✅ В JS (ЕДИНЫЙ МЕХАНИЗМ)

```js
this.stateColorTargets =
    this.container.querySelectorAll('[data-npk-color-target="state"]');
```

```js
updateStateColors(state) {
    this.stateColorTargets.forEach(el => {
        el.style.backgroundColor = state.color;
    });
}
```

❗ **Нельзя менять цвет “по месту”**  
❗ **Нельзя хардкодить классы состояний**

---

## 5️⃣ СЛАЙДЕР КОНЦЕНТРАЦИИ

### Требования:

1. Цвет `npk-slider-fill` **совпадает с `state.color`**
    
2. Ширина fill **зависит только от текущей концентрации**
    
3. Слайдер **не определяет состояние**, он лишь отражает его
    

```js
updateSliderUI(state) {
    const percent = this.calculateSliderPercent();
    this.sliderFill.style.width = percent + '%';
    this.sliderFill.style.backgroundColor = state.color;
}
```

---

## 6️⃣ КРИТИЧЕСКОЕ: ХРАНЕНИЕ СОСТОЯНИЯ

### ❌ Запрещено

- обращаться к `data.data`
    
- использовать `this.finalData`
    
- читать `state` напрямую из AJAX-ответа в разных местах
    

---

### ✅ ОБЯЗАТЕЛЬНО

```js
handleServerSuccess(response) {
    this.currentState = response.state;

    this.updateStateTexts(this.currentState);
    this.updateStateColors(this.currentState);
    this.updateSliderUI(this.currentState);
    this.updateWarnings(this.currentState);
}
```

📌 `this.currentState` — **единственное хранилище состояния**

## 9️⃣ ПРОВЕРКА РЕЗУЛЬТАТА (ОБЯЗАТЕЛЬНО)

После исправлений должно выполняться:

- изменение концентрации → AJAX → новый `state`
    
- одновременно меняются:
    
    - текст состояния (везде),
        
    - цвет (везде),
        
    - emoji,
        
    - описание,
        
    - цвет шкалы
        
- **нет рассинхрона**
    
- **нет “магии” на клиенте**
