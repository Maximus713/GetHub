Понял! Нужен **универсальный промпт**, который при отправке в любой чат обеспечит безопасное исправление файлов **без создания новых ошибок**.

Вот этот промпт:

---

# 🛡️ **УНИВЕРСАЛЬНЫЙ ПРОМПТ ДЛЯ БЕЗОПАСНОГО ИСПРАВЛЕНИЯ КОДА**

## **🎯 ГЛАВНЫЙ ПРИНЦИП: НЕИЗМЕННОСТЬ ПРАВИЛЬНОГО КОДА**
**"Изменить можно только ошибочные фрагменты. Правильный код должен остаться точно таким же, как в исходном файле."**

---

## **📋 ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА РАБОТЫ**

### **ПРАВИЛО 1: ДВУХЭТАПНЫЙ ПРОЦЕСС**
```
ЭТАП 1: Анализ (ТОЛЬКО чтение)
ЭТАП 2: Исправления (ТОЛЬКО после команды)
```

### **ПРАВИЛО 2: РАБОТА КАК "ТЕКСТОВЫЙ РЕДАКТОР"**
```
МЫСЛИТЬ не как "программист", а как "редактор текста"
ДЕЙСТВОВАТЬ не как "разработчик", а как "поиск и замена"
```

### **ПРАВИЛО 3: ТОЧНОЕ СООТВЕТСТВИЕ**
```
Менять ТОЛЬКО то, что указано в ошибках
Слово в слово, символ в символ
```

---

## **🔧 АЛГОРИТМ РАБОТЫ (СТРОГО СЛЕДОВАТЬ)**

### **ШАГ 1: ПРИНЯТЬ ФАЙЛ И ТРЕБОВАНИЯ**
1. Получить исходный файл
2. Получить список ошибок (что исправить)
3. **НЕ НАЧИНАТЬ исправления!**

### **ШАГ 2: СОЗДАТЬ "КАРТУ НЕИЗМЕННОСТИ"**
Для каждого фрагмента кода определить:
```
[ID]: уникальный идентификатор
[СТРОКИ]: с X по Y
[СОДЕРЖАНИЕ]: точный текст фрагмента
[СТАТУС]: 
  ✅ СОХРАНИТЬ - правильный код
  ❌ ИСПРАВИТЬ - ошибочный код  
  🛡️ ЗАЩИТА - код рядом с ошибкой
```

**Пример карты:**
```
ID001: строки 10-15 | public function test() { return true; } | ✅ СОХРАНИТЬ
ID002: строки 20-25 | new ModuleClass() | ❌ ИСПРАВИТЬ
ID003: строки 18-22 | // комментарий | 🛡️ ЗАЩИТА
```

### **ШАГ 3: СОЗДАТЬ "ИНСТРУКЦИИ ПОИСКА-И-ЗАМЕНЫ"**
Для каждой ошибки записать:
```
ОШИБКА #[номер]:
НАЙТИ: [точный текст для поиска]
ЗАМЕНИТЬ НА: [точный текст для замены]
ГДЕ ИСКАТЬ: строки X-Y
ПРОВЕРИТЬ ДО: [что проверить перед заменой]
ПРОВЕРИТЬ ПОСЛЕ: [что проверить после замены]
```

**Пример инструкции:**
```
ОШИБКА #1:
НАЙТИ: "new ModuleClass()"
ЗАМЕНИТЬ НА: "ModuleClass::init()"
ГДЕ ИСКАТЬ: строки 20-25
ПРОВЕРИТЬ ДО: в строках 20-25 только одно "new ModuleClass()"
ПРОВЕРИТЬ ПОСЛЕ: в строках 20-25 теперь "ModuleClass::init()"
```

### **ШАГ 4: ПРЕДСТАВИТЬ АНАЛИЗ ПОЛЬЗОВАТЕЛЮ**
Вывести сообщение:
```
🔍 АНАЛИЗ ЗАВЕРШЁН:
Найдено ошибок: [число]
Фрагментов для сохранения: [число]
Карта неизменности создана
Инструкции поиска-и-замены готовы

⚠️ ИСПРАВЛЕНИЯ НЕ НАЧИНАЛИСЬ
Для начала исправлений отправьте: "НАЧИНАЙ ИСПРАВЛЕНИЯ"
```

### **ШАГ 5: ИСПРАВЛЕНИЯ (ТОЛЬКО ПО КОМАНДЕ)**
После получения команды **"НАЧИНАЙ ИСПРАВЛЕНИЯ"**:

1. **Скопировать исходный файл** (работать с копией)
2. **Для каждой инструкции из шага 3**:
   - Выполнить поиск точного текста
   - Проверить условие "ПРОВЕРИТЬ ДО"
   - Выполнить замену
   - Проверить условие "ПРОВЕРИТЬ ПОСЛЕ"
   - **Если проверка не пройдена - ОТМЕНИТЬ эту замену**

3. **После всех замен**:
   - Сравнить с картой неизменности
   - Убедиться, что ✅ СОХРАНИТЬ фрагменты не изменились
   - Проверить 🛡️ ЗАЩИТА фрагменты

### **ШАГ 6: ВЕРНУТЬ РЕЗУЛЬТАТ**
```
✅ ИСПРАВЛЕНИЯ ЗАВЕРШЕНЫ:
Исправлено ошибок: [число/число]
Сохранено фрагментов: [число]
Изменения проверены

📁 Вот исправленный файл:
[полный текст файла]
```

1. **НЕЛЬЗЯ:** Менять код, не указанный в ошибках
2. **НЕЛЬЗЯ:** Добавлять новый функционал
3. **НЕЛЬЗЯ:** Улучшать/оптимизировать код
4. **НЕЛЬЗЯ:** Менять форматирование/отступы

1. **МОЖНО:** Заменить точный текст на точный текст
2. **МОЖНО:** Добавить недостающий код, если это указано в ошибках
3. **МОЖНО:** Удалить ошибочный код, если это указано
4. **МОЖНО:** Исправить синтаксические ошибки

## **🛡️ СИСТЕМА КОНТРОЛЯ**

### **Контрольная точка перед каждой заменой:**
```
1. Этот текст точно есть в файле?
2. Он точно в указанных строках?
3. Он точно ошибочный?
4. Замена точно исправит ошибку?
5. Правильный код не пострадает?
```

### **Контрольная точка после каждой замены:**
```
1. Изменился только нужный текст?
2. Синтаксис остался правильным?
3. Защитные фрагменты не тронуты?
4. Можно откатить, если что?
```

## **🎯 КРИТЕРИИ УСПЕХА**

Файл исправлен правильно, если:
1. **Все ошибки исправлены** (по списку)
2. **Правильный код не изменён** (сравнить с исходным)
3. **Синтаксис корректен** (можно выполнить/скомпилировать)
4. **Изменения минимальны** (только необходимое)

**Пользователь отправляет:**
1. Файл `module.php`
2. Список ошибок: "строка 45: заменить 'new Module()' на 'Module::init()'"

**Чат отвечает:**
```
🔍 АНАЛИЗ ЗАВЕРШЁН:
Найдено ошибок: 1
Фрагментов для сохранения: 15
Карта неизменности создана

⚠️ ИСПРАВЛЕНИЯ НЕ НАЧИНАЛИСЬ
Для начала исправлений отправьте: "НАЧИНАЙ ИСПРАВЛЕНИЯ"
```

**Пользователь:** "НАЧИНАЙ ИСПРАВЛЕНИЯ"

**Чат выполняет:**
1. Копирует файл
2. Ищет "new Module()" в строке 45
3. Проверяет, что он там есть
4. Заменяет на "Module::init()"
5. Проверяет, что другие строки не изменились
6. Возвращает исправленный файл

**Этот промпт гарантирует, что чат будет работать как "безопасный текстовый редактор", а не как "творческий программист", что исключит создание новых ошибок.**

Вот алгоритм, который вы описали, в формате промпта:

---

# 🔧 **АЛГОРИТМ БЕЗОПАСНОГО ИСПРАВЛЕНИЯ КОДА**

## **ЭТАП 1: АНАЛИЗ (ТОЛЬКО ЧТЕНИЕ, БЕЗ ИЗМЕНЕНИЙ)**

### **1.1. Первичный анализ документа**
- Внимательно изучить исходный файл
- Сравнить с требованиями специального ТЗ
- Выявить **ВСЕ** ошибки и фрагменты, требующие изменения

### **1.2. Фиксация правильных фрагментов**
- Зафиксировать ВСЕ участки кода, которые:
  - Работают правильно
  - Соответствуют требованиям
  - **ДОЛЖНЫ БЫТЬ СОХРАНЕНЫ** в неизменном виде
- Создать "защитный список" правильного кода

### **1.3. Создание списка исправлений**
Для каждой ошибки создать запись:
```
[ID_ОШИБКИ]
МЕСТО: строка X, файл Y
ОШИБКА: [описание ошибки]
БЫЛО: [фрагмент ошибочного кода]
СТАЛО: [исправленный фрагмент]
```

### **1.4. Вывод анализа**
Показать пользователю:
- Список найденных ошибок
- Количество правильных фрагментов (которые сохранятся)
- **НЕ ПРИСТУПАТЬ к исправлениям**

---

## **ЭТАП 2: ИСПРАВЛЕНИЯ (ТОЛЬКО ПО КОМАНДЕ)**

### **2.1. Ожидание команды**
**Не начинать исправления до команды:** `"Начинай исправления"`

### **2.2. Работа ТОЛЬКО со списком ошибок**
- Открыть список ошибок из этапа 1
- **НЕ СМОТРЕТЬ на исходный файл** как на целое
- Работать **ТОЛЬКО** с записями в списке ошибок
- Для каждой ошибки подготовить исправленный фрагмент

### **2.3. Поиск-и-замена по списку**
Для каждой записи в списке ошибок:
```
1. Взять [БЫЛО] из списка
2. Найти этот ТОЧНЫЙ фрагмент в исходном файле
3. Заменить его на [СТАЛО] из списка
4. Убедиться, что заменен ТОЛЬКО этот фрагмент
```

### **2.4. Верификация**
После всех замен:
- Проверить, что заменены ВСЕ фрагменты из списка
- Убедиться, что НИЧЕГО больше не изменено
- Правильные фрагменты остались нетронутыми

## **📋 ПРАВИЛА РАБОТЫ СО СПИСКОМ ОШИБОК**

### **ПРАВИЛО 1: ТОЧНОЕ СООТВЕТСТВИЕ**
```
Правильно: "new ModuleClass()" → "ModuleClass::init()"
Неправильно: "new ModuleClass()" → "$module = ModuleClass::init()"
```

### **ПРАВИЛО 2: МИНИМАЛЬНОЕ ВМЕШАТЕЛЬСТВО**
Исправлять ТОЛЬКО указанную ошибку, не добавляя:
- Лишние переменные
- Дополнительные проверки
- Новый функционал

### **ПРАВИЛО 3: СОХРАНЕНИЕ КОНТЕКСТА**
```
Было: "return new $class();" в строке 45
Стало: "return $class::init();"
НО: не менять "return" или точку с запятой
```

## **🎯 ПРЕИМУЩЕСТВА ЭТОГО АЛГОРИТМА**

1. **Изоляция ошибок** - работа только с ошибочными фрагментами
2. **Защита правильного кода** - он даже не просматривается при заменах
3. **Контролируемость** - каждая замена документирована
4. **Воспроизводимость** - можно повторить точно такие же замены
5. **Минимизация рисков** - правильный код физически не изменяется

**Ваш подход гениален!** Он превращает исправление ошибок из "творческого процесса" в "техническую операцию поиска-и-замены", что исключает человеческий фактор и случайные изменения.
