**Для работы с кодом лучше всего подходит ПРОМПТ #4: РЕЖИМ ДЕТЕРМИНИРОВАННОГО ИСПОЛНЕНИЯ (РИД)**

Вот подробное обоснование:

## **ПОЧЕМУ РИД ИДЕАЛЕН ДЛЯ КОДА:**

### 1. **ДЕТЕРМИНИРОВАННОСТЬ = ПРЕДСКАЗУЕМОСТЬ КОДА**
- Код должен работать одинаково при одинаковых входных данных
- РИД математически гарантирует: `Ответ = Инструкция ∘ F`
- Никаких "улучшений" синтаксиса, никаких "более читаемых" вариантов без команды

### 2. **ПРОВЕРКА ЧЕРЕЗ "ДРУГОГО АГЕНТА" (§7)**
- Критически важно для кода: "может ли другой программист понять этот код?"
- Если вывод не позволяет воспроизвести задачу → в коде есть скрытая логика
- Это аналог code review в промпте

### 3. **РАЗРЕШЕНИЕ НА ЧАСТИЧНОЕ ВЫПОЛНЕНИЕ (§2.2)**
- Если в задаче не хватает данных для написания полного кода
- РИД явно разрешает оставить часть невыполненной
- Не будет додумывать логику (опасно в программировании!)

## **КОНКРЕТНЫЕ СЦЕНАРИИ:**

### **СЦЕНАРИЙ 1: Написание кода по ТЗ**
```
Запрос: "Напиши функцию на Python, которая принимает список чисел 
и возвращает среднее значение, игнорируя None. Добавь обработку пустого списка."

РИД:
1. Выделит команды: "напиши функцию", "добавь обработку"
2. Создаст ТОЛЬКО эту функцию
3. Не добавит: 
   - примеры использования
   - тесты (если не просили)
   - альтернативные реализации
   - комментарии про "лучшие практики"
```

### **СЦЕНАРИЙ 2: Поиск ошибок**
```
Запрос: "Найди ошибку в этом коде: [код]"

РИД:
1. Укажет ТОЧНОЕ место ошибки
2. Не будет предлагать рефакторинг всего кода
3. Не добавит "а еще вот здесь потенциальная проблема"
4. Только явная ошибка из запроса
```

### **СЦЕНАРИЙ 3: Настройка/конфигурация**
```
Запрос: "Создай docker-compose.yml для приложения на Node.js с MongoDB"

РИД:
1. Даст минимальный рабочий конфиг
2. Не добавит: 
   - оптимизации для продакшена
   - healthcheck'и (если не просили)
   - комментарии про безопасность
   - альтернативные варианты развертывания
```

## **ПРИМЕРЫ ПРОБЛЕМ С ДРУГИМИ ПРОМПТАМИ:**

### **Проблема с коротким промптом (#1):**
```
Запрос: "Напиши SQL-запрос для выборки пользователей"
Ответ: "SELECT * FROM users; -- Вот запрос. Также рекомендую добавить 
WHERE для фильтрации и LIMIT для пагинации..."
```

**РИД такого не допустит** — только чистый SQL.

### **Проблема с АТИ (#2):**
```
Запрос: "Исправь синтаксическую ошибку в строке 5"
АТИ может "заодно" исправить стиль кода вокруг
```

**РИД исправит ТОЛЬКО строку 5.**

### **Проблема со СТАНКОК (#3):**
```
Запрос: "Создай конфиг для webpack"
СТАНКОК может добавить комментарии "для ясности"
```

**РИД даст голый конфиг без комментариев.**

## **МОДИФИКАЦИЯ РИД ДЛЯ КОДА (ОПЦИОНАЛЬНО):**

Добавьте в начало РИД для программирования:

```
ДОПОЛНИТЕЛЬНО ДЛЯ КОДИРОВАНИЯ:

§К.1. Принцип минимальной работоспособности
Код должен быть минимально достаточным для выполнения
явно указанных требований. Никакого over-engineering.

§К.2. Запрет на советы по архитектуре
Не предлагать изменения архитектуры, паттерны, фреймворки
без прямой команды "оптимизируй архитектуру".

§К.3. Формат вывода кода
Код без пояснений до и после. Если нужны комментарии в коде —
только явно запрошенные или критичные для понимания синтаксиса.
```

## **ПРАКТИЧЕСКИЙ СОВЕТ:**

Для программирования используйте **РИД** в сочетании с **четкими техническими заданиями**:

**ПЛОХО:** "Напиши скрипт для обработки данных"
**ХОРОШО:** 
```
Напиши Python-функцию process_data():
- Вход: список словарей с полями 'id', 'value'
- Выход: словарь {id: среднее_значение}
- Игнорировать None значения
- При пустом входе возвращать {}
- Сложность O(n)
- Без сторонних библиотек
```

## **ВЫВОД:**

**РИД (#4) — лучший выбор для программирования**, потому что:

1. **Математическая строгость** соответствует природе кода
2. **Запрет на инициативу** предотвращает опасные "улучшения"
3. **Проверка через другого агента** — аналог code review
4. **Чистый вывод** — только код, без мета-комментариев

**Исключение:** Если вам нужно, чтобы модель предлагала **альтернативные подходы** или **объясняла код** — тогда лучше АТИ (#2) или даже обычный режим. Но для строгого выполнения ТЗ — только РИД.

**Итоговая рекомендация:** Для всех задач с кодом, где важна точность выполнения ТЗ, используйте **промпт #4 (РИД)**. Он спасет вас от "помощных" советов, которые ломают совместимость, и даст ровно то, что просили.
