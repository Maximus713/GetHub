**АНАЛИЗ ДЛЯ РАБОТЫ С КОДОМ**

Для программирования нужен особый баланс: **строгость исполнения + понимание контекста кода + возможность точечных улучшений**.

---

## **ЛУЧШИЙ ВЫБОР: «АТИ» (Режим Абсолютно Точного Исполнения)**

**Почему именно он:**

1. **Алгоритмичность** (блок 4) — идеально для пошаговых задач:
   - «Найди ошибку в строках 15-30» → шаг 4.1: выделить команду «найди»
   - «Рефакторинг функции X» → четкое соответствие команд элементам

2. **Запрет на интерпретацию** (3.4) — критичен для кода:
   - Не будет «улучшать» алгоритм без просьбы
   - Не будет добавлять «более современные» подходы

3. **Иерархия запретов** — 3.1 (Инициатива) и 3.2 (Изменения) защищают от:
   - Автоматического добавления комментариев
   - Изменения стиля кода без запроса
   - «Оптимизаций», которые ломают логику

---

## **ПОЧЕМУ НЕ ДРУГИЕ:**

### **«СТАНКОК»** — слишком общий:
- Критерий «скрипт» плохо работает для творческих задач рефакторинга
- «Обрабатывай запрос» не подходит для поиска скрытых ошибок

### **«РИД»** — избыточно формален:
- Математическая строгость мешает пониманию контекста кода
- Трехуровневый контроль замедляет работу

### **Базовый промпт** — недостаточно строг:
- Может добавить «полезные» комментарии
- Не защищает от стилевых изменений

---

## **МОДИФИЦИРОВАННЫЙ «АТИ» ДЛЯ ПРОГРАММИРОВАНИЯ**

Добавьте к вашему АТИ-промпту специфичные для кода правила:

```
ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА ДЛЯ РАБОТЫ С КОДОМ:

1. КОНТЕКСТ КОДА:
   - Не изменяй именования переменных/функций без явной команды
   - Сохраняй существующие комментарии и docstrings
   - Не меняй стиль отступов, скобок, переносов строк

2. ДЛЯ ПОИСКА ОШИБОК:
   - Указывай ТОЧНОЕ место ошибки (файл:строка:символ)
   - Приводий ТОЧНЫЙ текст ошибки (если есть)
   - Не предлагай альтернативные реализации без запроса
   - Если есть несколько возможных причин — перечисли их БЕЗ приоритизации

3. ДЛЯ НАСТРОЙКИ КОНФИГУРАЦИИ:
   - Изменяй ТОЛЬКО указанные параметры
   - Сохраняй формат конфигурационного файла
   - Не добавляй «рекомендуемых» значений без запроса

4. ПРИНЦИП МИНИМАЛЬНОГО ИСПРАВЛЕНИЯ:
   - Все изменения должны быть локализованы в явно указанной области
   - Не рефактори соседний код «заодно»
   - Не оптимизируй производительность без команды
```

---

## **КОГДА ЧТО ИСПОЛЬЗОВАТЬ:**

### **1. Написание нового кода**
- **АТИ** с доп. правилами
- **Конкретная инструкция:** «Напиши функцию, которая делает X с параметрами Y, Z. Сигнатура: def func(y, z) -> bool»

### **2. Поиск ошибок (debugging)**
- **Чистый АТИ** (без модификаций)
- **Пример запроса:** «Вот код [код]. Вот ошибка [текст]. Найди причину. Не предлагай исправления»

### **3. Рефакторинг**
- **АТИ** с акцентом на «Принцип минимального изменения»
- **Пример:** «Рефактори функцию calculate() для повышения читаемости. Не меняй логику»

### **4. Настройка конфигурации**
- **АТИ** с доп. правилом 3
- **Пример:** «В этом конфиге YAML измени параметр timeout с 30 на 60. Больше ничего не меняй»

### **5. Оптимизация производительности**
- **Требуется креативность → используйте СТАНКОК с явным разрешением:**
  «Проанализируй код на предмет bottlenecks. Ты МОЖЕШЬ предлагать альтернативные реализации»

---

## **ПРАКТИЧЕСКИЕ ПРИМЕРЫ:**

**Плохой запрос для кода:** «Сделай этот код лучше»
**Хороший запрос для АТИ:** «В функции process_data() замени цикл for на list comprehension. Не изменяй другие части кода»

**Плохой запрос:** «Почему эта программа падает?»
**Хороший запрос для АТИ:** «Программа падает с ошибкой KeyError. Проанализируй только строки 45-52. Перечисли ВСЕ возможные причины без приоритизации»

---

## **ВЫВОД:**

Для программирования **«АТИ» — лучшая база** благодаря:
1. Алгоритмической структуре (шаги 4.1-4.4)
2. Явному запрету на интерпретацию 
3. Иерархии приоритетов

**Дополните его правилами для кода** — и получите идеальный инструмент для:
- ✅ Написания кода по ТЗ
- ✅ Точечного исправления ошибок  
- ✅ Безопасного рефакторинга
- ✅ Конфигурирования без побочных эффектов

**Альтернатива:** Если нужно **креативное решение архитектурной проблемы** — временно отключите АТИ и используйте **СТАНКОК** с явным разрешением на инициативу.
