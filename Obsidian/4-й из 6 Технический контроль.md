## 🔍 ЧТО ТЫ ДЕЛАЕШЬ (шаги)

### ШАГ 1: ПРОВЕРКА РЕАЛИЗУЕМОСТИ МЕТОДОВ
Для каждого метода в техзадании проверь:

1. **Существование зависимостей:**
   - Все вызываемые методы/классы существуют?
   - NPK_Database:: методы из версии 4.0?
   - normalize_npk() доступен (public/private)?

2. **Техническая выполнимость логики:**
   - Можно ли выполнить все шаги логики?
   - Нет ли противоречий в алгоритме?
   - Edge cases технически обрабатываемы?

3. **Type hints и возвращаемые типы:**
   - Type hints корректны для реализации?
   - Возвращаемый тип соответствует логике?
   - Нет ли невозможных преобразований типов?

### ШАГ 2: ПРОВЕРКА УЧЁТА ТЕХНИЧЕСКИХ ЗАПРЕТОВ
Проверь соответствие "Списку ошибок":

1. **Запрещённые конструкции:**
   - Нет ли URLSearchParams() в AJAX описании?
   - Нет ли статических стилей в PHP/JS?
   - Правильный ли формат AJAX (FormData())?
   - DOM обновления в requestAnimationFrame()?

2. **Технические требования:**
   - Имена файлов в kebab-case?
   - CSS селекторы с префиксом .npk-?
   - Порядок создания файлов технически корректен?

3. **Ошибки модуля 1 (предотвращение):**
   - Нет ли конструкций, вызывавших ошибки ранее?
   - Учтены ли все "критические ошибки" из списка?

### ШАГ 3: ПРОВЕРКА БЕЗОПАСНОСТИ
Проверь безопасность реализации:

1. **Валидация входных данных:**
   - Проверяются ли входные параметры методов?
   - Есть ли sanitize/escape для данных из БД?
   - Нет ли прямого использования $_POST/$_GET?

2. **WordPress безопасность:**
   - Используются ли nonce для AJAX?
   - Есть ли проверка прав доступа?
   - Используются ли esc_* функции для вывода?

3. **Защита от уязвимостей:**
   - Нет риска SQL-инъекций?
   - Нет риска XSS?
   - Нет прямых SQL запросов?

### ШАГ 4: ПРОВЕРКА СООТВЕТСТВИЯ СТАНДАРТАМ
Проверь соответствие стандартам:

1. **WordPress Coding Standards:**
   - Правильные имена методов (camelCase)?
   - Правильные отступы (4 пробела)?
   - PHPDoc комментарии для всех методов?

2. **Технические стандарты:**
   - Все публичные методы имеют type hints?
   - Правильное использование namespace?
   - Соответствие PSR-4?

### ШАГ 5: ПРОВЕРКА СПЕЦИФИКИ МОДУЛЯ 2
Проверь учёт "Инструкции проверки":

1. **Алгоритм Отиаи:**
   - Корректен ли алгоритм (нормализация, минимумы, сумма)?
   - Учтены ли разные масштабы NPK (проценты vs 1.0-2.0-1.0)?
   - Правильно ли работает fallback режим?

2. **Instant Preview:**
   - Технически реализуем за <100мс?
   - Использует предзагруженные данные?
   - Заменяется точными данными с сервера?

3. **Технические проверки:**
   - Порог 75% берётся из БД (не хардкод)?
   - Кэширование на 1 час технически предусмотрено?
   - AJAX ответ <500мс технически достижим?

### ШАГ 6: ПОИСК ТЕХНИЧЕСКИХ ОШИБОК
Найди конкретные технические проблемы:

1. **Невыполнимые требования:**
   - Метод требует несуществующий класс/метод
   - Логика противоречит сама себе
   - Type hints не соответствуют реализации

2. **Нарушения запретов:**
   - Использование запрещённых конструкций
   - Игнорирование технических требований
   - Повторение ошибок модуля 1

3. **Проблемы безопасности:**
   - Отсутствие валидации входных данных
   - Потенциальные уязвимости
   - Небезопасные практики

4. **Несоответствия стандартам:**
   - Нарушения WordPress Coding Standards
   - Неправильные type hints
   - Отсутствие необходимой документации

### ШАГ 7: СОЗДАНИЕ ИСПРАВЛЕННОГО ТЕХЗАДАНИЯ
Для каждой найденной технической ошибки:
1. Опиши ошибку технически точно
2. Укажи, почему это техническая проблема
3. Предложи конкретное техническое исправление

## 4. ТЕХНИЧЕСКИЕ РЕШЕНИЯ ДЛЯ ПРОБЛЕМ:

### ПРОБЛЕМА: normalize_npk() — private метод
**Техническая проблема:** Selection_Engine не может вызвать private метод
**Решение:** Сделать метод public в NPK_Database или создать public-обёртку
**Техническая реализация:** В БД: `public static function normalize_npk(array $npk): array`
**Причина:** Иначе технически нереализуемо

### ПРОБЛЕМА: AJAX <500мс при высокой нагрузке
**Техническая проблема:** Алгоритм Отиаи может быть медленным для многих удобрений
**Решение:** Добавить кэширование результатов расчётов
**Техническая реализация:** Cache_Manager кэширует результаты по ключу crop+phase
**Причина:** Техническое требование производительности

### ПРОБЛЕМА: Instant Preview <100мс
**Техническая проблема:** JavaScript должен быстро считать для UX
**Решение:** Использовать предзагруженные данные и упрощённый алгоритм
**Техническая реализация:** Данные культур/фаз/удобрений в window.NPK_Selector_Data
**Причина:** Техническое требование отзывчивости UI
